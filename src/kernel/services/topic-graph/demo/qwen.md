# Исследовательский документ: OpenCode Desktop 1.19.4 как ядро расширяемой AI-экосистемы

## 0. Методологическая рамка

Прежде чем перейти к карте расширений, зафиксируем **мета-уровень подхода**. OpenCode 1.19.4 — не «законченное приложение», а **ядро (kernel)** в терминологии операционных систем. Всё, что мы строим вокруг — это «userspace»: драйверы контекста, демоны памяти, сервисы инструментов, интерфейсы-оболочки.

Применяем **трёхслойную модель**:
- **L1 — Ядро** (сам OpenCode 1.19.4, его неизменяемые примитивы: промпт, tools, MCP-хост, сессии)
- **L2 — Системные сервисы** (MCP-серверы, Sidekick, внешние демоны, индексаторы)
- **L3 — Пользовательские пространства** (Skills, workflow-оркестраторы, UI-надстройки, мульти-агентные рои)

Главный принцип: **ядро остаётся нетронутым, вся мощь выносится в периферию**.

## 2. Skills — системный подход

### 2.1 Что такое Skills в OpenCode 1.19.4
Skills — это **маркированные блоки инструкций** в `skills/` или `AGENTS.md`, которые агент подгружает по контексту. В 1.19.4 они работают через директивы `@skill` и авто-подбор по описанию.

### 2.2 Архитектура Skills-библиотеки
Рекомендую **иерархическую структуру**:

```
skills/
├── meta/                    # Мета-Skills (о системе)
│   ├── self-reflection.md   # Саморефлексия агента
│   ├── architecture.md      # Архитектурные принципы
│   └── security.md          # Безопасность кода
├── domain/                  # Доменные Skills
│   ├── super-agents-os.md   # Специфика твоего проекта
│   ├── mercury-patterns.md  # Паттерны для Mercury-3
│   └── mcp-integration.md   # Паттерны MCP
├── workflow/                # Workflow-Skills
│   ├── code-review.md
│   ├── refactor.md
│   └── debug.md
└── composite/               # Композитные (ссылаются на другие)
    └── full-pipeline.md
```

### 2.3 Ключевые Skills для разработки
| Skill | Назначение | Сложность |
|-------|-----------|-----------|
| `self-reflection` | Агент анализирует свой вывод перед финализацией | Низкая |
| `architecture-guard` | Проверяет соответствие кода архитектурным принципам | Средняя |
| `memory-anchor` | Явно помечает важные решения для долговременной памяти | Низкая |
| `context-bridge` | Связывает текущую задачу с другими репозиториями | Средняя |
| `multi-model-delegate` | Помечает задачи для передачи в SuperAgents OS | Высокая |

### 2.4 Взаимодействие Skills
Skills могут **вызывать друг друга через ссылки** в тексте (`см. также @skill:architecture-guard`). Это даёт примитивный, но рабочий механизм композиции.

## 3. Tools — расширение инструментов

### 3.1 Встроенные Tools OpenCode 1.19.4
В этой версии уже есть: `read_file`, `write_file`, `edit_file`, `list_dir`, `shell`, `search`. Ограничение — они работают синхронно и в рамках одной сессии.

### 3.2 Собственные Tools через MCP
**MCP — главный рычаг расширения**. Любой MCP-сервер = новый tool для OpenCode.

**Лёгкие MCP-серверы, совместимые с AMD E-350:**

| MCP-сервер | Назначение | Нагрузка |
|------------|-----------|----------|
| `filesystem` (официальный) | Расширенный доступ к файлам | Низкая |
| `memory` (sqlite-backed) | Долговременная память | Низкая |
| `sequential-thinking` | Цепочки рассуждений | Средняя |
| `context7` | Актуальная документация библиотек | Средняя (сеть) |
| `git` | Расширенные git-операции | Низкая |
| `fetch` | HTTP-запросы | Низкая |
| `todoist`/`obsidian` | Внешние базы знаний | Низкая |

### 3.3 Собственные MCP-серверы на Node.js
Учитывая Node.js v24.20.0, **пишем собственные MCP-серверы на TypeScript/JavaScript**. Минимальный шаблон:

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new McpServer({ name: "super-agents-tools", version: "1.0.0" });

server.tool(
  "query_agents_os",
  "Запрос к SuperAgents OS",
  { query: z.string() },
  async ({ query }) => ({ /* ... */ })
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

**Идеи собственных MCP-серверов под твой проект:**
- `super-agents-bridge` — мост к ядру ai-os-new
- `mercury-context` — специфичные паттерны для Mercury-3
- `codebase-indexer` — локальный индекс репозитория (на sqlite)
- `decision-log` — журнал архитектурных решений
- `esoteric-symbols` (да, с учётом твоих интересов) — символический слой для метафорического мышления агента

### 3.4 PowerShell-инструменты как Tools
Через встроенный `shell` tool можно запускать **любой PowerShell-скрипт**. Это даёт:
- Управление системой
- Манипуляции с реестром/службами
- Интеграцию с Windows API через .NET
- Лёгкие парсеры и конвертеры

## 4. Plugins и MCP-интеграции

### 4.1 Конфигурация MCP в OpenCode 1.19.4
В `opencode.json`:

```json
{
  "mcp": {
    "super-agents": {
      "type": "stdio",
      "command": "node",
      "args": ["C:/tools/mcp-bridge/index.js"]
    },
    "memory": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"]
    }
  }
}
```

### 4.2 Стратегия интеграций
**Подтверждённые возможности:**
- Любые MCP-серверы на Node.js работают стабильно
- Stdio-транспорт — самый лёгкий для CPU
- SSE-транспорт — можно использовать для локальных HTTP-сервисов

**Экспериментальные решения:**
- Запуск MCP-серверов в **Windows Subsystem for Linux** (если установлен) — расширяет совместимость
- Использование **Deno** как альтернативы Node для некоторых MCP (если совместимо)

**Гипотезы:**
- Можно создать **MCP-роутер**, который по запросу направляет вызовы к разным бэкендам (включая внешние API Gemini, Groq и т.д.)
- MCP-сервер может быть **тонким клиентом** к твоему SuperAgents OS

## 5. OpenCode Sidekick — развитие

### 5.1 Что такое Sidekick
Sidekick — companion-приложение, которое **дополняет** основной OpenCode. В 1.19.4 оно уже существует как отдельный процесс.

### 5.2 Направления развития Sidekick
Предлагаю превратить Sidekick в **центр управления экосистемой**:

**Функциональные слои:**
1. **Монитор ресурсов** — CPU/RAM AMD E-350 в реальном времени
2. **Менеджер MCP-серверов** — запуск/остановка/логирование
3. **Панель Skills** — визуальный редактор и активатор
4. **Контекстный навигатор** — дерево текущего контекста агента
5. **Workflow-оркестратор** — визуальные цепочки задач
6. **Журнал решений** — что агент делал и почему
7. **Мульти-агентный диспетчер** — управление ролями в SuperAgents OS

### 5.3 Техническая реализация
Sidekick можно развить как:
- **Electron-приложение** (используя тот же Electron 42.3.3, что и OpenCode) — гарантированная совместимость
- **Tauri-приложение** (если Rust-окружение доступно) — легче по памяти
- **Веб-интерфейс + Node.js backend** — самый гибкий вариант, запускается локально

**Рекомендую третий путь**: лёгкий Express/Fastify сервер + Svelte/React SPA. Потребляет ~50-100 MB RAM, легко масштабируется.

## 7. Автоматизация

### 7.1 Workflow-цепочки
**Минимальный workflow-движок** на Node.js:

```
workflow.json:
{
  "name": "feature-pipeline",
  "steps": [
    {"skill": "architecture-guard", "input": "$task"},
    {"tool": "read_file", "input": "src/$file"},
    {"skill": "code-review", "input": "$output"},
    {"tool": "decision-log", "input": "$output"}
  ]
}
```

Запускается через MCP-tool `run_workflow`.

### 7.2 Файловые watcher'ы
Node.js `chokidar` → при изменении файлов в проекте → триггерить определённые Skills. Это даёт **реактивную среду**: агент автоматически реагирует на изменения.

### 7.3 Cron-подобные задачи
PowerShell Scheduled Tasks + MCP-вызовы = **фоновые агенты**:
- Ночью — переиндексация кодовой базы
- Каждые N часов — анализ изменений
- По событию git — обновление контекста

### 7.4 Цепочки агентов (SuperAgents OS интеграция)
OpenCode 1.19.4 = **один агент-исполнитель**. SuperAgents OS = **оркестратор**. Связь через:
- MCP-bridge
- Файловые артефакты (JSON-сообщения в общей папке)
- HTTP API (лёгкий Express-сервер как шлюз)

## 8. Контекст и память

### 8.1 Проблема контекста
OpenCode 1.19.4 имеет ограниченный контекст. На слабой машине нельзя держать весь репозиторий в памяти.

### 8.2 Стратегия: трёхуровневая память

**L1 — Горячая (в сессии):**
- Текущие файлы, открытый контекст
- Управляется самим OpenCode

**L2 — Тёплая (MCP-memory):**
- Ключевые решения, архитектурные принципы
- SQLite-база, индексируется по эмбеддингам (можно через внешний API)
- MCP-сервер `memory` или собственный

**L3 — Холодная (файловая):**
- Весь репозиторий, документация
- Индексируется ripgrep + sqlite FTS5
- MCP-сервер `codebase-search`

### 8.3 Индексация репозитория
**Лёгкий индексатор** на Node.js:
- Обходит файлы, строит inverted index
- Сохраняет в SQLite FTS5
- Обновляется инкрементально через watcher
- MCP-сервер отдаёт результаты поиска

**Ресурсы:** ~50 MB RAM, ~100 MB на диске для среднего проекта.

### 8.4 AGENTS.md как живой документ
Сделать `AGENTS.md` **главным артефактом памяти**:
- Архитектурные решения
- Текущие задачи
- Контекст проекта
- Ссылки на внешние документы

Агент читает его в начале каждой сессии.

## 9. Мультиагентная архитектура

### 9.1 Ролевая модель
В рамках OpenCode 1.19.4 + SuperAgents OS:

| Роль | Где работает | Задача |
|------|--------------|--------|
| **Architect** | OpenCode | Проектирование, ревью |
| **Coder** | OpenCode | Написание кода |
| **Reviewer** | OpenCode (другая сессия) | Критика, поиск багов |
| **Researcher** | SuperAgents OS (Gemini/Groq) | Внешний поиск, анализ |
| **Coordinator** | SuperAgents OS | Оркестрация |
| **Critic** | SuperAgents OS (Mercury-3) | Мета-оценка |

### 9.2 Механизм передачи задач
**Файловый протокол** (самый надёжный на слабом железе):
```
tasks/
├── pending/
│   └── task-001.json
├── in-progress/
├── review/
└── done/
```

Каждый агент — отдельный процесс OpenCode или SuperAgents, читает свою папку.

### 9.3 Дебаты агентов
Используя твой опыт с SuperAgents OS: два агента (OpenCode + внешний) ведут **структурированные дебаты** по архитектурному решению. Протокол — markdown-файл, куда каждый дописывает реплики.

## 11. Собственная разработка — что создать

### 11.1 Приоритетные проекты

**Проект 1: `super-agents-bridge` (MCP-сервер)**
- Мост между OpenCode и SuperAgents OS
- Позволяет агенту OpenCode делегировать задачи другим моделям
- Сложность: средняя, ~2 недели
- Нагрузка: минимальная

**Проект 2: `codebase-indexer`**
- Локальный индекс репозитория на SQLite FTS5
- MCP-сервер с методами `search`, `get_context`, `get_related`
- Сложность: средняя, ~3 недели
- Нагрузка: низкая

**Проект 3: `sidekick-web`**
- Веб-панель управления экосистемой
- Мониторинг MCP, управление Skills, визуализация workflow
- Сложность: высокая, ~1-2 месяца
- Нагрузка: низкая (работает по запросу)

**Проект 4: `decision-log`**
- MCP-сервер для журналирования архитектурных решений
- Автоматически извлекает решения из диалога агента
- Сложность: низкая, ~1 неделя
- Нагрузка: минимальная

**Проект 5: `workflow-engine`**
- Движок цепочек задач на Node.js
- Поддержка условий, циклов, параллелизма
- Сложность: высокая, ~1 месяц
- Нагрузка: низкая

### 11.2 Необычные идеи

**Идея A: «Символический слой»**
Учитывая твой интерес к эзотерике — создать MCP-сервер, который **переводит технические концепции в символические образы** и обратно. Агент получает «двойной контекст»: технический + метафорический. Это может улучшать креативные решения через аналогии.

**Идея B: «Теневой агент»**
Второй экземпляр OpenCode 1.19.4, работающий в фоне, который **пассивно читает все действия основного агента** и ведёт журнал аномалий, паттернов, ошибок. Не вмешивается, только наблюдает и периодически выдаёт отчёт. Реализуется через файловый watcher + отдельная сессия.

**Идея C: «Контекстный оракул»**
Перед каждым серьёзным действием агент вызывает **внешнюю модель** (через SuperAgents OS) с вопросом «Стоит ли это делать?». Получает мета-оценку. Реализуется через MCP-bridge.

**Идея D: «Эволюционный репозиторий»**
Каждое архитектурное решение сохраняется как **ген в базе**. Периодически «скрещиваются» лучшие решения из разных проектов, порождая новые подходы. Это уже на уровне SuperAgents OS, но OpenCode — источник «генов».

**Идея E: «Ритуальный слой»**
Продолжая эзотерическую линию — **ритуализированные workflow**: перед началом работы — «активация контекста» (специальный Skill, читающий AGENTS.md и инициализирующий память), перед завершением — «закрытие цикла» (фиксация решений). Психологически структурирует работу агента и повышает качество.

## 15. Ответ на главный вопрос

> **Насколько далеко можно продвинуть OpenCode Desktop 1.19.4?**

**Ответ:** Практически до уровня полноценной AI-разработческой экосистемы, если перестроить мышление.

**Ключевой инсайт:** OpenCode 1.19.4 — это не «старая версия», а **стабильное ядро**. Все ограничения конкретной версии компенсируются через MCP, Skills и внешние сервисы. Фактически ты получаешь:

- ✅ Функциональность современных AI-IDE через MCP-серверы
- ✅ Мульти-агентность через SuperAgents OS
- ✅ Долговременную память через sqlite-backed MCP
- ✅ Индексацию кодовой базы через собственные MCP
- ✅ Workflow-оркестрацию через собственный движок
- ✅ Уникальные мета-возможности (символический слой, теневой агент), которых нет ни в одной коммерческой IDE

**Главное ограничение** — не версия OpenCode, а **CPU AMD E-350**. Но и оно обходится через:
1. Вынос тяжёлых задач в SuperAgents OS (внешние API)
2. Асинхронную архитектуру (фоновые задачи ночью)
3. Лёгкие MCP-серверы на Node.js
4. Трёхуровневую память (не держать всё в RAM)

**Философский сдвиг:** ты перестаёшь быть «пользователем IDE» и становишься **архитектором AI-экосистемы**, где OpenCode 1.19.4 — лишь один из узлов. И это, учитывая твой интерес к системному мышлению и многослойным моделям, — гораздо более интересный путь, чем просто обновление до новой версии.
