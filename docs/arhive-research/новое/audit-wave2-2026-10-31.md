## 1. Executive summary

Волна 1 закрыла вертикальные слои (memory/security/data-integrity/race/types/perf/UX/build/observability/logic/SOT/resilience). Волна 2 прошла **горизонтально по 12 прикладным категориям**, которые волна 1 либо не касалась, либо затрагивала вскользь: тестирование, документация, контракты, кэширование, LLM-специфика, auth-флоу, RBAC, input-validation, очереди, время, логирование, dead-code.

### Что нового относительно волны 1

- **Тестовое покрытие сломано системно:** coverage-gate `vitest.config.ts` применяется только к 5 «удобным» директориям (~10% src); 13 файлов в `debate-runtime/*.test.ts` — placeholder'ы `expect(true).toBe(true)`, проходят при любой поломке; критические сервисы (`key-service.ts` 1098 LOC, `debate-engine.ts` 820 LOC, `graph-service.ts` 605 LOC, `trace-service.ts` 560 LOC, `routing-policy-service.ts` 327 LOC) — с **нулевым** unit-покрытием.
- **Auth-flow — это один static `SYNC_SECRET`** без ротации, refresh, JWT, OAuth, MFA, password-reset; токен хранится в `localStorage` (7 панелей), а `KeyVault` подключён через **auto-unlock deviceKey из localStorage** — PBKDF2 600k итераций бесполезен, когда ключ лежит рядом с шифротекстом. Любая XSS = полная компрометация ключей + чата + трейсов.
- **RBAC существует как типы, но не enforced в runtime:** `role.permissions` (`system:admin`, `agents:spawn`) — placebo (parallel vocabulary `tool:*` в `AgentPermissionService`); `GovernanceService.assignRole` не вызывает собственный `can('direct')`; `PermissionMiddleware` fail-open при отсутствии `ctx.agentId` — 4 callsite'а (`capability-manager`, `orchestration-service`, `sandbox-service`, `ToolsPanel`) опускают `link.agentId`, sandboxed JS получает неограниченный доступ к `t-web`/`t-mcp`/`t-api-call` в обход capability/policy.
- **Multi-tenant IDOR на sync-server:** ~30 HTTP routes проверяют только shared bearer token; после auth — НЕТ per-tenant/per-user ACL. Любой клиент мутирует бюджет/issues/approvals/runs ЛЮБОЙ компании.
- **LLM-генерация агентов без валидации:** `agent-generator.ts:82-110` принимает LLM-сгенерированные `prompt`/`tools`/`permissions` как есть — без каталога инструментов, без anti-injection-сканирования. Один промпт-инъекционный description → персистентный малварный агент с `terminal`/`email_send`.
- **Browser-use sidecar: HTTP без auth + CORS localhost + SSRF-allow-loopback/RFC1918** — любой процесс в docker-сети или XSS на origin'е управляет браузером, делает скриншоты внутренних admin-панелей.
- **Кэш-ключи игнорируют `provider`/`temperature`/`maxTokens`:** `CacheService.generateKey` строит ключ только из `model|messages` — ответ для `temperature=0` возвращается для `temperature=0.9`; 4 DAL-репозитория грузят кэш один раз без `Dexie liveQuery`/`BroadcastChannel`, multi-tab UX сломан полностью.
- **Очереди — in-memory, без recovery:** `write-queue.mjs`, `ExecutionQueue`, `BatchProcessorService.running-state`, `AutonomyOrchestrator.goals/plans/tasks`, EventBus DLQ sink — все теряются на reload. `DeadLetterQueueService.retry()` — заглушка, инкрементирует счётчик без ре-эмитта.
- **Логирование персистит PII/токены:** `EventLogRepository.save()` пишет `JSON.stringify(ev.data)` в Dexie без санитайза (WAL-санитайзер применяется только к localStorage); `TraceRepository` хранит полный `input` (без slice) и `output` до 50 КБ; `LoggerService.flushPersist` + `exportLogs('json')` хранят/выгружают raw `meta` и `error` — комментарий «safe to log» в `llm-http-client.ts:286` **врёт**.
- **Initial bundle много-МБ:** `service-registration/index.ts` статически импортирует 80+ phase-файлов → весь `kernel/services/**` в entry; `groq-sdk` и `@google/generative-ai` в initial bundle; `monaco-editor` через `import * as monaco` ломает tree-shaking (3 МБ+ на `/editors`).
- **Cost manager включён, но enforcement отсутствует:** `CostManagerDecorator` сконфигурирован `{ logCosts: true }` без `pricing`/`dailyBudget`/`onExceeded`; `BudgetService.canUseGlobal` fail-open при `monthlyBudget=0` (default). Промпт-инъекция / debate-runaway / tool-loop = неограниченный spend.

## 2. Scope и метод

### Метод

Каждая задача запускалась как независимый `general-purpose` subagent. Подсказка включала:

- project root `/home/z/my-project/ai-os-new/`
- список Wave-1 категорий (для `cross_wave_hint="wave1"` разметки)
- output schema: `task_id, category, scope_checked, coverage_notes, findings[], no_findings_reason, top_risks`
- требование: CONFIRMED только при наличии `file_path + line_range + code evidence + clear trigger path`

Subagent'ы читали файлы напрямую через `Read`/`Grep`/`Glob` — без запуска `vitest`/`tsc` (node_modules не установлен в sandbox). Подтверждение синтаксических ошибок — через статический parse (`node:vm.Script` для F1 W2-T1).

### Ограничения

- **Нет runtime-верификации:** для находок с confidence `Needs runtime` — нужны npm install + vitest/playwright запуск.
- **Coverage оценён грубо:** subagent'ы указывали примерный % охвата; глубокий file-by-file audit 3098 src-файлов не выполнялся.
- **2 задачи перезапущены:** W2-T2 (Documentation) и W2-T12 (Dead Code) превысили 200 turns в первой попытке. После retry с focused-scope — обе успешно завершены (11 и 8 findings соответственно).
- **Verificator (W2-A) подтвердил 10/12 топ-находок**, 2 оказались false positive (V6, V7) — обновлённое состояние репозитория уже не содержит syntax-error в `ChatService.autoRouting.test.ts` и YAML-typo в `ci.yml`.

### Что не входило в scope

- `cli/superagents.mjs` — не открывался подробно (только проверка в W2-C на rate-limit surface).
- `e2e/*.spec.ts` — surface-level (только W2-T1 упоминал как smoke).
- `rivals*/` (18 директорий × ~10 файлов) — W2-T1 отметил «zero tests», остальное не копалось.
- `docs/audits/` (исторические аудиты) — не сравнивались с текущими находками для дедупликации.

### W2-001 · Permission middleware fail-open при отсутствии agentId

- **severity:** Critical
- **confidence:** Confirmed (verificator V1)
- **categories:** Authorization & RBAC, LLM (sandbox escape), Input Validation
- **file_path:** `src/kernel/services/tool-pipeline/permission-middleware.ts:44`
- **line_range_or_symbol:** `:44` (`createPermissionMiddleware.pre`)
- **evidence:**
  ```ts
  async pre(ctx) {
      if (!ctx.agentId) return { kind: 'allow' };   // <-- bypass
      const { action, resource } = resolveAction(ctx.toolId);
      const decision = await permissionService.evaluate(ctx.agentId, action, resource);
  ```
  Callsites, опускающие `link.agentId`:
  - `src/kernel/services/capability-manager.ts:19` → `toolService.execute(toolId, input, signal)`
  - `src/kernel/services/orchestration-service.ts:605` → `toolService.execute(toolId, input)`
  - `src/kernel/services/sandbox-service.ts:192-195` → `toolService.execute(params.toolId, params.input)`
  - `src/components/ToolsPanel/ToolsPanel.tsx:220` → `toolService.execute(selectedTool.id, parsedParams)`
- **problem:** Permission gate полностью отключается, если вызывающий код не передал `agentId` через `link`. `tool-executor.ts:563` прокидывает `agentId: link?.agentId` as-is → undefined → middleware возвращает `allow` ДО обращения к `AgentPermissionService.evaluate`.
- **risk:** Sandbox escape: любой скрипт внутри `t-code` (sandbox-service worker) вызывает `worker.postMessage({type:'cap_call', params:{toolId:'t-web', input:'https://evil.com'}})` → запрос уходит в сеть БЕЗ policy/preset/secret-protection. Аналогично через `CapabilityManager.executeTool` и `orchestration-service.executeToolNode`. Полностью аннулирует RBAC для каталог-инструментов.
- **repro_or_trigger:** ToolsPanel → Test на `t-code` с `params.toolId='t-web'`, `params.input={url:'https://attacker.com'}` через sandbox.
- **recommended_fix:** Удалить `if (!ctx.agentId) return { kind: 'allow' };`. Middleware должен fail-closed: при отсутствии `agentId` возвращать `deny` (или `ask` с reasoning `'no authenticated caller'`). Всем callers обязательно прокидывать `link.agentId` (даже системный `'orchestrator'`).
- **related_findings:** W2-053 (tool-loop-detector не подключён), W2-046 (tools без rate limit), W2-047 (tool-loop без budget)

### W2-005 · Single static SYNC_SECRET + auto-unlock deviceKey из localStorage

- **severity:** Critical

- **categories:** Authentication, Secrets-management, Crypto
- **file_path:** `server/ws-auth.mjs:25-47`; `server/sync-server.mjs:60-79`; `src/kernel/services/key-management/key-service.ts:399-413`
- **line_range_or_symbol:** `ws-auth.mjs:25` (`verifyWsUpgrade`), `sync-server.mjs:79` (`const SYNC_SECRET = AUTH_TOKEN`), `key-service.ts:403-409` (auto-unlock)

  - `key-service.ts:399-413`:
    ```ts

        if (!this.vault.isLocked()) return;
        const STORAGE_KEY = 'key-vault:device-key';
        let deviceKey = ssrSafeStorage.getItem(STORAGE_KEY);  // localStorage
        if (!deviceKey) {

            deviceKey = btoa(String.fromCharCode(...bytes));
    ```

- **recommended_fix:** (a) Per-session токены (HMAC-signed или JWT с коротким `exp`), отдельный refresh-токен с ротацией и серверным revocation list. Endpoint `/api/auth/logout`. (c) Удалить silent-plaintext-fallback в `unlockVault()`. (d) Удалить устаревший комментарий в `key-vault.ts:32-38`.
- **related_findings:** W2-015 (Bearer в localStorage в 7 панелях), W2-048 (vault comment врёт), W2-006 (eventLog stores PII), W2-033 (traces stores full input)
- **cross_wave_hint:** wave1 (S1-08 pattern)

- Initial bundle много-МБ из-за F1+F2+F3: groq-sdk + @google/generative-ai + весь kernel-services (через 80+ phase-файлов) в entry-чанке.
- framer-motion на критическом пути first paint (~50 КБ gzip).
- manualChunks неполный и хрупкий.
- EditorsPanel + monaco-editor = 3 МБ+ при открытии /editors.
- chunkSizeWarningLimit поднят, чтобы заглушить warnings.

### W2-C — Rate Limiting & Abuse Prevention

12 findings (см. тема I и сводную таблицу W2-045..W2-047 + W2-081..W2-082). Ключевое:

- Cost abuse через прямой chat-path без enforcement (F1+F2+F3): server-side budget gate ловит только Gateway runs, клиентские LLM-вызовы (chat, debate, race) — без hard-stop.
- Tool-loop без budget и per-tool rate limit: 32+ tool-вызовов на один chat, 480+ за debate.
- Fallback × retry × 429-loop мультипликатор: до 24底层 LLM-вызовов на один пользовательский запрос.
- SSE/WS resource exhaustion через long-lived connections.
- Manual wakeup + agent spawn без rate limit; autocycle guard обходит через `trigger='manual'`.
