## 1. Executive summary

Волна 8 фокусируется на поведении системы **под нагрузкой и в динамике** — capacity, realtime, LLM context/memory, tool design, vector ops, worker architecture, browser storage, distributed cache, multi-region, gateway, data quality, model eval. Это дополняет волны 1–7 (статика, контракты, безопасность, perf, persistence, realtime-pure, observability, testing).

### Что нового по сравнению с волнами 1–7

1. **Capacity hot-path map** построена для 14 критичных путей (chat send, stream read, tool-call, hybrid search, debate turn, memory read/write, export, bulk, WS broadcast, heartbeat tick, embedding batch, VectorSpace.match, cost recording). Подтверждено: 4 пути — O(N) по размеру корпуса/клиентов без лимитов (`W8-012`, `W8-013`, `W8-014`, `W8-015`); 0 load-тестов в репозитории (`W8-027`).
2. **LLM context & memory map** — инвентаризированы 32 LLM call-site. Найдена системная проблема: `CompressRouteDecorator` opt-in и **не включён по умолчанию** (`W8-005`), silent truncation в 12 call-site'ах, native prompt-cache (Anthropic `cache_control`, Gemini `cachedContent`) не используется (`W8-053`), `CacheDecorator` использует FNV-1a хэш-аппроксимацию вместо реальных эмбеддингов (`W8-045`).
3. **Cross-tenant изоляция отсутствует на нескольких слоях**: нет `tenantId` в `MemoryEntry` (`W8-040`, `W8-074`), одна глобальная `VectorSpace` на воркер (`W8-074`), одна глобальная очередь на 50 LLM-слотов (`W8-016`), sync-server использует единый `SYNC_SECRET` и не фильтрует broadcast по tenant (`W8-003`, `W8-148`).
4. **Production deployment gap**: Docker-образ шипит только `nginx + static SPA`; весь `server/` (sync-server, heartbeat, write-queue, autocycle-guard) **не попадает в прод-контейнер** (`W8-006`).
5. **Persistence антипаттерн**: `company-store.mjs` — синхронный JSON-файл-как-БД с read-modify-write на каждый запрос и `MAX_COST_EVENTS=20000` cap (`W8-001`); `write-queue.mjs` — одна глобальная Promise-chain, сериализующая ВСЕ записи во ВСЕ файлы ВСЕХ тенантов (`W8-002`).
6. **Worker durability отсутствует**: in-memory очереди теряют всё при крэше (`W8-083`), SIGTERM не дреинит (`W8-084`), wakeups at-most-once без DLQ (`W8-082`), `DeadLetterQueueService.retry()` не пере-ставит задачу (`W8-087`).
7. **Browser storage**: `clearAllData` оставляет ~70% Dexie-таблиц и большинство localStorage-ключей (`W8-104`); `localStorage.companyGateway.secret` хранится в plaintext в 7 панелях (`W8-098`); vault "encryption-at-rest" побит — device-key лежит в localStorage рядом с ciphertext (`W8-099`).
8. **Model eval methodology отсутствует**: A/B-сравнение делает 1 сэмпл на сторону (`W8-172`); eval-раны не пиннят temperature/seed/model-version (`W8-173`, `W8-177`); LLM-judge — stub (`W8-175`); `EvalService.compare` label-only без wired `setSecondary` (`W8-176`).
9. **Tool design**: 6 каталог-тулов экспонируются модели, но бросают "not implemented" (`W8-057`); runner-tools не оборачивают external output в `<external_data>` → prompt injection (`W8-011`); malformed tool args тихо становятся `{}` (`W8-058`).
10. **Multi-region полностью отсутствует**: single-region single-host sync-server (`W8-127`); backup локально в той же директории (`W8-129`); LLM-провайдеры на hardcoded глобальных endpoints без residency-контроля (`W8-130`); нет tenant-region mapping (`W8-135`).

## 5. Critical findings (полные карточки)

### W8-001 — company-store.mjs synchronous JSON-file-as-DB

- **Categories**: capacity, worker, data-quality
- **Severity**: Critical
- **Confidence**: Confirmed-by-code
- **File:Line**: `server/company-store.mjs:19-23, 29-38, 40-56, 185-196`
- **Evidence**:
  ```js
  const MAX_COST_EVENTS = 20000; // L19
  function readJson(file, fallback) {
    if (!fs.existsSync(file)) return fallback;
    const raw = fs.readFileSync(file, 'utf8'); // SYNC, blocks event loop
    return JSON.parse(raw); // O(file_size)
  }
  function writeJsonAtomic(file, data) {
    fs.writeFileSync(tmp, JSON.stringify(data, null, 2)); // SYNC
    fs.renameSync(tmp, file); // atomic but blocks
  }
  export function heartbeatCompany(id, note) {
    const all = listCompanies(); // readJson
    const org = all.find((c) => c.id === id);
    org.heartbeats += 1;
    saveCompanies(all); // writeJsonAtomic — full file rewrite
  }
  ```
- **Problem**: Каждая мутация (heartbeat, createIssue, setIssueStatus, startRun, finishRun, recordCost, decideApproval, enqueueWakeup, consumeAutocycleSlot) делает read-modify-write всего JSON-файла синхронно. Caps: MAX_COST_EVENTS=20000, MAX_ISSUES=20000, MAX_RUNS=5000, MAX_ACTIVITY=10000.
- **Risk**: При 50 cost-events/sec event loop полностью блокируется sync read+parse+write multi-MB JSON. Latency растёт O(file_size) per op. Lost-update race: два параллельных `POST /api/companies/:id/heartbeat` — оба читают full file, мутируют in-memory, `renameSync` — last-writer-wins, один heartbeat теряется. Двойное списание autocycle slot'ов (`consumeAutocycleSlot` читает `used=9`, оба пишут `used=10`).
- **Repro/Trigger**: 50 параллельных `POST /api/companies/:id/heartbeat` → финальный `org.heartbeats` будет < 50. Stress `POST /api/companies/:id/costs` at 20-50 RPS в течение минуты → p99 latency уходит в секунды при росте `costs.json` > 5000 записей.
- **Recommended fix**:
  1. Мигрировать на SQLite (WAL mode) с индексом по companyId+month.
  2. Если миграция отложена: кэш в памяти + батчевые appends через write-queue + асинхронные fs.promises.
  3. Обернуть ВСЕ read-modify-write в `enqueueDbWrite` (не только `/api/db`).
  4. Для autocycle counter — append-only event log + derived counter.
- **Guards present**: atomic write via tmp+rename; tmp cleanup on rename failure (P-MED-5); per-collection caps.
- **Guards missing**: async I/O; real DB; fsync() before rename (durability window); per-collection file sharding; optimistic-concurrency token; per-tenant file partition.
- **Related findings**: W8-002 (write-queue), W8-082 (wakeups at-most-once), W8-086 (autocycle racy), W8-146 (no idempotency).
- **Cross-wave hint**: wave-1 (architecture — single-process file-as-db), wave-2 (data-integrity).

### W8-002 — write-queue.mjs single global chain

- **Categories**: capacity, worker, backpressure
- **Severity**: Critical
- **Confidence**: Confirmed-by-code
- **File:Line**: `server/write-queue.mjs:14-22` (весь файл, 28 строк)
- **Evidence**:
  ```js
  let tail = Promise.resolve();
  export function enqueueDbWrite(fn) {
    const run = tail.then(() => fn());
    tail = run.catch((e) => {
      console.error('[write-queue] unit failed, chain continues', e);
    });
    return run;
  }
  ```
- **Problem**: Один module-level `tail` Promise разделяется между всеми файлами (`companies.json`, `wakeups.json`, `costs.json`, `issues.json`, `runs.json`, `approvals.json`, `activity.json`, `shared-db.bin`), всеми роутами, всеми тенантами. Нет maxQueueDepth, нет backpressure, нет per-key queue. `enqueueDbWrite` возвращает Promise, удерживающий req/res closures; под sustained overload цепочка растёт без границ в памяти.
- **Risk**: Один медленный или большой write (PUT `/api/db` до 50MB) блокирует все concurrent writes всех тенантов. ### W8-003 — WS: no maxPayload + O(C) broadcast + cross-tenant leak

- **Categories**: realtime, gateway, capacity
- **Severity**: Critical
- **Confidence**: Confirmed-by-code (cross-tenant leak demo возможно runtime)
- **File:Line**: `server/sync-server.mjs:1113-1155` (WebSocketServer init), `:128-144` (broadcastLive), `:1115-1154` (verifyClient), `:1157-1172` (wss.on('connection')), `:1177-1211` (reaper)

(d) `verifyClient` валидирует единый `SYNC_SECRET` — нет per-tenant token, нет room abstraction, нет фильтра broadcast по tenant.   3. `client.send(msg, (err) => { if (err) client.terminate(); })` callback-based; проверка `client.bufferedAmount > 1MB` → skip/terminate.

- **Guards missing**: `maxPayload` cap; per-tenant token/room; `bufferedAmount` check; global connection cap; callback-based send.
- **Related findings**: W8-148 (single shared secret auth), W8-140 (X-Forwarded-For trust), W8-147 (rate limit per IP only).
