## 1. Executive summary

Волна 6 — про глубину, а не повторение. По сравнению с волнами 1–5 добавлены:

- **Доказанный Critical на стороне контейнеров**: браузер-сайдкар запускается как root с `--no-sandbox` Chromium без `cap_drop`/`read_only`/`init`/`pids_limit` (W6-001). Dockerfile-комментарий про non-root — ложный.
- **Доказанный Critical в observability**: AgentObservabilityTab фабрикует гистограммы и P50/P90/P95/P99 из одного среднего (`latencyBuckets = 40 - latency*0.02`, `P99 = s.latency * 2.2`) — операторы видят вымышленные SLA (W6-003).
- **Доказанный Critical в budget**: `agentSpend` накапливается за всё время, а `agentBudgets` подаётся как месячный — после первого месяца все агенты «вечно превышают бюджет» (W6-004).
- **Доказанный Critical в SLA**: `error_rate = consecutiveErrors / usedRequests` — consecutiveErrors сбрасывается в 0 при первом успехе, поэтому SLA всегда «pass» даже во время активной деградации (W6-005).
- **Доказанный High-каскад №1**: отсутствие `Idempotency-Key` на LLM-запросах (W6-008) является центром трёх разных каскадов, в том числе 36×-биллинга при Groq-5xx (хотя сама цифра 36 — false positive, реальный множитель ~3×3=9, всё равно критично из-за отсутствия дедупа на стороне провайдера).
- **Доказанный High-каскад №2**: SSRF через http-адаптер (W6-021) → `http://127.0.0.1:3100/execute` → root-Chromium без sandbox → escape на хост.
- **Доказанный High-каскад №3**: распределённая блокировка debate-engine без fencing-токена (TTL=60s, сессия=30min) + singleton `ArgumentGraphService.build()` → перекрёстная порча графа между сессиями.
- **Мёрдж ReDoS-семейства**: 6 различных мест принимают пользовательские/админские regex без `isRedosPattern`-проверки — `prompt-security-service`, `policy-service`, `guardrail-service`, `message-index-service`, `project-workspace grepContent/searchFiles`, `router-request-classifier` (W6-023).
- **Мёрдж prototype-pollution-семейства**: `JSON.parse` без ревивера на LLM-tool-args, в `readJsonBody`, в `PluginSdkPanel`, в `safeClone`, в `sanitizeObject` — `safeJsonParse` существует в репозитории, но применяется непоследовательно (W6-051).
- **Один false positive** идентифицирован и помечен: W6-06-F01 «Groq 36-fetch retry storm» — математически невозможен при текущей композиции декораторов (см. раздел 10.A и раздел 13).

Из 158 сырых находок после дедупликации и слияния первопричин получено **65 уникальных W6-находок**: 5 Critical, 35 High, 18 Medium, 7 Low. Ещё 1 находка переведена в False positive.

### W6-024 — X-Forwarded-For rate-limit bypass

- **Categories**: Adversarial Input; Rate-limit bypass; Auth
- **Severity**: High
- **Confidence**: Confirmed
- **File:Line**:
  - `server/sync-server.mjs:90-98` (`getClientIP` trusts leftmost XFF)
  - `server/sync-server.mjs:100-112` (`checkRateLimit`)
  - `server/sync-server.mjs:191-203` (`checkWsRateLimit`)
  - `server/sync-server.mjs:1117-1121` (WS `verifyClient`)
  - `docker/nginx.conf:91,105` (`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`)
- **Evidence**:
  ```js
  // sync-server.mjs:90-98
  function getClientIP(req) {
    const forwarded = req.headers['x-forwarded-for'];
    if (forwarded) {
      const leftmost = forwarded.split(',')[0].trim();
      if (leftmost) return leftmost; // client-controlled!
    }
    return req.socket.remoteAddress;
  }
  // nginx.conf: $proxy_add_x_forwarded_for APPENDS client IP, preserving client-supplied XFF as leftmost
  ```
- **Problem**: `getClientIP` доверяет leftmost X-Forwarded-For entry, который client-controlled. nginx's `$proxy_add_x_forwarded_for` append-ит real client IP к existing XFF chain — client-supplied value остаётся leftmost. Attacker ротирует `X-Forwarded-For: <random-ip>` на каждом request чтобы получить fresh rate-limit bucket, bypass-ая и 30/min HTTP limit, и 10/min WS connection limit.
- **Risk**: Rate-limit bypass via distributed/spoofed clients. Authenticated attacker (или с leaked SYNC_SECRET) может flood REST API и WebSocket endpoint без throttling — cache-busting (unique query params), SSE connection flood (см. W6-030), rapid DB writes.
- **Repro / Trigger**: `for i in $(seq 1 1000); do curl -H "Authorization: Bearer $SECRET" -H "X-Forwarded-For: 10.0.0.$i" http://host:3001/api/companies; done` — all succeed, no 429.
- **Recommended fix**: Не доверять XFF by default. Либо (a) bind sync-server к 127.0.0.1 и trust `req.socket.remoteAddress`, либо (b) если behind known proxy, configure `TRUSTED_PROXY_COUNT` и take Nth-from-right XFF entry. Add global concurrency cap на in-flight requests. Consider token-bucket на `SYNC_SECRET` (не только IP).
- **Related findings**: W6-030 (unbounded SSE clients)
- **Cross-wave hint**: wave5

## 9. Системные темы

Сгруппированные системные проблемы, выходящие за отдельные находки:

### 9.1 Глубокая конкурентность

- **Cancel propagation обрывается на границе tool-loop** (W6-012): AbortSignal проверяется перед `runTool`, но не передаётся внутрь. Это системный gap — тот же паттерн в `chat-executor.ts:140` и `assistant-service.ts:398`.
- **Distributed lock без fencing — привычный паттерн** (W6-007): `cross-tab-lock-service` имеет TTL+heartbeat, но `LockAcquisition` контракт не содержит fencing-токена. Все consumers (debate-engine, chat-send-message, debate-engine-cancel) уязвимы к stale-writer split-brain.
- **Singleton services с mutable state в DI** (W6-014): `ArgumentGraphService` — пример. `container.ts:registerFactory` caches instance в `services` Map. Любой service с mutable state, зарегистрированный через `register(...)`, — кандидат на ту же проблему.
- **In-flight dedup maps с eviction без abort** (W6-015, W6-039): и `cache-decorator.ts:#inFlight`, и `chat-executor.ts:cacheInflight` evict-ят записи при capacity, оставляя orphaned HTTP calls. Системный паттерн «bounded map → evict oldest» без отмены underlying work.

### 9.2 Языковые ловушки

- **`JSON.parse` без reviver — системный gap** (W6-051): `safeJsonParse` с reviver существует в `src/shared/utils/safe-json.ts`, но применяется непоследовательно. 7+ мест используют raw `JSON.parse` на sensitive inputs (LLM tool args, HTTP body, plugin config, import files).
- **`safeClone` silent fallback** (W6-052): pattern «try structuredClone, catch → JSON roundtrip» скрывает data loss. Тот же паттерн в `kernel.ts:554` (SystemState snapshot).

### 9.3 Контейнеры / OS

- **Sidecar hardening отсутствует** (W6-001, W6-022, W6-028): browser-use sidecar — наименее защищённый контейнер в стеке. Root + no-sandbox + no cap_drop + no init + no pids_limit + no auth (JS version). Контраст с gateway/ui, которые имеют `user: 'node'`, `cap_drop: ALL`, `read_only: true`.
- **SIGTERM handling неполный** (W6-029): shutdown handler только `server.close()`, без `wss.close()`, без force-exit timer. Rolling updates leak connections, риск mid-write DB corruption.
- **Image pinning inconsistency** (W6-025, W6-026, см. сводную): main `Dockerfile` digest-pinned, но `docker-compose.quickstart.yml` gateway `image: node:22-alpine` (tag) и `docker/browser-use-sidecar/Dockerfile:9` (tag). Dependabot docker-ecosystem не покрывает sidecar.

### 9.4 Распределёнка

- **No Idempotency-Key — центр 3-х каскадов** (W6-008): центральный системный gap. Касается W6-009 (duplicate run), W6-040 (retry after partial tool-call), W6-038 (cost-manager 429 cascade).
- **Stale-write detection — мёртвый код** (W6-011): `isStaleSessionWrite` требует `incomingVersion > 0`, но production callers не ставят version. `mergeStaleSession` union-by-id logic никогда не достигается.
- **Saga checkpoint pattern сломан** (W6-010): side-effect персистится ДО checkpoint. `transaction.ts` saga primitive существует, но только guards kernel-level emit/persist deferral, не cross-file company-store side effects.

### 9.5 LLM-пайплайны

- **Retry-budget multiplication across layers** (W6-008, W6-015, W6-016, W6-038): RetryDecorator × ChatExecutor × provider SDK × CacheDecorator timeout — все имеют свои retry/timeout логики без координации.
- **Budget cap bypassed under concurrency** (W6-004, W6-041): и CostManager, и BudgetService имеют TOCTOU races на cross-request budget. Budget advisory, не enforced.
- **Cache stampede на streaming** (W6-039): `CacheDecorator.sendMessage` имеет `#inFlight` dedup, `streamMessage` — нет. Streaming — default chat path.

### 9.6 Комбинаторика фич

- **Feature-flag UI структурно сломан** (W6-018): `as unknown as Record<string, boolean>` cast — type lie. Все 7 toggles показывают default независимо от actual CONFIG value.
- **Race strategy × tool profile** (W6-020): race проверяется ДО tool resolution. Combinatorial interaction, не покрытый тестами.
- **Cross-session event subscription** (W6-019, W6-049): global `activeRequestIds` Set, global `directorStore` event subscription — оба нарушают per-session isolation.

### 9.7 Метрики

- **Fabricated metrics в UI** (W6-003, W6-031): AgentObservabilityTab фабрикует гистограммы из одного среднего. Cost-optimization per-model request counts double-counted.
- **Off-by-one percentile — системный паттерн** (W6-034): `Math.floor(len*p)` в `metrics-service`, `agent-health-monitor`, `profiler-utils`, `custom-metrics-service`, `ProviderDashboard`. 5 мест с одним и тем же багом.
- **Counter non-monotonicity across restarts** (W6-033): `counters`/`gauges` Maps in-memory only. На рестарте counter → 0 → rate-alerts ломаются.

### 9.8 Adversarial input

- **ReDoS-семейство** (W6-023): 6 мест принимают user/admin regex без `isRedosPattern`. `orchestration-service.ts:544` имеет защиту, но она не re-used.
- **SSRF через unguarded adapters** (W6-021, W6-022): `isPrivateIP` существует в `network.ts:49-60`, применяется в `tool-executor.ts:773`, но НЕ в `httpAdapter` или JS browser-sidecar.
- **XFF trust** (W6-024): `getClientIP` trusts leftmost XFF. nginx `$proxy_add_x_forwarded_for` сохраняет client-supplied XFF первым.

### 9.9 Toolchain / Supply chain

- **Production deps in devDependencies** (W6-026): `ws` и `playwright` в devDeps, но импортируются в production server code. `npm ci --omit=dev` ломает runtime.
- **Unpinned npx в deploy** (W6-025): `npx @sentry/cli` / `npx datadog-ci` без pin. Supply-chain RCE на deploy job.
- **No `--ignore-scripts`** (W6-036): любой transitive dep с `postinstall` execute-ся на CI runner с `GITHUB_TOKEN`.
- **No SBOM / image signing** (W6-037): consumers и incident response не могут verifiable-identity build artifacts.

### 9.10 Wire formats

- **SSE parser spec deviations** (W6-053): CR-only line endings, dropped `event:`/`id:`/`retry:`, `.trim()` вместо single-leading-space strip.
- **No compression anywhere** (см. сводную W6-11-F10): 50MB DB exports, 20k-entry lists — uncompressed.
- **Prototype pollution via `JSON.parse`** (W6-051): cross-cuts serialization, security, language pitfalls.

**W6-FP-01 — False positive**: «Groq retry storm 36 fetches» (W6-06-F01). Цитированное умножение `3 (groq-sdk maxRetries=2) × 4 (RetryDecorator maxRetries=3) × 3 (ChatExecutor MAX_429_RETRIES=3) = 36` — математически невозможно при текущей композиции декораторов:
