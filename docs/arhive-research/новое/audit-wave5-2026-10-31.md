## 1. Executive summary (что нового по сравнению с волнами 1–4)

Волна 5 сфокусирована на legal/privacy, транспортной безопасности, деньгах и точности, бизнес-инвариантах, интеграциях, DevEx и углублённой AI-наблюдаемости. По сравнению с предыдущими волнами обнаружены следующие новые системные проблемы:

1. **Critical-цепочка plaintext-PII-secrets-traces → shared-db.bin.** IndexedDB хранит API-ключи, внешние секреты, историю чатов, память и traces **в открытом виде** (по дизайну — `KeyVault` закомментирован). Endpoint `PUT/GET /api/db` принимает и отдаёт 50 MB binary dump всего этого без пер-записной redaction, под единственным `SYNC_SECRET` без tenant-изоляции. Любая утечка `SYNC_SECRET` = полный корпус данных пользователя за один запрос.

2. **Privacy: PII в `trace.input` без redaction.** `TraceService` дословно сохраняет последний user-prompt в Dexie `traces`. `sanitizeObject` покрывает только API-key patterns; `PolicyService.enforcePrivacy` запускается только на `COGNITIVE_STEP_COMPLETED` _output_, не на входящем prompt. Каждый введённый prompt остаётся в IndexedDB неограниченно долго.

3. **Float-точность в budget-gating.** `BudgetService.canUseProvider/canUseGlobal` сравнивают `<=` на float-USD; `recordSpend` не валидирует NaN/Infinity → один NaN заражает spend-ledger и отключает алерты навсегда. Серверный контур (`CostsPanel.tsx`) использует integer-центы, но локальный стек — нет. Несоответствие архитектур.

4. **Cost attribution на tool-calls отсутствует.** `ToolRunnerService.runWithTools` вызывает `llm.chat()` внутри tool-loop, но не эмитит `STREAM_END` и не вызывает `recordSpend`. Agentic loop из 5 раундов GPT-4o остаётся полностью невидимым для budget-gate и trace-service. `CHAT_TOOL_CALL`/`TOOL_EXECUTED` не имеют полей `cost`/`tokens`/`latencyMs`.

5. **HTTP-only nginx как default + ws:// без fail-closed.** `Dockerfile:74` `ARG NGINX_CONFIG=nginx.conf` — HTTP-only по умолчанию. `sync-server.mjs` принимает и `ws://`, и `wss://`, только warn'ит на `0.0.0.0`. На任何 non-loopback deployment это утечка `Authorization: Bearer` и API-ключей в открытом виде.

6. **Streaming latency fabricated.** `STREAM_END.ttft` объявлен в схеме, но **никогда не заполняется** в `chat-executor.ts:678-688`. `key-analytics.ts:132` затем фабрикует `ttft = latency * 0.4`. Routing-веса, основанные на TTFT, работают на синтетике.

7. **NVIDIA Enterprise fake compliance badges.** `nvidia-enterprise-service.ts:17-38` хардкодит SOC2/HIPAA/GDPR `certified: true`, SLA 99.9%, enterprise-регионы и фичи — всё это показывается в UI под trademark'ом NVIDIA. Не certified by NVIDIA. Ложные compliance-claims + trademark infringement.

8. **Conflicting copyright holder.** `LICENSE:3` → "Copyright (c) 2026 SuperAgents OS"; `README.md:736` → "MIT © 2026 Antigravity"; `docs/STRUCTURE.md:120` → "Maintained by: Antigravity". MIT sublicense attribution chain ambiguous.

9. **Webhook integration drift.** `X-Signature-256` HMAC scheme не соответствует ни Slack (`X-Slack-Signature`+timestamp v0), ни Discord (`X-Signature-Ed25519`). Retry только на `>=500`, не на 429 (Slack/Discord rate-limit). Подпись фактически не валидируется native receivers.

10. **Browser-use sidecar без auth.** `docker/browser-use-sidecar/server.py:45-58` — FastAPI на `:3100`, kill-switch только на gateway side; любой HTTP-клиент (curl, соседний контейнер в docker network) может submit задачу на browser automation без auth.

Волна 5 добавляет **100+ подтверждённых находок** (3 Critical после merge duplicates, 28 High, 60+ Medium, 20+ Low) и **3 follow-up артефакта** (verification, SDK reality check, GDPR data flow walkthrough).

**Evidence**: Service sends `X-Signature-256` HMAC-SHA256. Slack expects `X-Slack-Signature` (v0 scheme + `X-Slack-Request-Timestamp`). Discord expects `X-Signature-Ed25519` + `X-Signature-Timestamp` (Ed25519, не HMAC). Telegram uses `secret_token` query param.

**Problem**: Provider-native verification будет fail — подпись фактически игнорируется native receivers.

**Risk**: Webhook spoofing — любой может отправить fake alert в Slack/Discord если URL утёк (URL = credential).

**Fix**: Per-provider signing: Slack signing secret (X-Slack-Signature v0 + timestamp), Discord Ed25519 verify key, Telegram secret_token. Конфиг per-webhook `signingSecret`/`verifyToken`/`signingKey`.

### W5-032 — Webhook retry только на `>=500`, не на 429

- **Categories**: integration
- **Severity**: High | **Confidence**: Confirmed
- **File:Line**: `src/kernel/services/notification-webhook-service.ts:237`

**Evidence**: Retry logic: `if (res.status >= 500) retry;` — 429 не попадает.

**Problem**: Slack и Discord возвращают 429 при rate-limit. Webhook lost to DLQ без retry.

**Risk**: Critical alerts (`KEY_COMPROMISED`, `POLICY_VIOLATION`) молча теряются при rate-limit.

**Fix**: Retry on `429` (with `Retry-After` header respect) AND `>=500`. Exponential backoff with jitter.

## 9. Системные темы

### 9.1 Legal/Privacy (T1 + T2)

**Тема**: plaintiff storage of PII + отсутствующая privacy governance.

**Первопричины** (cross-task merge):

- Архитектурное решение "local-first без auth" → нет user/tenant → нет consent management → нет DPA с провайдерами → нет right-to-be-forgotten → нет privacy policy.
- `KeyVault` код существует, но **намеренно не подключён** — это cross-cutting decision affecting `apiKeys`, `external_secret:*`, потенциально `sessions`/`memories`/`traces`.
- `sanitizeObject` покрывает только API-keys → PII в traces/memory/debate content проливается везде.
- nginx forwarding `X-Real-IP`/`X-Forwarded-For` → IP PII утекает к провайдерам.
- Anthropic direct browser с `anthropic-dangerous-direct-browser-access: true` — нарушение ToS-friendly patterns и privacy.

**Связанные находки**: W5-001, W5-002, W5-003, W5-005, W5-006, W5-007, W5-008, W5-009, W5-035, W5-038, W5-039, W5-040.

### 9.2 Transport Security (T3 + T4)

**Тема**: HTTP-only default + ws:// accept + no Cache-Control + no trusted-proxy validation + no edge rate limiting.

**Первопричины**:

- "HTTP-only как dev default" документирован, но не fail-closed при non-loopback.
- `verifyClient` не инспектирует `info.secure`.
- `getClientIP` слепо доверяет `X-Forwarded-For` без `set_real_ip_from`.
- nginx `limit_req_zone` не может жить в `server{}` block — нужен custom image с `http{}`.
- Single replica, no origin shield.

**Связанные находки**: W5-010, W5-011, W5-012, W5-013, W5-028, W5-042, W5-043, W5-044, W5-045, W5-046, W5-105–W5-112.

### 9.3 Email/Webhooks (T5 + T6)

**Тема**: email infra отсутствует по дизайну (legitimate); webhook infra существует, но integration drift.

**Первопричины**:

- Webhook signing scheme generic (`X-Signature-256`) не совместим с Slack/Discord native.
- `testWebhook()` SSRF bypass + `connector-service.testConnection` unguarded.
- No replay protection на inbound verifier.

### 9.4 Money/Precision (T9)

**Тема**: float-USD во всём локальном cost-stack; server-side integer-центы не проброшены.

**Первопричины**:

- Hardcoded per-token prices в 7 файлах обходят `PricingService`.
- Нет `currency` ISO-4217 в контрактах.
- Display `toFixed(2)` vs enforcement raw float — рассинхрон.

**Связанные находки**: W5-018, W5-019, W5-020, W5-058–W5-063, W5-117–W5-119.

### 9.5 Business Invariants (T10)

**Первопричины**:

**Связанные находки**: W5-021, W5-022, W5-023, W5-064–W5-068, W5-120, W5-121.

### 9.6 DevEx (T11)

### 9.7 AI Traces & Cost Attribution (T12)
