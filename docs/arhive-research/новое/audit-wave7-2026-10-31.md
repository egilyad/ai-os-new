Multi-tab data loss (W7-ANA-007 Critical): per-tab in-memory state + KV last-writer-wins → silent loss revenue/usage data.

5. **HTTP semantics** — `301` redirect для POST→HTTPS вместо `308` (W7-HTTP-005 Medium, body loss на POST). SSE-парсер игнорирует `event:`/`id:`/`retry:`/`Last-Event-ID` (W7-HTTP-003 Medium): нет resume после обрыва.

## 5. Critical findings (полные карточки)

### W7-CRY-001 — KeyVault fail-open + deviceKey plaintext (CRITICAL)

**File:** `src/kernel/services/key-management/key-vault.ts:31-38, 144`; `src/kernel/services/key-management/key-service.ts:399-413`

**Evidence:**

```ts
// key-vault.ts:143-151
async encryptAllKeys(keys: ApiKey[]): Promise<ApiKey[]> {
    if (this._locked || !this.masterKey) return keys; // ← passthrough plaintext!
    ...
}

// key-service.ts:399-413
private async unlockVault(): Promise<void> {
    let deviceKey = ssrSafeStorage.getItem(STORAGE_KEY); // localStorage plaintext
    if (!deviceKey) {
        const bytes = crypto.getRandomValues(new Uint8Array(32));
        deviceKey = btoa(String.fromCharCode(...bytes));
        ssrSafeStorage.setItem(STORAGE_KEY, deviceKey); // ← plaintext localStorage
    }
    await this.vault.unlock(deviceKey);
    // catch → keys stored as plaintext (silent fail-open)
}
```

**Problem:** AES-GCM реализация корректна (свежий IV, PBKDF2 600k, non-extractable), но:

1. Master-ключ выведен из `deviceKey`, лежащего plaintext в `localStorage['key-vault:device-key']`
2. Любой JS в браузере читает deviceKey → `vault.unlock(deviceKey)` → расшифровывает IndexedDB
3. Fail-open fallback в `encryptAllKeys` (vault locked → passthrough plaintext) и `unlockVault` (catch → silent plaintext)

**Risk:** Компрометация всех LLM API-ключей (OpenAI, Anthropic, Gemini, OpenRouter). README прямо предупреждает, но код создаёт **ложное ощущение защиты** (`isEncrypted: true` выставляется, но НЕ снимается при fallback).

**Repro/trigger:**

1. Открыть DevTools → Application → Local Storage → `key-vault:device-key`
2. Скопировать значение
3. `await vault.unlock(copiedDeviceKey)` → `vault.decryptKey(ciphertext)` для любого ключа

**Recommended fix:**

1. Убрать fail-open в `encryptAllKeys`/`decryptKey` — бросать ошибку при locked
2. Мигрировать deviceKey из localStorage в WebAuthn / OS keychain / sessionStorage (привязка к вкладке)
3. В `unlockVault` catch → throw, не silent fallback
4. Обновить README — описать реальную threat model

**Cross-category hints:** W7-SES (sessions), W7-CRY-002 (LocalSecretStore тот же root cause), W7-ACC-014 (plaintext в IndexedDB by design).

**Cross-wave hint:** wave3 (config/secrets), wave5 (crypto).

### W7-SYN-001 — FederatedMemory sync не передаёт payload (CRITICAL)

**File:** `src/kernel/services/federated-memory-service.ts:204-232`

**Evidence:**

```ts
body: JSON.stringify({
    action: 'sync',
    nodeId: this.config.nodeId,
    nodeName: this.config.nodeName,
    role: this.config.role,
    timestamp: Date.now(),
}),
// ответ парсится только ради result.memoriesTransferred (число)
const count = typeof result.memoriesTransferred === 'number' ? result.memoriesTransferred : 0;
session.memoriesTransferred = count;
node.syncedMemories += count;
```

**Problem:** POST-тело sync-запроса содержит только метаданные — ни одной `MemoryEntry`, ни diff, ни even list ID. Любой peer может вернуть произвольное число → UI показывает «N memories synced» без реальной передачи.

**Risk:** Пользователь думает, что memory синхронизированы (UI показывает «X memories»), фактически их нет. Ложное чувство backup'а.

**Recommended fix:**

- Либо реализовать реальный payload (зашифрованный batch MemoryEntry с vector-clock/hlc)
- Либо убрать UI-панель и переименовать сервис в `FederatedNodeRegistry`

**Cross-category hints:** W7-SYN-002 (init не вызывается), W7-SYN-003 (syncInterval мёртвая), W7-SYN-010 (encryptionEnabled vanity).

**Cross-wave hint:** wave3 (data persistence).

### W7-UGC-009 — Нет CSAM/PhotoDNA/terror detection (CRITICAL)

**Files:** `src/kernel/services/wiki-brain/wiki-ingest.service.ts`, `src/components/ChatPanel/inline-markdown.tsx`, `src/kernel/services/rivals14/files-service.ts`

`SafeImage` в `inline-markdown.tsx:4-25` рендерит любой `https:` URL. `FilesApiService.upload` сохраняет `content.slice(0, 200000)` без классификации. Wiki ingest парсит markdown-источники без NSFW/CSAM-сканирования.

**Recommended fix:** Для любого бинарного content-pipeline: hash → check against industry databases (PhotoDNA Cloud API, Thorn NCMEC). Минимум — интеграция `IClassificationPort` с stub-реализацией + явный TODO.

### W7-ANA-007 — Multi-tab data loss (CRITICAL)

**Files:** `src/kernel/services/budget-service.ts:60-180`, `metrics-service.ts:147-174`, `usage-tracker.ts:49-69`, `provider-tracker.ts:142-166`, `contribution-service.ts:39-94`, `elo/elo-service.ts:88-107`

**Evidence:** Каждый analytics-сервис хранит данные в in-memory Map/Array, грузит из IndexedDB на init(), персистит через debounce. Cross-tab sync (`cross-tab-state.ts`) транслирует только circuit breakers/rate limits/debate state — **НЕ STREAM_END/costHistory/usage records**.

```
Tab A: costHistory=[e1], persist
Tab B: загрузил [e1], добавил e2, persist [e1,e2]
Tab A: добавил e3 (in-memory [e1,e3]), persist [e1,e3]
→ e2 потерян
```

**Risk:** Silent loss revenue/usage data при multi-tab. Самое серьёзное — `contribution-service`: вкладки не «сливают» дневные счётчики, а перезатирают.

**Recommended fix:**

- (а) Читать перед каждым persist (RMW с lock)
- (б) Использовать Dexie (transaction-safe) вместо KV-put
- (в) Broadcast analytics updates через существующий `cross-tab-state` BroadcastChannel + merge на приёме

**Cross-category hints:** W7-ANA-001 (alerts retention), W7-ANA-003 (counters не persist), W7-ANA-006 (dedup asymmetry).

**Cross-wave hint:** wave6 (concurrency на session).

## 9. Системные темы

### 9.1. HTTP/caching

**15 findings** — приложение browser-first, server-side HTTP surface ограничена `sync-server.mjs` + `cors-proxy.mjs` + nginx. Conditional requests (ETag/If-* /Range) **сознательно не используются** — правильный архитектурный выбор.

Главные дефекты:

- 301 вместо 308 для POST→HTTPS (body loss)
- SSE-парсер игнорирует event/id/retry/Last-Event-ID (нет resume)
- cors-proxy дропает критичные заголовки ответа (Retry-After, Vary, ETag)
- sync-server 429 без Retry-After

### 9.2. Web security deep

**5 confirmed + 6 coverage gaps** (subagent имел tool failures для server/).

Главный confirmed: **clickjacking** — CSP не имеет `frame-ancestors`, нет `X-Frame-Options`. One-line fix.

Coverage gaps: CSRF/CORS/WS-origin в `server/` требуют re-audit. По архитектуре (local-first, Bearer tokens) CSRF surface минимальна, но WS-upgrade к browser-sidecar критичен (computer-use loop).

### 9.3. Sessions/tokens

**12 findings** — auth-сессий нет by design (single-user local-first). Реальная поверхность = API-ключи + cross-tab locks + sync-server Bearer.

```
│       └─ FAIL-OPEN: catch → keys stored plaintext (key-service.ts:410)
├─ OnboardingWizard → keyService.addKey({status:'pending'}) (W7-ACC-013)
│   └─ Never validated → pending forever
├─ AddKeyModal → keyService.addKey({status:'active'})
│   └─ verifyKey HTTP call → optional
├─ sync-server WS upgrade → verifyWsUpgrade(token)
│   └─ timingSafeEqual + Origin check + rate limit ✅
└─ Browser sidecar WS → ??? (coverage gap W7-SEC-008)

Enforcement:
├─ KeyLifecycle.isRoutable(state) — excludes 'quarantined'
├─ BudgetService.canUseGlobal/canUseProvider — real quota gating
├─ UsageTracker.checkQuota — DEAD (W7-ANA-012), quotas не enforced
├─ PolicyService.enforcePrivacy — ✅
├─ PolicyService.enforceContentSafety — DEAD (W7-UGC-003)
└─ PromptSecurityService.scan — bypass-able (W7-UGC-001)

Bypasses:
├─ Vault fail-open (W7-CRY-001) — plaintext fallback
├─ Regex bypass via zero-width (W7-UGC-001) — prompt injection
├─ LocalSecretStore plaintext (W7-CRY-002)
├─ clearAllData не сбрасывает in-memory (W7-ACC-001) — keys могут оставаться
├─ deleteMemory не очищает embeddingCache (W7-ACC-002) — plaintext текст остаётся
└─ Hard-delete без tombstones (W7-SYN-006) — resurrection на sync
```

**Системные дыры идентичности:**

1. **Encryption theater** — vault существует, но bypass-able через deviceKey + fail-open
2. **Dead enforcement** — UsageTracker, enforceContentSafety, SecurityService — все registered, не вызываются
3. **Stale data after deletion** — embeddingCache, RAG chunks, traces, logs — не cascaded
4. **Cross-tab trust** — BroadcastChannel доверяет same-origin без HMAC
