## Выводы

### Где SAOS сильна (уникальное)

1. **Дебаты моделей** — мало кто делает это системно. Это «визитная карточка».
2. **Локальность/приватность** — всё в браузере, данные не уходят; ценность для конфиденциальных задач.
3. **Богатый UI** — ~200 панелей: дебаты, память, диагностика, конструктор. Конкуренты — в основном библиотеки без GUI.
4. **Когнитивные линзы и «кристаллы»** — уникальная терминология/концепции.

### Где SAOS отстаёт (что перенять)

1. **Плагинность** — AutoGen/CrewAI/LangGraph/n8n позволяют расширять. SAOS — монорепо.
2. **Графовая оркестрация** — LangGraph — золотой стандарт; у SAOS BuilderPanel есть, но граф-рантайм слабее.
3. **Мультиагентные протоколы** — A2A (Google), агентные стандарты. SAOS имеет Interop/Federation, но не стандартизирован.
4. **Долгосрочная память «модель-как-память»** — Letta/MemGPT лидируют (память как контекст модели); SAOS — отдельный слой.
5. **Оценка (eval)** — Promptfoo/DeepEval/OpenAI Evals более зрелые; SAOS eval-частично.
6. **Командная работа** — n8n/servers дают коллаборацию; SAOS — single-user (сейчас).

## Стратегия позиционирования

1. **Фокус на «дебаты + когнитивные конвейеры + локальность»** — это не просто «ещё один агентный фреймворк».
2. **Догнать по плагинности и граф-оркестрации** — это минимально необходимо для зрелости.
3. **Сделать eval-платформу** — чтобы доказывать преимущества цифрами (дебаты против single-shot).
4. **Не гнаться за «полным клонированием»** аналогов — брать только лучшие практики (см. `ROADMAP_11`).

### Ключевые тренды

1. **Протоколы — стандарт**: MCP (агент↔инструмент) + A2A (агент↔агент) становятся нормой интероперабельности.
2. **Eval и observability — встроенные** (не надстройка): LangSmith Engine, OpenAI tracing, OTel GenAI.
3. **Безопасность агентов** — отдельная дисциплина (OWASP Agentic, ACS).
4. **Sandbox / «компьютер»** как первоклассная абстракция (OpenAI Sandbox, Claude Agent SDK, Letta computers).
5. **Managed-рантаймы / «агенты как сервис»** (LangSmith Deployment, Claude Managed Agents, ADK Agent Runtime).
6. **Визуальные конструкторы** оркестраций (ADK Visual Builder, LangSmith Fleet, Dify, n8n).
7. **Код как действие** — генерация/исполнение кода — центральный механизм действия агентов.

### Рекомендации (обновлённые)

- **Интероперабельность**: поддержать MCP (уже есть) + A2A v1.0 (SPEC_09) — конкурентное преимущество.
- **Оркестрация**: взять концепцию AG2 Network (Hub+каналы) и графовый control-flow (LangGraph) — это ближе всего к нашему «браузерному OS».
- **Память/state**: у Letta — MemFS (виртуальная ФС памяти), shared memory, subagents с изоляцией контекста, compaction. Для нас критично сохранять состояние между вкладками/запусками.
- **Безопасность браузера**: главная зона риска — применить OWASP (SPEC_12), permission-модель + sandbox на агента (OpenAI Sandbox-паттерн).
- **Observability+eval с первого дня**: трассировка OTel-совместимая + eval-наборы (SPEC_04).
- **Позиционирование**: «мультиагентный OS для браузера» — ниша на стыке провайдеров, состояния и безопасности.
