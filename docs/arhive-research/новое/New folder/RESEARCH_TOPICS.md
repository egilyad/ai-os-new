# Исследовательские темы и эксперименты

> Эти темы не обязательны для продукта, но дают конкурентные преимущества и цифры,
> которыми можно подтверждать ценность. Формат: гипотеза → эксперимент → метрика.

---

## 1. Ценность дебатов против single-shot

- **Гипотеза**: мультиагентные дебаты повышают точность/полноту ответа по сравнению с одним прогоном.
- **Эксперимент**: на eval-датасете (вопросы с эталонами) прогнать (а) single-shot, (б) self-consistency, (в) дебаты 3–5 агентов.
- **Метрика**: точность, полнота, число фактических ошибок, стоимость, латентность.
- **Инструменты**: Eval-хаб (см. `NEW_COMPONENTS.md`), роутер, `DebateEngine`.

## 2. Аблации 75 техник

- **Гипотеза**: лишь часть техник реально улучшает качество; часть может вредить.
- **Эксперимент**: поочерёдно отключать каждую технику в дебате и сравнивать результат.
- **Метрика**: ELO/judge-оценки, согласованность, новизна аргументов.
- **Результат**: матрица «техника × тип вопроса» → основа для автоадаптации (см. `ROADMAP_02`).

## 3. Разнообразие агентов и качество

- **Гипотеза**: когнитивно разнородные агенты (разные роли/персоны/модели) дают лучшее покрытие пространства аргументов.
- **Эксперимент**: собрать дебаты из «похожих» и из «разнородных» составов (через `agent-diversity`).
- **Метрика**: покрытие тем, число уникальных идей, итоговая оценка.

## 4. Память: качество recall и влияние summarization

- **Гипотеза**: гибридный BM25+vector (RRF) превосходит каждый из методов по отдельности на корпусе SAOS.
- **Эксперимент**: бенчмарк retrieval (hit-rate, precision@k) на реальных данных памяти.
- **Дополнительно**: влияние sleep-engine/summarization на точность по мере роста памяти.

## 5. Семантический кэш: аппроксимация vs настоящие эмбеддинги

- **Гипотеза**: настоящие эмбеддинги дают заметно меньше ложных срабатываний, чем FNV-хэш-аппроксимация.
- **Эксперимент**: сравнить hit/miss и коэффициент ложных срабатываний на логе реальных запросов.
- **Результат**: решение, внедрять ли `IEmbeddingProvider` в кэш.

## 6. Автоадаптация стратегий

- **Гипотеза**: выбор стратегии дебата по типу вопроса (аналитический/креативный/правовой/…) улучшает результат.
- **Эксперимент**: классифицировать вопросы, подбирать стратегию из лидерборда (ELO), сравнить с фиксированной.
- **Метрика**: итоговая оценка, стоимость, время.

## 7. Мультиагентные протоколы (A2A)

- **Гипотеза**: стандартизация Interop по A2A упростит интеграцию с внешними агентами.
- **Эксперимент**: подключить внешнего агента (эмулировать) через A2A и проверить handoff.
- **Метрика**: время handoff, корректность передачи контекста.

## 8. Экономика провайдеров

- **Гипотеза**: маршрутизация «простое → дешёвое, сложное → мощное» (SemanticRouter) снижает стоимость без потери качества.
- **Эксперимент**: A/B через CanaryRouter; собрать стоимость/латентность/качество.
- **Метрика**: стоимость за успешный ответ.

## 9. Сравнение «дебаты vs совет (council) vs команда (crew)»

- **Гипотеза**: разные режимы мультиагентности оптимальны для разных задач.
- **Эксперимент**: прогнать один набор задач через Debate/Council/Crew/Forum/Graph.
- **Метрика**: качество, время, стоимость, наблюдаемость.

## 10. Долгосрочная память и «забывание» (Ebbinghaus)

- **Гипотеза**: кривая забывания (recency-веса) повышает релевантность recall.
- **Эксперимент**: сравнить recall с весами Ebbinghaus и без.

---

## Как организовать

- Заложить **Eval-хаб** (см. `NEW_COMPONENTS.md`) как инфраструктуру для всех экспериментов.
- Каждый эксперимент — отдельный «проект» (ProjectsPanel) с результатами в формате отчёта.
- Использовать `elo-service.ts` и `MetricsService` для единых метрик.
- Публиковать результаты в вики (`docs/wiki/research-*`).
