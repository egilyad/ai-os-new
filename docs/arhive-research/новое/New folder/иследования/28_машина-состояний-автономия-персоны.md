# Отчёт сабагента: Машина состояний, автономия, персоны, способности, топология

## 1. agent-runtime / agent-protocol

- `agent-runtime.ts` — `IAgentProjectRuntime` (init/runTask/runPrompt/pause/resume/getStatus/getProgress/getEvents): контракт верхнего уровня для задач агента в проекте. Реализация — AutonomyRunner (autonomy-runner.ts:22).
- `agent-protocol.ts` — `IAgentProtocolService` (реестр + AgentProtocolMessage: request/response/broadcast/error; capability chat/memory/tools/delegation/reasoning; TTL; traceId) — **паттерн «шина сообщений», но БЕЗ реализации** (только interface). Декларативный протокол, реально не задействован.
- Связь слабая: AutonomyRunner вызывает runtime.runTask; AgentFactory.execute() — низкоуровневый. Протокол и рантайм не соединены.

## 2. Autonomy

- **Нет уровней «1–10»**. Модель — фазовый автомат: AutonomyPhase = goal → planning → decomposition → assignment → execution → testing → revision → completed/failed (autonomy-types.ts:5,59). priority: low/medium/high/critical.
- AutonomyOrchestrator (autonomy-orchestrator.ts) — in-memory state-машина (goals/plans/tasks/runs в Map); `_projectManager/_workspace` **не используются** (void, :51-53) — декларативный.
- AutonomyRunner (autonomy-runner.ts) — связывает с IAgentProjectRuntime, autoDecompose, cancellable (AbortController). Тесты есть.

## 3. Persona

- PersonaService: дистилляция (styleNotesFor, extractJudgments, topPhrases); LLM-порт IPersonaLlmPort опционален; setDepth (traits/beliefs/values); promptFor (AgentCard-совместимо).
- PPRRecall / HippoRAG (ppr-recall.ts): настоящий Personalized PageRank (power method, α=0.85, dangling mass).
- LtMemoryService: тиры core/recall/archival, токен-оверлап, ссылки с временными окнами, neighbors BFS, associativeRecall = PPR, redactPii. Тесты есть.
- AssociativeContext: recall → PPR-расширение → дедуп-блок [ASSOCIATIVE MEMORY].
- SharedContextService: разделяемый контекст; защита credential_ref (regex SECRET_HINT). Тесты есть.
- PersonaMarketplace: сид-магазин (10 персон), install = флаг + downloads, рейтинг EMA. **UI-каталог, не связано с рантаймом**.

## 4. agent-diversity (DiversityScorer)

Веса semantic 0.4 / reasoning 0.3 / influence 0.2, штраф redundancyPenalty 0.3:

- semantic-distance.ts: попарный Jaccard, semanticDiversity = 1 − maxSim.
- reasoning-patterns.ts: детект паттерна (deductive/inductive/analogical/causal/adversarial/synthesis) по словарям RU+EN + рёбра.
- influence-tracker.ts: уникальные рёбра + противоречия + косвенное принятие.
- clustering.ts: агломеративная, one-hot паттерн + avgSemSim + influence.
  Итог overallScore + globalDiversityIndex; shouldSuppressAgent(). **Тестов нет**.

## 5. Capability

- CapabilityResolver (capability-resolver.ts): resolve(def) параллельно: personaToPrompt, skillToTools (permissions из маркетплейса), roleToPolicy (через IGovernanceService.checkCapability). Результат ResolvedAgent {prompt, tools, model, policyOk}.
- AgentFactory (agent-factory.ts): create → resolver.resolve → !policyOk → throw; createResolved; execute = LLM→Tools→Memory→Persist→Observe (fallback [echo:...]).
- Связь с permissions двойная и не соединена: роль через Governance (checkCapability), инструменты через отдельный AgentPermissionService (permission-middleware). CapabilityResolver не вызывает AgentPermissionService, middleware не вызывает Governance.

## 6. Permissions

- AgentPermissionService: rules-глобы, last-match wins; стек BASE(allow all)→preset→SECRET_PROTECTION→agent→saved; режимы read-only/guarded/workspace/full; circuit breaker (3 отказа ask→deny); fail-closed by design (без состояния → guarded).
- GovernanceService: capability grants, trust (EMA), policy rules (priority, deny wins, require_hitl), human-роли. Полный аудит.
- PolicyService как отдельный класс — нет (политики внутри Governance).
- **Fail-open места**: CapabilityResolver.roleToPolicy (нет gov → {ok:true}; catch → {ok:true}); GovernanceService.evaluate() (нет совпадения → allow); permission-middleware.pre (нет agentId → allow); BASE_PERMISSION_RULES = allow all. GovernanceService.checkCapability — наоборот fail-closed.

## 7. role-library

- LIBRARY_ROLES — ровно 28 ролей (RU-промпты, temperature, capabilities). **Используется только в UI RolesPanel/RoleLibrary.tsx** — в дебаты/агентов НЕ подключена.
- Дебаты используют отдельный PersonaSelector (debate-runtime/persona-selector.ts) — 10 вариантов по ключевым словам топика.
- Агенты топологии — третий набор (inline roleName/prompt в topology-defaults.ts).
- Итог: три параллельные системы ролей, не связанные.

## 8. Topology

- AuditorTopology (topology-defaults.ts): 62 узла agent; сборка normalizeAgentIdentity (Registry-first → AGENT_PROFILES → fallback) → assignArgumentStrategies → assignModelsToAgents. Рёбра router→агент→aggregator.
- **Расхождение**: AGENT_REGISTRY содержит только 15 канонических агентов; ~47 либо inline, либо в AGENT_PROFILES (комментарий «58 seeded workforce»/«25 nodes» — старые числа).
- topology-composer.ts: composeTopologyNodes() строит только из AGENT_REGISTRY (15) + router/aggregator — **не совпадает** с AuditorTopology (62).

## 9. Пробелы

- Декларативно vs реально: IAgentProtocolService без реализации; AutonomyOrchestrator с неиспользуемыми зависимостями; CapabilityResolver fail-open; PersonaMarketplace.install — просто флаг; LLM-порт опционален; топология 15/62.
- Дублирование: три системы ролей; два permission-механизма; два метода построения топологии; AGENT_PROFILES дублирует Registry (LEGACY DUPLICATES); PersonaCategory определён дважды.
- Нет тестов: agent-diversity/*, role-library, topology-composer, persona-marketplace, agent-protocol, unified-role/role-team, CapabilityResolver напрямую, GovernanceService.
