# Отчёт сабагента: Технический долг и рефакторинг UI-панелей

> Проход 4. Анализ 10 целевых панелей (структура, данные, действия, тесты, долг, рефакторинг).

## 1. ChatPanel (`ChatPanel/`) — ~3000 строк, 30 файлов

- Структура: ChatPanel.tsx (576), ChatSidebar (407), ChatInputArea (305), ChatMessagesSection (149), ChatHeader (148), ResponseCard (458), ChatHistoryEntry (306), MarkdownRenderer (273), CodeRunner (401), highlight-utils (297), inline-markdown (146), MermaidDiagram (81).
- Данные: useChatStore (Zustand), useKeyList, settingsService, uiPreferencesStore, orchestrator. **eventBus не используется**. `globalDefaults` читается через IIFE на каждый рендер.
- Действия: через стор (sendMessage/editEntry/forkSession/switchKey/switchModel/setAgent); seedChatDemo; storageAdapter для split-view.
- Тесты: 8 файлов (сильные).
- Долг: globalDefaults-IIFE (нужен useMemo); дублирование сборки guidance/veto (handleSend/handleRegenerate); Agent-attach `<select>` с хардкод-строками; MarkdownRenderer самописный парсер с дублированием code-fence; ~20 useState/useRef + 15 пропсов в ChatMessagesSection.
- Рефакторинг: хук useChatComposer; AgentSelector; утилита guidance/veto; CodeBlock; мемоизация.

## 2. DebatePanel (`DebatePanel/`) — ~7000 строк, 67 файлов (самая большая)

- Структура: DebatePanel.tsx (513), DebateTabContent (381), DebateWorkspacePanel (309), useDebatePanelSubscriptions (178), DebateChat (476), DebateVerdictPanel (450), HistoricalFiguresPicker (418), DebateSidebar (371), DebateStrategyBuilder (380), турнир/история/память/мастер.
- Данные: прямое чтение сервисов в useState-инициализаторах (debateService.getActiveDebateSession(), autoDebate.getResults(), getWinRates()); 7 подписок eventBus в useDebatePanelSubscriptions.
- Действия: прямое startDebate/addArgument/restoreDebateSession/linkDebate; eventBus.emit(NOTIFICATION).
- Тесты: 9 файлов (отличные).
- Долг: `baseProps` ~50 пропсов через {...baseProps} (нет контекста); useState-инициализаторы без кэша; глубокая обработка URL-параметров + history.replaceState (кандидат в хук); handleStart собирает участников тяжёлым инлайн-кодом (roleOrder захардкожен); useDebatePanelSubscriptions монолитный (17+ значений).
- Рефакторинг: контекст сценария; useDebateDeepLink; вынести сборку участников; разбить useDebatePanelSubscriptions.

## 3. BuilderPanel (`BuilderPanel/`) — ~1700 строк, 8 файлов

- Структура: CognitiveBuilder.tsx (397, React Flow), InspectorPanel (488), builder-nodes (265), ComponentPalette (135), WorkflowListPanel (176).
- Данные: useNodesState/useEdgesState от AuditorTopology; toolService; useKeyStore. Нет подписок eventBus.
- Действия: локальный стейт; сохранение через прямое **database.saveWorkflow**; деплой через orchestrator.mount.
- Тесты: слабые (только CognitiveBuilder.test.tsx 141; InspectorPanel не покрыт).
- Долг: handleSaveWorkflow/handleDeploy дублируют сериализацию топологии; прямой database.saveWorkflow в обход сервиса; разная обработка ошибок; aggregator/default AgentNode — маппинг-заглушки.
- Рефакторинг: serializeTopology(); единый workflow-сервис; тесты InspectorPanel/builder-nodes.

## 4. WikiPanel (`WikiPanel/`) — ~11 000 строк (большая часть — статические данные)

- Структура: WikiPanel.tsx (669) + wiki-components.ts (3219), wiki-articles.ts (3887), WikiArticleView.tsx (346), wiki-search/assistant/panels.
- Данные: чистые статические модули (articlesBySection, PANEL_ARTICLES, WIKI_PANEL_MAP, COMMITS_FEED, NAV_SECTIONS); searchWiki — утилита. Ни стора, ни сервиса.
- Действия: локальный стейт навигации (WikiView).
- Тесты: 3 файла.
- Долг: два файла по 3-4к строк данных (сплит/ленивая загрузка); **хардкод русских строк** при наличии пропса t (смешанная i18n, каст t as (k)=>string); инлайн-стили; дублирование паттерна «карточка».
- Рефакторинг: WikiSidebar; перевод на i18n; разбить блобы.

## 5. MemoryPanel (`MemoryPanel/`) — ~2000 строк, 16 файлов

- Данные: memoryService + eventBus memory:updated + configService + memoryGraphService; поиск — ручной debounce (setTimeout 300) + таймер 400 + AbortController.
- Действия: memoryService.clear/deleteMemory/search; configService.updateServices (semantic); экспорт Blob.
- Тесты: 4 файла.
- Долг: сложная ручная реализация debounce+abort (кандидат useDebouncedAsync); toggleSemantic содержит мёртвый код (`if (next) void Promise.resolve()`); инлайн activityMap/filteredMemories; Blob-даунлоад дублируется.
- Рефакторинг: useMemorySearch; удалить мёртвый код; общий debounce-хук; общая download-утилита.

## 6. ProviderManager (`ProviderManager/`) — ~8000 строк, 34 файла

- Структура: ProviderManagerContainer (443), ProviderManagerView (400), ProviderTableRow (768), InstalledProvidersView (599), ProviderCard (422), GroqKeyTable (396), OpenRouterKeyTable (400), BrowseModelsView (362), ModelCatalogView (260), ResourcePoolsView, RotationView, RoutingSLAView, модалки, commands.ts.
- Данные: useKeyStore; groupManager; 12 подписок eventBus.
- Действия: keyStore (checkHealth/importKeys/exportKeys/toggleKeyStatus/updateKey); groupManager.createKey; импорт FileReader.
- Тесты: 6 файлов (хорошие).
- Долг: Add Account-модалка — большой инлайн-JSX; хардкод английских строк и списка провайдеров ['gemini','groq','nvidia','openrouter']; импорт/экспорт дублируется; ручная клавиатурная навигация; ProviderTableRow (768) монолит.
- Рефакторинг: AddAccountModal; общая file-download/import-утилита; список провайдеров в конфиг; деление ProviderTableRow.

## 7. DashboardPanel (`DashboardPanel/`) — ~3000 строк, 15 файлов

- Данные: kernel.getState() + eventBus KERNEL_UPDATED; useKeyStore; settingsService; agentService; сеттинг читается IIFE с try/catch-фолбэком.
- Действия: useKeyStore.checkAllHealth; onNavigate.
- Тесты: слабые (только DashboardPanel.test 312; подкомпоненты не покрыты).
- Долг: фолбэк-объект пересчитывается; хардкод эмодзи и русских строк; подкомпоненты крупные без тестов.
- Рефакторинг: мемоизация сеттингов; i18n; тесты подкомпонентов.

## 8. LogsPanel (`LogsPanel/`) — 501 строка, 3 файла

- Данные: rootLogger.getBuffer() через **usePolling (1000мс)** — не событийная модель.
- Действия: rootLogger.clear/exportLogs; Blob.
- Тесты: LogsPanel.test (124).
- Долг: поллинг каждую секунду вместо событий; повторяющиеся тернарные цепочки фильтров; Blob-даунлоад.
- Рефакторинг: перейти на eventBus-push; вынести фильтр; общий download.

## 9. TracesPanel (`TracesPanel/`) — ~2200 строк, 8 файлов

- Данные: cognitiveService.getTraces() + eventBus trace:updated.
- Действия: cognitiveService.deleteTrace.
- Тесты: TracesPanel.test (235).
- Долг: хак с 3-секундным таймером-фолбэком isLoading; ручной visibleCount (100) вместо виртуализации (автор: «hundreds of motion.div rows jank»); монолит 718 строк.
- Рефакторинг: виртуализация; вынести строку трейса.

## 10. TimeMachinePanel (`TimeMachinePanel.tsx`) — 370 строк, 1 файл

- Данные: timeMachineService.getSnapshots() (синхронно).
- Действия: createSnapshot/restoreSnapshot/deleteSnapshot/compareSnapshots + ручной refresh().
- Тесты: отсутствуют.
- Долг: монолит без тестов и без обработки ошибок; нет событийной подписки (ручной refresh); инлайн-палитра SCOPE_COLORS.
- Рефакторинг: SnapshotCard; единая обработка ошибок; тесты.

## 11. ChatDock (`ChatDock/`) — 328 строк, 2 файла

- Данные: только useChatStore sessions. Действия: локальный стейт; не отправляет сообщения.
- **сты: ChatDock.test (29).
- Долг: поле unread никогда не обновляется (мёртвая фича); хардкод английских строк; прямой доступ к e.role/e.text.
- Рефакторинг: реализовать unread или удалить; i18n; подключить к реальной отправке.

**Общий тренд:** панели уже декомпозированы и покрыты тестами, но страдают от (1) монолитных контейнеров с дрилингом пропсов (Debate), (2) хардкода строк при наличии i18n, (3) дублирования инфраструктурных утилит (download/import/debounce), (4) отсутствия единого workflow-слоя (Builder). Порядок: DebatePanel (контекст) → общие утилиты → i18n → тесты.
