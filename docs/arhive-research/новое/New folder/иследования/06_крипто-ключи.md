# Отчёт сабагента: Безопасность, ключи и хранение

## 1. KeyVault

`KeyVault implements IKeyVaultService` — `src/kernel/services/key-management/key-vault.ts`; интерфейс `IKeyVaultService` — `contracts/key-vault.ts`. Методы: unlock(password) (46), lock(keys?) (81), isLocked() (91), encryptKey/decryptKey (95/114), decryptAllKeys/encryptAllKeys (131/143), stripPlaintextKeys (153), purgeKey/purgeAll (160/164). Крипто: AES-GCM-256, PBKDF2-HMAC-SHA-256 600k итераций (ITERATIONS=600_000), salt 16B, IV 12B; мастер-ключ extractable:false. Хранит только salt в localStorage (key-vault:salt). **Vault преднамеренно не встроен** — шапка файла: «Vault system removed — keys stored as plaintext». encryptAllKeys/decryptAllKeys короткозамыкаются при locked; decryptKey возвращает ciphertext как есть (:115).

## 2. deviceKey — fail-open

`KeyService.unlockVault()` (`key-service.ts:399-413`): ключ `key-vault:device-key` в localStorage; если нет — генерится 32 байта (btoa) и пишется в localStorage (407); vault.unlock(deviceKey) (409). Catch (:410-412) молча глотает ошибку — «non-fatal». Защита косметическая.
Отдельный `SecurityService` (`src/kernel/security.ts`) — AES-GCM + PBKDF2 600k, salt security_salt; регистрируется (runtime.ts:240), но нигде не инициализируется паролем.

## 3. LocalSecretStore / ExternalSecretsService

`LocalSecretStore implements SecretStore` — `local-secret-store.ts`: IndexedDB keyValue (префикс external_secret:${path}, индекс external_secret_index), plaintext at rest (комментарий). `ExternalSecretsService` — фасад (local/vault/aws/gcp), activeBackend; getSecret fallback на local только при исключении. Атомарность: set/delete — две неатомарные операции (setKv + обновление индекса; 40-58), индекс может рассинхронизироваться.

## 4. Крипто-примитивы

WebCrypto (AES-GCM, PBKDF2, SHA-256 для отпечатков). `utils/constant-time.ts` — constantTimeEqual (XOR-цикл), не используется нигде. `utils/hash.ts` — stableHash (FNV-1a 32-bit, не криптографический). `utils/safe-json.ts`, `utils/pii-redact.ts` (redactPii; применяется на границах персистенции памяти).

## 5. Permission/Policy/Governance/AgentPermission

- `AgentPermissionService` (`permissions/permission-service.ts`): per-agent (mode/preset/rules/consecutiveDenials); evaluate(agentId,action,resource) → PermissionDecision через evaluatePermission (`contracts/agent-permissions.ts`) — last-match wins; база BASE_PERMISSION_RULES=[{action:'_',resource:'_',effect:'allow'}] → fail-open; SECRET_PROTECTION_RULES добавляют ask для _.env/_.key/*.pem; Hermes-подобный circuit breaker (3 отказа → deny); getState/hasState.
- `PolicyService` (`policy-service.ts`): политики latency/privacy/cost/rate_limit/content/custom; enforcePrivacy; checkAgentPolicy; isReDoSPattern; хранит keyValue plaintext.
- `GovernanceService` (`trust/governance-service.ts`): grantCapability/checkCapability, feedback/trustOf (EMA), addPolicy/evaluate; **evaluate возвращает {decision:'allow'} при отсутствии совпадения (:171) — fail-open**; deny при равном приоритете.

## 6. Trust/CapabilityTrust/Provenance/Audit

- `CapabilityTrustService` (`capability-trust/capability-trust-service.ts`): ступени declared → discovered → verified (canPromote), markStale; in-memory, не персистится.
- `ProvenanceService` (`trust/provenance-service.ts`): граф узлов/рёбер с временными окнами (validFrom/validTo); sandboxLevelFor; НЕ hash-chain.
- `AuditService` (`ops/audit-service.ts`): единственный настоящий hash-chain: auditHash = FNV-1a(prevHash|seq|actor|action|target|detail|ts), genesis '00000000', append/verify (реплей, обрезка 100k). FNV — не криптостойкий.

## 7. Passphrase-UI

Нет. AddKeyModal — без пароля; SettingsPanel.tsx:365 — «passphrase encryption via KeyVault is not wired up yet»; SecurityPanel не существует; нет вызова securityService.initialize/vault.unlock(passphrase).

## 8. Хранение/экспорт/импорт; useKeyStore

- Канонически: IndexedDB (Dexie), таблица apiKeys (DexieKeyStore, dexie-storage.ts:66). KeyRegistry.saveKeys() → doSaveKeysWithSnapshot (key-registry.ts:586) → vault.encryptAllKeys(snapshot) (589) → keyStore.bulkPut. Но vault разблокирован deviceKey → на практике plaintext.
- Legacy localStorage `super_agents_api_keys` (key-service.ts:44); миграция через bootstrap-key-init.ts.
- В памяти: KeyRegistry хранит ключи открытым текстом (key-registry.ts:652).
- Экспорт: exportKeys() → buildExportData; если encryptKey вернул null (locked) — бросает исключение (157-158). Импорт: importKeys (key-registry.ts:843) пропускает isEncrypted:true (skippedEncrypted, 118-121).
- useKeyStore (Zustand): addKey→groupManager.createKey, exportKeys, importKeys (ф-print FNV), refresh читает напрямую getDexieDb().apiKeys.toArray() (в обход vault).

## Резюме

Крипто-каркас есть (KeyVault, SecurityService), но оба обходят; deviceKey в localStorage ⇒ fail-open. Осевая точка шифрования at-rest — KeyRegistry.doSaveKeysWithSnapshot (заменить deviceKey на passphrase; при locked — отказ). Fail-open закрыть (GovernanceService.evaluate, AgentPermissionService, decryptKey). Нужен passphrase-UI. LocalSecretStore — атомарность+шифрование. Три независимых механизма прав — свести в единый decision point.
