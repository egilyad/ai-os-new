# Отчёт сабагента: Внешние интеграции, событийный API, трансляция

## 1. event-bridge

- EventBridge (event-bridge.ts) + ProjectionRegistry + phase0-event-bridge.ts.
- Механика: subscribeAll(payload) → KernelEvent {type, payload, timestamp, seq} → registry.dispatch(kernelEvent). Буферизация: bufferEvent() в preStartBuffer до start(); при start() сначала subscribeAll (гонка P2-43), затем проигрывание буфера. После stop/start буфер не восстанавливается.
- Фильтрация: пропускаются 4 когнитивных (cognitive:trace:updated, cognitive:step:*, cognitive:decision:made).
- ProjectionRegistry: dispatch с индивидуальным try/catch; единственная реальная проекция — RouterProjection.

## 2. interop

- A2AService (a2a-service.ts): реклама (advertise→InteropRepository.putAgent), discover (по capability/protocol), negotiate (untrusted не принимает автоматически), handoff (HandoffRecord, HANDOFF_DISPATCHED), reportError. **Работает только loopback — транспорт не передаётся (undefined), реальной сети нет.**
- CoordinationService: Manifest 2.0 (in-memory Map), cross-runtime handoff, рынок (openListing/bid/award — победитель по минимальной цене), route (score = перекрытие capability − загрузка − цена + доверие), контракты (proposeContract/acceptContract/completeContract). **Реально подключён к crewService/agentForgeService.**
- FederationService: пиры (addPeer/listPeers/heartbeat), trust-gated dispatch (untrusted → отказ; transport.send иначе loopback). **Транспорт не реализован нигде.** interop-demo-seed создаёт loopback-пир «Демо-стенд».
- GatewayService: ingress() нормализует в GatewayEnvelope (ring-buffer MAX_BUFFER=300), эмитит GATEWAY_INGRESS; translate(); recent(limit). **Только in-process API — сетевого endpoint нет.**
- McpHarnessService: reconnectAll/proxyTool (авто-переподключение; недоступен → {handoff:true, reason:"BLOCKED-RUNTIME"})/health. Реально работает поверх MCPService.
- translation.ts: toEnvelope/translateEnvelope (A2A↔MCP↔ACP↔webhook↔websocket↔internal), a2aError. Чистая логика.
- Итог: логика/персистенс реальны; **транспортный слой IInteropTransport отсутствует** (контракт есть, реализаций нет) → A2A/федерация «по проводу» заявлены, но не работают.

## 3. webhook

- Каталог services/webhook/ пуст. Реальный: notification-webhook-service.ts.
- Отправка: fetch POST, AbortSignal.timeout; форматтеры slack/telegram/discord.
- SSRF: isValidUrl() перед каждой отправкой (https: + !isPrivateIP, читается из network); та же проверка в addWebhook/updateWebhook.
- Подписки (6): system:notification, key:quota:exceeded, key:state:changed, key:compromised, chat:stream:error, policy:violation.
- Надёжность: ретраи backoff+jitter, maxRetries; после исчерпания WEBHOOK_DELIVERY_FAILED + DLQ; HMAC X-Signature-256 (SHA-256). Персистенс Dexie KV (max 50).
- compromise-webhook-service.ts: входящий fail-closed (секрет+HMAC+raw body), но **нет HTTP-точки входа в продакшене (SPA)** — «живой путь — ручной manuallyCompromise».

## 4. telegram-service

- Отдельный per-agent мост (не связан с NotificationWebhookService).
- setBot(agentId, {botToken, allowedChatIds, channelId}) — валидация токена, JSON в agentMemory (kind:'telegram'); getBot читает последнюю валидную; bridgeMessage → Bot API sendMessage (chat_id), обрезка 4096, ретраи 3× (не ретраит 429/4xx/Timeout), timeout 8с.
- Безопасность: C-3 регулярка ^\d{5,}:[A-Za-z0-9_-]{20,}$; whitelist allowedChatIds. **Пробел: токен в открытом виде в agentMemory (attacker-writable), не через secret-store/key-vault.**

## 5. integrations/ — отсутствует

- connector-service.ts: карточки коннекторов, testConnection (HEAD, 10с), generateWebhookUrl. **Без реальных API/OAuth.**
- ConnectorsPanel/connector-constants.tsx: демо-карточки (Slack, Discord, Telegram, Google Workspace/Drive, Dropbox, Gmail, GitHub OAuth, Notion) — все заявлены, без реализации (только disconnected).
- Дополнительно: gatewayApi.ts (local-dev HTTP sidecar loopback + Bearer + SSRF-allowlist).

## 6. Панели

- ConnectorsPanel: сетка коннекторов, подключение/отключение (custom → testConnection HEAD; без endpoint → просто connected, пометка «Simulated»), добавление кастомного, вкладка Webhooks. Внешней логики нет.
- MCPPanel: реальное управление MCP-серверами через mcpService. Реальная интеграция.
- WebhooksPanel (файл): реальный CRUD через notificationWebhookService.
- SessionBindingsPanel (файл): read-only мониторинг привязок сессия↔ключ (session affinity), polling 15с.

## 7. Итог

**Реально:** EventBridge+ProjectionRegistry; NotificationWebhookService (SSRF, HMAC, ретраи, DLQ); TelegramService; McpHarnessService+MCPPanel; CoordinationService; Translation; GatewayService как in-process.
**Заявлено, не работает:** IInteropTransport (нет реализации); A2A/Federation только loopback; Gateway без сетевого endpoint; внешние коннекторы (декоративные); compromise-webhook без HTTP-входа.
**Пробелы:** Telegram-токен в открытом виде (→ key-vault); ConnectorService.testConnection без SSRF; дублирование telegram-каналов.
**Что расширить:** реализовать IInteropTransport (по образцу gatewayApi); Gateway как реальный HTTP ingress/egress; подпись/верификация между пирами; heartbeat/обнаружение; перенос токенов в vault; реальный слой OAuth для коннекторов.
