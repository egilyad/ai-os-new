## 2. startDebate и почему strategy «игнорируется»

`DebateSyncManager.startDebate(topic, participants, strategy='round_robin', maxRounds=5, …)` (`debate-sync-manager.ts:260`). Стратегия не передаётся в движок; транслируется в топологию + форсированные quality-техники: `resolveStrategyConfig` (`debate-session-bridge.ts:276`). Если `builtin.` — `builtinExecutionHints` → `ROOT_TO_EXECUTION` (:189): sequence→linear, debate_graph→roundtable, critic_loop→roundtable, voting→roundtable, peer_review→judge; иначе `buildTopologyForStrategy` (:308) — switch даёт отдельные топологии только для sequential/tree(judge-роли)/judge/red-blue/tournament; все остальные enum → `default:` → `buildRoundtableTopology()` (:338). Итог: различие стратегий реализовано через quality-техники и промпт-блоки по session.strategy, а не через топологию.

## 4. Фазы/шаги внутри раунда

`roundLoop` (`debate-pipeline-builder.ts:142-465`) потребляет события из generateRoundEvents(). Шаги:

1. `round:start` → transition('deliberating'), incrementRound, бюджет (:179-193)
2. `agent:thinking` → setAgentPhase ('thinking') (:194)
3. `agent:responded` → setAgentPhase('streaming'), estimateConfidence, memory.recordStep({type:'claim'}), timeline, DEBATE_AGENT_RESPONDED (:205-233)
4. `round:end` (:251): postProcessor.processFactCheck (факт-чек, :262-279), RAG-индексация (memoryExtractor.extractFromTimeline + retriever.indexUnits, :284-314), allErrored → пауза/фейл (:316), gatherClaims → consensus.evaluate (триангуляция, :333-343), earlyExitConfidence (:347), policyEngine.evaluate → executePolicyActions (:367-403).

Затем `consensusAndFinalize` (:467-624): transition('consensus') → gatherClaims → consensus.evaluate → transition('summarizing') → conclusionEngine.generateVerdictWithLLM() (таймаут 30с) → validateAndSaveVerdict → transition('completed').

`debate-phase-handler.ts`: onPhaseChange → скоринг: memoryExtractor.extractClaims → blindEval/blindly или evaluator.scoreArguments → bayesianJudge.update → stanceDriftTracker → qualityCollector.record/finalizeSession (:91-331).

Реально исполняемый порядок спикеров — `DebatePolicy` (`debate-policy.ts`) proposeNextTurn (адаптивный порядок + bid).

Подключение к исполнению: (1) через топологию (только sequential/tournament/red-blue/judge/tree-of-thought); (2) через промпт (isSocratic/isArgumentTree/isConstrained, блоки в `debate-prompt-builder.ts`); (3) через quality-техники (strategyQualityForced: cross-examination→['cross-examination'], tournament→['adaptive-order'], jury_trial→['blind-evaluation','bayesian-judges'], moderated→['critic'], free_for_all→['insight-bus']); (4) DebateInterpreter (debate-interpreter.ts) для аналитики.
Итог: интерпретатора DSL-примитивов нет.

## Вывод для интерпретатора

Движок исполняет только DebateTopology; «стратегия» = топология + quality-техники + промпт-блоки. Интерпретатор должен компилировать StrategyPrimitive в (а) топологию, (б) маску qualitySettings, (в) порядок ходов поверх DebatePolicy, переиспользуя LLM-цикл/бюджет/консенсус как есть.
