# Отчёт сабагента: Конвенции разработки (чек-лист)

## 1. DI-регистрация сервиса

- `src/kernel/container.ts`: `register(id,instance)` (eager singleton, :48), `registerFactory` (lazy, :57), `registerTransient` (:66), `override` (:70), `get/getOptional` (:88/140).
- Пример (`service-registration/phase2-infrastructure.ts:40`): `register('chatBookmarksService', (c) => new ChatBookmarksService({ eventBus: c.get(...), database: c.get(...), logger: c.get(...) }))`.
- Хелпер `register` (helpers.ts:53) → registerFactory + lazy через Lifecycle (init/start/destroy).
- 3 шага: файл фазы `phaseNN-<name>.ts` (export const registerPhaseNN: Phase), подключение в `index.ts` (:93-172), при init/start — добавить в `INIT_TIERS` (bootstrap-phases.ts:35), критический — в `CRITICAL_SERVICES` (:15).
- Bootstrap: kernel (bootstrap.ts:91) → services (initServices, тиры Tier0..7, checkDependencies :243) → topology (:385) → startAll (:412) → post-start (GroupManager sync, KeyStateStore seed, DebateService.init, MemoryWatchdog).

## 2. Контракт

- `src/kernel/contracts/<domain>.ts` (типы + I<Service>). Реализация в services/. Связь по строковому токену DI; интерфейс — тип: `lazyService<I<Service>>('token')`.
- Паттерн `Result<T,E>` (`contracts/results.ts`): для ожидаемых ошибок бизнес-логики; не для программных.

## 3. Событие

- `src/kernel/events/event-registry.ts` — единственный источник: `KEY_X: event('domain:action', z.object({...}))`.
- НЕ редактировать event-names.ts/types/event-map.ts/EventValidators (ре-экспорт). Имя namespace:name; payload — Zod; дубликаты — структурно идентичные схемы (тест-дрейф). Горячие — декоративные (помечать @internal). Emit: eventBus.emit(EVENTS.KEY_X, {...}); подписка on/onSafe.

## 4. Панель (4 места + тест)

1. `src/components/<Panel>/<Panel>.tsx`; 2. lazy-import в `route-imports.ts` (PANEL_COMPONENTS); 3. пункт в `route-registry-*.ts`; 4. i18n в en+ru; 5. тест `<Panel>.test.tsx` с моком useTranslation.

## 5. Стор (Zustand)

- Зависимости через `*-deps.ts` (ре-экспорт из kernel/instances). Подписки на eventBus в инициализаторе (ensureInitialized), возвращать unsubscribe; очистка destroy()/HMR. Hydration из Dexie, флаг isLoaded; события = дельта. Для тестов override/vi.mock.

## 6. Утилиты

- sanitize: `src/shared/utils/sanitize.ts` (sanitizeObject/sanitizeError/sanitizeApiKey/sanitizePromptVar).
- runGuarded — идиом панели (try/catch + setError + уведомление), не общая утилита.
- EventBus валидирует Zod, невалидное → dead-letter; HOT_EVENTS минуют defer.

## 7. lazyService

- `src/kernel/service-helper.ts:15` — Proxy (резолв при первом обращении, кэш, байндинг, fallback). Использовать из UI/сторов без циклов; до регистрации — fallback или ServiceNotRegisteredError; после — invalidateLazyServiceNotFound (helpers.ts:67).

## 8. Тесты

- `vitest.config.ts`: jsdom, globals, setup-light.ts (jest-dom, fake-indexeddb, mock Worker, crypto.randomUUID). Рядом с исходником. Store-тесты: vi.mock + vi.hoisted + beforeEach reset. Дрейф событий: event-registry.test.ts. Паритет i18n: i18n-keys.test.ts.

## 9. «Золотой сценарий» фичи

1. Контракт → 2. Сервис → 3. Событие → 4. Регистрация (фаза+тир) → 5. lazyService в instances/services-core.ts → 6. Стор (+hydration) → 7. Панель (+lazy+route+i18n) → 8. Тесты → 9. Проверка (typecheck/lint/тесты/circular/cruise/docs).

## 10. Чего НЕ делать

- Не импортировать React/UI в kernel. Не редактировать автогенерируемое (wiki, каталоги, event-names). Не менять автоматические хвосты event-registry. Не оставлять голые await без runGuarded. Не коммитить без просьбы.
