# Отчёт сабагента: Инструменты, песочница, browser/computer, MCP

## 1. ToolService (`src/kernel/services/tool-executor.ts`)

Класс `ToolService` (:242). Дефолтные инструменты (массив `tools` :243-352, ровно 10): t-search, t-code, t-web, t-mcp, t-read-file, t-list-files, t-summarize, t-translate, t-web-search, t-api-call.

- Методы: init/destroy, load/persist (KV super_agents_tools), getTools/getToolsByCategory/getEnabledTools, addTool/updateTool/removeTool/toggleTool, checkRateLimit, execute, fetchWithTimeout, pushHistory, recordExternalExecution, getExecutionHistory/getExecutionStats, exportTools/importTools.
- allowlist: внутри execute нет; снаружи `ToolExposureService` (tools/tool-exposure-service.ts): list() (:137) фильтрует по профилю resolveToolSet(profileId,{allow,deny}); без селекции фолбэк = профиль minimal (read-only). invoke() (:168) диспатчит по namespace (catalog→toolService, runner→toolRunner).
- crypto: `crypto.randomUUID` только в sandbox.worker.ts:35 и browser-harness-service.ts:103.
- Санитизация вывода: `wrapExternalData()` (:90) — оборачивает внешние данные в `<external_data>DO NOT TRUST…</external_data>` (анти-prompt-injection); применяется для t-search/t-web/t-mcp/plugins.
- rate-limit: `checkRateLimit()` (:501) — фиксированное окно 60000мс, per-tool. **Важно: у 10 дефолтов rateLimit не задан → rate-limiting у дефолтов фактически выключен.**
- История: executionHistory (кап maxHistory ?? 200), вход/выход режутся capTrailValue (2000/8000), персист в KV.
- AST-валидация (meriyah): `validateToolCode()` (:95) + `walkAst()` (:55). Блокирует FORBIDDEN_IDS (:27): eval, Function, fetch, XMLHttpRequest, importScripts, WebSocket, Worker, SharedArrayBuffer, Atomics, Proxy, Reflect, globalThis, self, top, parent, window, arguments; WithStatement; CallExpression с callee eval; NewExpression с Function; ImportExpression; computed-MemberExpression с TemplateLiteral/BinaryExpression. Применяется только к хранимым тулам (addTool/updateTool/importTools) при наличии code — не к исполнению. t-code идёт через deps.sandboxService.execute (:649).
- fetch: `fetchWithTimeout()` (:753) — только https:, блок private IP до и **после редиректа** (:819); allowedDomains deny-all для t-web ([]); fallback /proxy/fetch.
- Тесты: tool-exposure-service.test.ts, tool-executor.test.ts (P-CRIT-4, trail, капы). **Нет тестов**: validateToolCode/walkAst (eval/new Function/fetch/with/computed), checkRateLimit, SSRF-редирект, wrapExternalData, importTools, интеграция с пайплайном, read-only-профиль против invoke.

## 2. Tool-Pipeline (`services/tool-pipeline/`)

`ToolPipeline` (:94): pre→exec→post, middleware. Типы: ToolPreDecision (allow/deny/cancel/ask/replace), ToolPostDecision (accept/replace/enrich/block), ToolPipelineMiddleware, ToolApprovalResolver, ToolPipelinePort (:76), ToolPipelineResult.

- runPre (:122): первый middleware с решением ≠ allow — short-circuit; ask без резолвера → deny (fail closed).
- runPost (:182): первый block — short-circuit; последние replace/enrich выигрывают.
- permission-middleware.ts: createPermissionMiddleware (id 'permission') — permissionService.evaluate; createPermissionApprovalResolver / createChannelApprovalResolver (через IToolApprovalService).
- tool-approval-service.ts: ToolApprovalService — request/resolve/listPending/setAttended/isAttended/destroy; DEFAULT_TIMEOUT_MS=120_000; без attended → мгновенный deny.
- tool-availability.ts: ToolAvailabilityRegistry — register/unregister/list/isAvailable/filterAvailable (TTL 30s, grace 60s), порт check_fn.
- Потребители: ToolService.execute (:560), ToolRunnerService.callTool (:244, gatingApplies). Тесты: tool-pipeline/availability/approval.

## 3. Tool-Loop (`services/tool-loop/tool-loop.ts`)

`runToolLoop(messages, call, opts)` (:77): цикл «LLM→tool calls→execute→LLM». call→{content, toolCalls}; нет вызовов → выход. maxRounds 1..8 (default 4); signal.aborted между раундами/перед тулом. W8-009: аргументы через JSON.parse, невалидный → ERROR: (тул не вызывается) (:112-129). W4-022: вывод режется до 6000 + redactPii() (:142). Использует ToolRunnerService.runWithTools (:330). Computer-CUA — отдельный. Тест: tool-loop.test.ts.

## 4. Sandbox (два параллельных слоя)

**a) SandboxService** (`services/sandbox-service.ts:14`, worker-путь, используется t-code): execute(code,data,timeoutMs=5000,allowedTools) (:113) — только если VITE_SANDBOX_ENABLED=true; поднимает Worker sandbox.worker.ts. fetchUrl — https-only + isPrivateIP, fallback /proxy/fetch. Гейт тулов: cap_request → allowedTools (вкл '*') + кап 10 вызовов (:151-186).
**b) CodeSandboxService** (`sandbox/code-sandbox-service.ts:23`, G5): SandboxPolicy (maxChars 20000, allowedLanguages [python,javascript,typescript,sql], banned DEFAULT_BANNED: eval, Function, process, require, import(, **proto**, constructor, globalThis, fetch, XMLHttpRequest, defaultTimeoutMs 15000). **Бан-слова — substring (code.includes), не AST (:63)**; таймаут 1s..120s; артефакты KV codesandbox/artifact/<id>. **Реальный E2B = BLOCKED-RUNTIME** (stub artifact).

- sandbox.worker.ts: onmessage → runSandboxCode(code,data,os); os.executeTool через cap_request/cap_response (таймаут 5s); таймаут default 5000.
- sandbox-interpreter.ts: meriyah-AST-интерпретатор runSandboxCode (+validateSandboxCode): блок FORBIDDEN_IDENTIFIERS (fetch, eval, Function, setTimeout, self, globalThis…) и FORBIDDEN_MEMBER_PROPERTIES (constructor, **proto**, prototype, getPrototypeOf…); глобальный объект — Proxy c whitelist SAFE_BUILTINS (:205); set:()=>false; шаг-лимит 2M, глубина 2000; подмножество JS.
- Тесты: sandbox-interpreter.test.ts, code-sandbox-service.test.ts. **Нет тестов на SandboxService.execute (worker-интеграция, кап 10, allowedTools).**
- Риски: substring-бан обходится тривиально (unicode-escape/пробелы); доверие к «бан-словам» ложно-безопасно vs интерпретатора; sandbox-функции получают живые console/Math/crypto из globalThis; evalNew вызывает new(ctor)(…a) на builtin-конструкторах (:1006); две sandbox-политики рассинхронизированы (разные баны).

## 7. Пробелы (для SPEC_05 / роадмапа 05)

**Безопасность/evasion:**

1. Substring-бан в CodeSandboxService (:63) — наивный, обходится; две несогласованные политики.
2. runner http.fetch (tool-runner-service.ts:440) — httpGuard проверяет private IP до redirect, но **не пере-проверяет финальный URL после redirect** (SSRF-обход через redirect).
3. ToolService.validateToolCode — не покрывает obj.fetch()/obj['fetch'](), (0,eval), Reflect-обходы; и это не путь исполнения t-code.
4. MCP HTTP-fallback readResource — несанитизированный вывод (:416-424).
5. Browser/computer sidecar — cleartext http://localhost:3100, токен опционален, allowedDomains не принуждаются — поверхность MITM/exfiltration.
6. Rate-limit дефолтов выключен (нет rateLimit у 10 тулов).
7. Скриншот/секреты — BrowserUseService и BrowserHarnessService дублируют дефолтный regex.

**Нет тестов:** validateToolCode/walkAst негативы; rate-limit; SSRF redirect-перепроверка; wrapExternalData; importTools; ToolService+пайплайн; SandboxService.execute; MCP validateUri/HTTP-fallback; prompt-injection через <external_data>.

**Дублирование:** 4 fetch-обёртки (ToolService.fetchWithTimeout, SandboxService.fetchUrl, runner http.fetch, MCPService.safeFetch); SSRF-логика isPrivateIP повторена; два sandbox-слоя; три HITL-канала (ToolApprovalService, agemsApprovalService, permission-middleware); sensitive-regex дублирован.

**BLOCKED-RUNTIME заглушки:** code-sandbox (E2B), browser-harness (реальный браузер), mcp-harness (неподключённые), deploy-bundle, hybrid-rag reranker, llm-judge, execution-viz canvas.

**Главное для SPEC_05:** унификация ban-политики sandbox (substring → AST), пере-проверка redirect в runner-http, санитизация всех MCP-fallback, TLS/token для sidecar, включение rate-limit на дефолтах, eval-тесты.
