## Топ-5 с деталями реализации

### 1. Плагинная система

**Проблема**: весь функционал живёт в монорепо; чтобы добавить сервис/панель/инструмент,
надо править ядро. Для «ОС» расширяемость — это суть.

**Что сделать**:

- `IPluginManifest` (id, version, services[], panels[], tools[], mcpServers[], settingsSchema).
- `PluginLoader`: читает манифест, валидирует (Zod), регистрирует сервисы через
  `Container.register`, добавляет маршруты в `NAV_SECTIONS`/`PANEL_COMPONENTS`, инструменты в `ToolService`.
- Песочница плагинов: переиспользовать `code-sandbox-service` для изоляции стороннего кода.
- UI: «Plugin Marketplace» (локальный), вкладка управление плагинами.

**Куда класть**: `src/kernel/services/plugins/`, `src/components/PluginMarketplacePanel`, `docs/plugin-sdk.md`.

**Аналог**: VS Code extensions; n8n nodes; Obsidian plugins — у всех есть манифест + sandbox.

### 2. Embedding-пайплайн / RAG-стандарт

**Проблема**: три разных подхода к поиску (BM25/Orama, провайдерские эмбеддинги, офлайн-хэш) без общего интерфейса; дублирование памяти.

**Что сделать**:

- `IEmbeddingProvider` (embed, dimensions, normalize) + `embedding-service.ts` с выбором бэкенда и fallback.
- `IRetrievalProvider` (query → ranked chunks) поверх BM25/hybrid/vector; единый RAG-стандарт.
- Перевести MemoryService/RagService/WikiBrain/дебатный RAG на эти интерфейсы.

### 3. Eval-платформа

**Проблема**: есть ELO, eval/, frontier, но нет единого хаба для прогона датасетов и сравнения.

**Что сделать**:

- `EvalDataset` (вопросы + эталоны + метрики), `EvalRunner` (прогон через роутер/дебаты/агентов), `EvalReport`.
- Подключить к `MetricsService` и убе UI (`EvalDatasetPanel`, `EvalReportPanel`, `ABTestPanel` уже есть — связать).
- Сравнение «модель/стратегия/техника» на одном датасете.

### 4. Единый агентный runtime-фасад

**Проблема**: Council/Crew/Forum/Graph/Director — разные циклы управления.

**Что сделать**:

- `IAgentRuntime` с общим циклом «протокол входа → LLM → инструменты → выход» (переиспользовать `tool-loop.ts`).
- Реализовать фасады: `CrewRuntime`, `CouncilRuntime`, `ForumRuntime`, `GraphRuntime` (декораторы над единым ядром).
- Это даст «плагинность» и избавит от дублирования (см. `ROADMAP_11`).

### 5. Супервизор флота

**Проблема**: FleetMonitor — read-only проекция; нет операций.

**Что сделать**:

- `FleetSupervisor`: restart agent / retry task / change profile / drain — все через approval-поток с аудитом.
- UI: `FleetSupervisorPanel` (список агентов, статусы, кнопки операций, история).

## Что НЕ стоит писать (или отложить)

- **Свой LLM-провайдер** — это не задача этого проекта; хватает адаптеров.
- **Полноценный рендеринг документов / офисный редактор** — вне фокуса.
- **Блокчейн/токеномика** — не обосновано.
- **Мобильные нативные приложения** — раньше разобраться с web-мобильным UX.
