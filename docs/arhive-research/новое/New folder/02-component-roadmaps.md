# SuperAgents OS — Дорожные карты по компонентам

> Для каждого модуля: текущее состояние, критические/быстрые улучшения, среднесрочные,
> стратегические, и показатели готовности. Коды (`W4-025` и т.п.) — из аудитов.

---

## 1. Чат и диалог

**Состояние:** зрелый (8.5/10), есть streaming, race-режим, UCB1-роутинг, экспорт, поиск по сообщениям.

**Сделать:**

- P1: RAG в чат — память/знания по умолчанию попадают в контекст с индикацией источников (Dial6-020, W8-005).
- P1: Обрезка контекста прозрачная: показывать «контекст обрезан (N токенов)» + policy сжатия.
- P2: Idempotency-Key на отправке (W6-008) — не дублировать сообщения при ретраях.
- P2: Отменяемость долгих задач с реальным abort (W6-012).
- Стратегически: «чат как центр» — из любого сообщения можно развернуть исследование/дебаты/кристалл.

## 2. Провайдеры и ключи

**Состояние:** ядро, отличное покрытие (8.5/10).

**Сделать:**

- P0: passphrase-vault + шифрование ключей at-rest (W7-CRY-001, W5-002).
- P1: per-key circuit-breaker (W6-017): один плохой ключ не должен банить весь провайдер.
- P1: OpenRouter rotation с revoke (W4-021).
- P2: Показ «какой ключ/модель использованы» в каждом запросе (cost-attribution).

## 3. Дебаты

**Состояние:** зрелый (8.5/10): 33 стратегии, 75 техник, live/replay/tournament.

**Сделать:**

- P1: Debate→memory provenance (W2-014): какие воспоминания повлияли на вывод.
- P1: Debate→crystal bi-directional (Synthesis→Crystal уже есть; добавить ссылку обратно).
- P2: Рефакторинг 62 TechniquePanels → generic `TechniquePanel` (сэкономит ~14.5k LOC).
- Стратегически: «дебаты как сервис принятия решений» — единый API для любого «что выбрать?».

## 4. Память и знания

**Состояние:** 8/10; проблема — раздробленность (8 типов) и отсутствие единого обзора.

**Сделать:**

- P1: MemoryCenterPanel как hub (обзор всех типов + владелец + дата + фильтр по типу) (W3-016, W7-ANA-007).
- P1: Retrieval без O(N)-сканов: индекс + TTL + пересборка при смене эмбеддинг-модели (W8-012/014/015).
- P1: Provenance/качество знаний: обязательные источник+дата+доверие, авто-детекция противоречий (Card 14).
- P2: Сквозной перенос контекста «исследование → дебаты → Wiki».
- Стратегически: единая «модель знания» с графом и версионированием.

## 5. Кристаллы и синтез

**Состояние:** уникальные подсистемы, но слабо связаны с остальным.

**Сделать:**

- P1: Builder killer-service nodes: Crystal/Synthesis/Lens/TimeMachine/MemoryOrchestrator как node-типы (ROI 11.6; Card 24).
- P1: «Синтез → кристалл → wiki → пересмотр» как один контур.
- P2: Уведомления: кристалл опровергнут / дебаты завершены (W9-1/9.2).

## 6. Builder (конструктор пайплайнов)

**Состояние:** 3/10 — вызывает только agent/router/guardrail/tool.

**Сделать:**

- P1: Добавить 8 killer-node-типов (см. выше). Это **главный архитектурный unlock**.
- P2: Версионирование пайплайнов + экспорт/импорт (round-trip).
- Стратегически: «cognitive DSL» — визуальный пайплайн = код, который можно переиспользовать.

## 7. Агенты и автономия

**Состояние:** зрелый UI, но рискованная автономия (W4-042/043/044).

**Сделать:**

- P0: Зарегистрировать всех агентов в permission-пайплайне (default `guarded`).
- P1: Уровни автономности 1–10 per-агента + HITL.
- P1: Undo/rollback для опасных действий.
- P2: Единый «state of all agents» overview.

## 8. Наблюдаемость и диагностика

**Состояние:** богатая инфраструктура (18+ панелей), но раздроблена.

**Сделать:**

- P1: unified «explain state» dashboard.
- P1: Cross-nav из диагностики к источнику.
- P1: Алертинг в внешние каналы (Slack/Discord/Telegram) в bootstrap (W4-011).
- P2: UI для MemoryWatchdog/DLQ/CircuitBreaker/Bootstrap/Event registry.

## 9. Бюджет и стоимость

**Состояние:** логирование есть, enforcement нет.

**Сделать:**

- P1: pre-call budget-gate (canUseProvider/estimatedCost) (W4-030/031).
- P1: Атрибуция стоимости на request/tool/agent; recordSpend с enforcement (W5-021/024).
- P2: Промпт/ответ-кэш + маршрутизация дешёвых задач на дешёвые модели.

## 10. Интеграции (MCP/Tools/Skills)

**Состояние:** хорошее; главная проблема — инструменты без схем и санитизации.

**Сделать:**

- P1: Только-схемы для инструментов; валидация аргументов до вызова (W4-027, W8-009/011).
- P1: Санитизация tool-вывода перед возвратом в контекст (W4-022).
- P2: Per-agent/per-tool rate limits.

## 11. Wiki и документация

**Состояние:** автогенерируемая, 25 карт аудитов.

**Сделать:**

- P1: Индивидуальные статьи для техник-панелей (19 из 62) и для 64 панелей без wiki.
- P2: «Публикация» карт в wiki (уже есть через `docs/audits/waves`).
- Стратегически: wiki как живой «мозг ОС», который агенты читают и пополняют.

## 12. Настройки и конфигурация

**Состояние:** 8 вкладок; проблемы с feature-флагами (W6-018) и скрытыми дефолтами.

**Сделать:**

- P1: Поиск по настройкам; правдивые флаги (убрать `as unknown`).
- P1: Единый конфиг-реестр с типизацией и влиянием.
- P2: Гейт `mockServices` по умолчанию выключен; скрыть DemoGated-панели.

## Общекомпонентные рекомендации

- **Контракты:** реестр контрактов + авто-проверка совместимости при изменении.
- **Наблюдаемость:** каждый сервис — диагностируем (status/последняя ошибка).
- **Тесты:** добавить coverage-gate; включить в `test:stable` по одному пути на раздел.
- **Безопасность:** authz на всех мутациях; санитизация внешнего контента.
