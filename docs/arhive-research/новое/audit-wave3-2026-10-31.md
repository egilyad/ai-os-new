## 1. Executive summary (что нового по сравнению с волнами 1–2)

Волны 1 и 2 закрыли runtime-слой: bootstrap, build/repo, keys/secrets, architecture, domains,
data-streaming, security/hardening, memory leaks, auth/sandbox/CSP/XSS/SSRF, data integrity /
migrations (Zod-hooks, atomic writes, partial-write guards), race/lifecycle/abort, types/contracts
event-drift, performance/indexes/cache, UX correctness, build/deploy/config (Docker/nginx/env/CI),
observability/monitoring, logic errors, state consistency, contract violations.

Волна 3 — **платформенный слой**, 12 новых аудитов. Главные системные выводы:

1. **Multi-tenancy фактически отсутствует.** Только подсистема Project (P1, v35) корректно
   изолирует данные через `projectId`. Все остальные ~95 таблиц Dexie (`memories`, `sessions`,
   `apiKeys`, `crystals`, `councilSessions`, `crews`, `forumTopics`, `agentLoops`,
   `sharedContexts`, `goals` …) и `sync-server.mjs` (единый `shared-db.bin` blob + единый
   `SYNC_SECRET` + `broadcastLive` без фильтра по companyId) — single-tenant по дизайну.
   4 Critical + 3 High находки — самая горячая зона.

2. **Accessibility layer полностью отсутствует как инженерная дисциплина.** Нет `eslint-plugin-jsx-a11y`,
   212 inline `outline: 'none'` в 130 файлах убивают focus-visible, основные модальные UI
   (CommandPalette, OnboardingWizard, PromptLibraryPanel, ProviderDetailModal) не имеют
   `role="dialog"`/`aria-modal`/focus-trap/Escape; live-regions отсутствуют для чат-стриминга
   и критичных алертов (KEY_COMPROMISED). WCAG 2.4.7, 4.1.3, 2.4.1, 1.4.11 — множественные fail.

3. **i18n-debt накоплен и не ловится CI.** Паритет-тест `i18n-keys.test.ts` ловит только
   en↔ru, но не ловит "ключ вызывается в коде, но отсутствует в обоих словарях" — таких
   мёртвых вызовов ≥9 (`runs.loading`, `scheduler.create_title`, `lenses.context_placeholder`
   и др.), 104 `?? 'fallback'`-выражения в 22 файлах мертвы (т.к. `t()` всегда возвращает
   строку). Нет pluralization, нет locale-aware форматирования дат/чисел/валюты (160 callsites
   без locale-аргумента).

4. **Feature flags имеют критическую двойную бухгалтерию.** `featureFlags` в `CONFIG`
   хранит состояние, `FeatureFlagsConfigSection`-тип описывает форму, `FEATURE_FLAGS` enum
   объявлен, но **никем не используется**. UI-тумблеры в Settings (GeneralTab) читают
   `featureFlags['memory.enabled']` (dotted-key) из объекта `CONFIG.featureFlags`
   (nested) — всегда `undefined`, показывают всегда ON. `ConfigOverlays` НЕ включает
   `featureFlags` → все toggle'ы теряются при reload. `memory-engine.clear()` при
   выключении memory не вызывается никогда (dotted-path в `changes` не соответствует
   формату emit) → после отключения memory данные остаются в IndexedDB.

5. **Backup / DR-слой отсутствует полностью.** Нет автоматического бэкапа ни для
   клиентской IndexedDB, ни для `server/data/`. `exportToJson()` — мёртвый код, покрывает
   16/136 таблиц. `exportKeys()` экспортирует vault-envelope, но `salt` (от которого
   зависит мастер-ключ) не экспортируется → ключи на новом устройстве НЕ расшифровываются.
   `cli db-backup` копирует файлы без sha256/retention/encryption. RPO/RTO/retention
   policy/runbook отсутствуют. Silent retention-prune в `company-store.mjs` (caps 5k–20k)
   обрезает историю без архивации.

6. **PWA полностью отсутствует.** Нет service worker, нет `manifest.webmanifest`, нет
   `theme-color`, нет `apple-touch-icon`, нет PNG-иконок 192/512/maskable. На flaky-сети
   или offline приложение бесполезно. Нет `navigator.onLine`-обработки в UI. iOS
   IndexedDB может быть вычищен через 7 дней без `navigator.storage.persist()`.

7. **Browser compat baseline `es2023` без progressive enhancement.** Нет `browserslist`,
   нет `@vite/plugin-legacy`, нет `<noscript>`. Safari 15.x и Chrome <110 получают
   белый экран из-за top-level await в `main.tsx:112`. `backdrop-filter` без
   `-webkit-` префикса в ~50 компонентах → теряется blur на Safari <18. Нет
   `prefers-color-scheme` CSS-fallback. framer-motion игнорирует `prefers-reduced-motion`
   (нет `<MotionConfig reducedMotion="user">`).

8. **Search & Retrieval: гибридный поиск — частичная имитация.** Design doc
   `004-hybrid-search-strategy.md` обещает Transformers.js + MiniLM, но в рантайме —
   хэш-эмбеддинг (причём две разные хэш-функции). Production reranker `BLOCKED-RUNTIME`,
   fallback на stub. N+1 embedding API-вызовов на холодный RAG-запрос. Cross-session
   memory leak в `chat-send-message.ts:127` (если session-scoped < 2 hits → fallback на
   глобальный `search()` без фильтра → в LLM-контекст попадает чужая память).

9. **sync-server — single-tenant по всем граням.** `/api/db` — атомарная перезапись
   одного `shared-db.bin` (last-write-wins, без versioning/CRDT). `broadcastLive` шлёт
   всем WS/SSE клиентам. `/api/approvals/<id>/decide` и `/api/runs/<id>/execute`
   не проверяют, что вызывающий имеет доступ к company-владельцу → любой клиент
   с `SYNC_SECRET` может нанимать/увольнять агентов в чужой компании. `ReconnectionService`
   полностью реализован, но не подключён ни к одному LLM-адаптеру.

10. **Миграции Dexie: тесты устарели и не запускаются.** `dexie-schema-versioning.test.ts`
    трижды asserts `db.verno === 35`, но реальная схема — v43. Файл НЕ включён в
    `test:stable` script в `package.json`, поэтому CI его не запускает. `versionDefs`
    массив (используется `validateMigrations()`) также останавливается на v35 → 8
    последних миграций (v36–v43, AGEMS Phase 0–9) вообще не валидируются. 4 upgrade-функции
    (v6/v9/v11/v12) не покрыты тестами с pre-populated legacy data, v11 silently
    дропает HISTORY_LIST_ID при parse-error. Нет pre-migration backup, нет rollback path.

Итого: **135 confirmed findings** (15 Critical, 40 High, 47 Medium, 33 Low),
сгруппированных в ~75 consolidated карточек ниже. Build/typecheck/lint проходят
чисто (0 ошибок typecheck, 0 ошибок lint, 5375 warnings).

## 2. Scope и метод

**Запущено:**

- 12 параллельных аудитов (W3-01…W3-12) через Explore-субагентов. Каждый получил:
  явный scope, список ключевых файлов, информацию о предыдущих волнах (для `cross_wave_hint`),
  формат выходного отчёта.
- 3 follow-up задачи: A (verify top Critical/High), B (typecheck+lint+build), C (bundle analysis).

**Метод аудита:**

- Статический анализ (Grep/Glob/Read), без запуска рантайма (только `npm ci`, `typecheck`,
  `lint`, `build` в чистой копии). `test` намеренно НЕ запускался (бьёт по внешним сервисам
  и IndexedDB). Анализ тест-сценариев — по коду.
- Для каждого finding-а требовались file:line + понятный триггер.
- Подтверждённые находки отделены от предположений через поле `confidence` (Confirmed / Likely / Needs runtime).

**Что НЕ запускалось (требует рантайма):**

- Полный test suite (vitest run) — может бить по внешним API и IndexedDB.
- e2e (playwright) — требует реального браузера и сервисов.
- Реальная проверка IndexedDB corruption, multi-tab sync, network blip recovery.
- Реальное тестирование accessibility на screen reader (NVDA/VoiceOver).
- Проверка CSRF/CORS в продакшн-окружении.

**Cross-wave policy:**

- Каждая находка имеет `cross_wave_hint: wave1`/`wave2`/`none`. Явно отмечено, какие
  темы уже закрыты волнами 1/2 (например, `SYNC_SECRET` fail-fast, `.dockerignore` для
  `.env`, `key-vault.ts` AES-GCM и т.д.).
- Аудит конфигов/секретов (W3-05) намеренно НЕ дублирует wave1/2 — помечены только
  новые углы (env schema, дрейф `.env.example`, sandbox fail-loud, TLS-by-default).

### W3-003 — sync-server: единый binary blob без tenant-префикса

### W3-004 — broadcastLive шлёт всем клиентам без workspace-фильтра

- **Categories:** W3-03 multi-tenancy
- **Severity:** Critical
- **Confidence:** Confirmed
- **File:Line:** `server/sync-server.mjs:127-152` (`broadcastLive` + `sseClients`),
  `server/sync-server.mjs:1157-1172` (`wss.on('connection')`)
- **Evidence:**
  ```js

  function broadcastLive(type, payload) {
    const msg = JSON.stringify({ type, timestamp: Date.now(), ...payload });

    } // ВСЕ WS
    for (const res of sseClients) {
  ```

- **Problem:** WS/SSE не имеют понятия комнаты/workspace. `broadcastLive()` отправляет каждое

  хранить `Map<ws, Set<workspaceId>>`, фильтровать `broadcastLive` по workspaceId. Добавить
  `ws.on('message')` для `subscribe`/`unsubscribe` комнат.
- **Cross-wave hint:** wave1 (security/auth).

- **File:Line:** `src/components/ProjectsPanel/WebsitePreview.tsx:153-159`
- **Evidence:**

### W3-054 — `/api/db` whole-file last-write-wins без merge/CRDT

- **File:Line:** `server/sync-server.mjs:270-313` (PUT /api/db handler); `server/write-queue.mjs:14-22` (`enqueueDbWrite`)
- **Evidence:**
  ```js
  req.on('end', () => {
    enqueueDbWrite(async () => {
      const tmpFile = DB_FILE + '.tmp.' + Date.now();
      fs.writeFileSync(tmpFile, Buffer.concat(chunks));
      fs.renameSync(tmpFile, DB_FILE); // ← АТОМНАЯ ПЕРЕЗАПИСЬ ВСЕГО ФАЙЛА
      broadcastLive('db_changed', {});
      writeJson(res, 200, { status: 'ok' });
    });
  });
  ```
  Content-Type: `application/octet-stream` — клиент шлёт бинарник всей базы. `write-queue.mjs:14-22` — простая serial queue, без merge/CRDT/diff. В теле PUT НЕТ поля `version`, `etag`, `vectorClock`, `lastModifiedAt`, `clientId` — голый blob.
- **Problem:** Серверный `/api/db` — whole-file last-write-wins. Если клиент A офлайн-редактировал 10 минут, клиент B в это время писал 5 записей, а потом A переподключился и пушил свой blob — сервер атомарно перетёр изменения B. Никакого слияния по записям, векторных часов, tombstones или CRDT.
- **Risk:** Multi-tenant/shared-server сценарий: две команды редактируют debate-сессию параллельно → теряются аргументы одной из сторон. На мобильном устройстве после offline-режима переподключение рискует затереть серверные апдейты от других клиентов. Это не offline-mode, это offline-футура-что-то-сделает-но-нельзя-доверять.
- **Trigger:**
  1. Клиент A: PUT /api/db (v1).
  2. Клиент B: PUT /api/db (v2).
  3. Клиент A (после offline): PUT /api/db (старый v1 + новые локальные правки) → v2 от B полностью потерян.
- **Fix:**
  - Либо перейти на per-record sync API (`PATCH /api/db/record/:table/:id` с `If-Match: <etag>`, 409 Conflict при рассинхроне).
  - Либо внедрить CRDT (Yjs / Automerge / Y-Sweet) для автоматического merge без конфликтов.
  - Минимум: добавить поле `version`/`updatedAt` в PUT-пайлоад, на сервере сравнивать с текущим — если `incoming.version < server.version`, ответить 409 и попросить клиента rebase на основе diff.
- **Cross-wave hint:** wave2 (state consistency — primary).

## 9. Системные темы

### 9.1. i18n / a11y (UX-инженерная дисциплина отсутствует)

- **i18n**: CI ловит только en↔ru parity, но не "ключ в коде, нет в translations" (≥9 мёртвых ключей). Нет pluralization, locale-aware форматирования, RTL-readiness. Архитектурный lock-in на 2 локали (`nameRu` в типе + 122 ternary). MemoryCenterPanel — полностью hardcoded Russian.
- **a11y**: Нет `eslint-plugin-jsx-a11y`, 212 inline `outline: 'none'`. 5 основных модальных UI без `role="dialog"`/focus-trap/Escape. Live regions отсутствуют для chat streaming и critical alerts. Complex widgets (vis-network, Monaco, TipTap, Mermaid) без accessible alternative.
- **Root cause**: i18n/a11y не встроены в CI-гейт; нет engineer-owned discipline; паритет-тест даёт ложное чувство "i18n OK".

### 9.2. Multi-tenancy (single-tenant по дизайну)

- Все ~95 таблиц Dexie (кроме project-подсистемы) — глобальные, без workspaceId.
- Sync-server: один `SYNC_SECRET`, один `shared-db.bin` blob, `broadcastLive` без фильтра, cross-tenant control plane (`/api/approvals/<id>/decide`).
- RAG-memory течёт между проектами через `chat-send-message.ts:127` fallback.
- **Root cause**: приложение эволюционировало из single-user PWA; концепция workspace не была заложена в data model. Все новые features (AGEMS, debate, council, forum, persona) наследуют single-tenant assumption.

### 9.3. Flags / config / secrets (двойная бухгалтерия + missing schema)

- `featureFlags` — три источника истины (`CONFIG.featureFlags`, `FeatureFlagsConfigSection`, `FEATURE_FLAGS` enum), не связанных. UI читает dotted-key из nested object → всегда `undefined`. `ConfigOverlays` не включает `featureFlags` → toggle'ы не персистят. `memory-engine.clear()` не вызывается из-за mismatch в event payload.
- 4 dead/misleading flags (`FEATURE_FLAGS` enum, `memory.semantic`, `debate.runtimeEngine`, `ui.experimentalVisuals`).
- ABTest/ExperimentEngine — без guard-rail, без auto-stop, без sticky-assignment.
- Config: нет zod-схемы env; `.env.example` дрейфует (15 мёртвых `VITE_KEY_*`, 20+ missing); `VITE_PROXY_URL` не fail-fast; `SYNC_ORIGINS=*` принимается; `SYNC_SECRET` без длины-check; Dockerfile default HTTP.
- Vault envelope: salt не экспортируется → ключи не восстанавливаемы на новом устройстве.
- **Root cause**: feature flags добавлялись ad-hoc без единого ownership; env vars копились без контракта.

### 9.4. Миграции / бэкапы (нет rollback, нет recovery)

- Dexie schema v5→v43 (8 версий добавлены в AGEMS Phase 0–9), но `versionDefs` массив и `dexie-schema-versioning.test.ts` остановились на v35 — test НЕ включён в `test:stable` script → CI не запускает.
- 4 upgrade functions (v6/v9/v11/v12) полностью не протестированы с pre-populated legacy data.
- Нет pre-migration snapshot, нет rollback path. Botched schema release bricks user's local DB.
- 6+ репозиториев делают cascade delete non-transactionally (debate/graph/council/crew/synthesis/agems/wiki-brain).
- Backup: нет автоматического бэкапа ни для клиентской IndexedDB, ни для server/data. `exportToJson` — мёртвый код, 16/136 таблиц. `exportKeys` envelope без salt. `cli db-backup` без SHA-256/retention/encryption. IndexedDB corruption detected but no recovery path.
- Server-side retention prune (5k-20k caps) silent без archive coordination.
- **Root cause**: backup/DR не закладывались в архитектуру; ADR-003 "Dexie as primary storage" не имеет parallel DR story.

### 9.5. Realtime и стриминг (ReconnectionService мёртв, WS без backpressure)

- SSE `/api/live-events` non-resumable (нет `id:`, `Last-Event-ID`, `retry:`) и без keepalive.
- WS server без `maxPayload` (default 100 MiB) и без `perMessageDeflate`; `broadcastLive` не проверяет `bufferedAmount` → memory-exhaustion DoS.
- `ReconnectionService` полностью реализован (exp backoff + jitter), зарегистрирован в DI, но 0 callers вне тестов. LLM-стримы после обрыва не переподключаются.
- HMR dispose chat-store не абортит in-flight LLM-стримы → dev-mode теряет остаток ответа + сжигает токены.
- Graceful shutdown не закрывает WS/SSE.
- SSE parser silently дропает truncated final chunk без STREAM_ERROR.
- **Root cause**: collaboration/realtime фичи добавлены без протокольной discipline; ReconnectionService остался "half-implemented" (service есть, wiring нет).

### 9.6. Поиск (гибридный поиск — частичная имитация)

- Design doc обещает Transformers.js + MiniLM; рантайм — хэш-эмбеддинг (причём две разные хэш-функции, `detectSpace` conflates).
- ProviderRerankerService `BLOCKED-RUNTIME` — fallback to StubReranker. Любые замеры "гибридного" качества сделаны на стабе.
- Orama schema не индексирует namespace-поля → scoped-поиск может вернуть 0 даже при наличии релевантных записей.
- N+1 embedding API-вызовов на холодный RAG-запрос (нет батчинга, нет пре-компьютинга).
- `vectorCache` без eviction и без invalidation на source update.
- Worker MAX_ENTRIES=10000 vs cache maxEntries=1000 — search возвращает "удалённые" записи.
- Cross-session memory leak в `chat-send-message.ts:127` (если scoped <2 → fallback на глобальный `search()` без фильтра).
- Нет pagination/cursor. `MessageIndexService.search` score = `needle.length / content.length` (nonsense ranking).
- **Root cause**: RAG-feature добавлена как "demo-grade" без production hardening; design doc расходится с реализацией.

### 9.7. Медиа (sandbox hole + size validation gap)

- `WebsitePreview.tsx` iframe `allow-scripts allow-same-origin` + `srcDoc` из user project files — textbook XSS → API key exfiltration. Дубликат правильного `ProjectsPanel.tsx:332` (`sandbox="allow-scripts"` only) был пропущен при hardening.
- 8 JSON-import pipelines + GoogleMultimodalTab image upload — без size cap (`FileReader.readAsText`/`readAsDataURL` для arbitrary-size file).
- aquarium-screenshots-service: full-res PNG dataURLs в localStorage (5MB quota) → silent data loss + collateral блокировка других localStorage writes.
- Avatar URL принимает любой scheme — tracking pixel vector через export/import.
- **Root cause**: file/media validation не стандартизирована; один компонент (`ChatAdminPanel.tsx:68-78`) имеет size check, остальные игнорируют.

### 9.8. PWA / offline (полностью отсутствует)

- Нет service worker, нет `manifest.webmanifest`, нет `theme-color`, нет `apple-touch-icon`, нет PNG-иконок 192/512/maskable. Lighthouse PWA = 0 баллов.
- Нет `navigator.onLine`/online-offline event listeners в UI — обрывы сети молча теряются.
- Нет `navigator.storage.persist()` → iOS Safari может вычистить IndexedDB через 7 дней неактивности.
- `viewport-fit=cover` отсутствует → `env(safe-area-inset-bottom)` в BottomNav.tsx:38 возвращает 0 (dead code).
- `/api/db` whole-file last-write-wins — при reconnect после offline клиент может атомарно перетереть чужие записи.
- **Root cause**: PWA-слой не закладывался; приложение эволюционировало как "browser-only SPA".

6. **Locale chunks (ru 208KB / en 159KB) — reasonable.** Async-loaded через `loadLocale()`.
   Один из немногих правильно lazy-loaded ресурсов.

7. **Source maps в prod (1053 `.map` файла, 93MB):** `vite.config.ts:65` `sourcemap: 'hidden'`
   — карты генерируются, но не ссылаются из JS (нет `//# sourceMappingURL=`). Согласно
   комментарию в `vite.config.ts:61-63` и `scripts/upload-sourcemaps.mjs:1-15`, maps
   предназначены для upload в Sentry/Datadog через отдельный post-build step.
   - **Risk:** если `scripts/upload-sourcemaps.mjs` НЕ запущен в CI, sourcemaps остаются
     рядом с билдом. Если `dist/` публикуется на CDN/static-хостинг без фильтра `*.map` —
     любой может скачать maps и реконструировать исходный код. Verification: в
     `nginx.conf`/`nginx-ssl.conf` нет `location ~ \.map$ { deny all; }`.
   - **Fix:** добавить `location ~* \.map$ { deny all; return 404; }` в nginx config, либо
     удалять `*.map` файлы из `dist/` после upload в Sentry.

8. **Tree-shaking quality:** Build report показывает 5 chunks >700KB warning — это ожидаемо
   для heavy-app. Vite+esbuild делают reasonable tree-shaking, но monaco (через
   `import * as monaco`) не tree-shake'ится. Consider `monaco-editor/esm/vs/editor/editor.api`
   для импорта только нужной части.

9. **Lazy-loading на роутах:** `route-imports.ts` имеет `React.lazy(...)` для ~50 панелей —
   хорошая практика. CodeEditor.tsx статически импортирует monaco, но он попал в
   `vendor-monaco` chunk (отдельный от main bundle) — acceptable.

10. **CSS:** `src/styles/` имеет ~5 CSS файлов (base, layout, panels, variables, common).
    Inline стили в компонентах преобладают (~10k+ `style={{...}}` occurrences) — нет
    CSS-modules / styled-components / Tailwind. Это сознательное решение (см. ESLint rule
    `rule-no-raw-style-color.mjs`), но означает, что dead CSS не tree-shake'ится.
