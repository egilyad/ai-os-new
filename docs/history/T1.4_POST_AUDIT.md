# T1.4 POST Audit — Привязка агента в редактировании

> Дата: 2026-09-09. Scope: AgentConfigTab + Agent mapping. Рантайм уже умеет (T1.3).

## Что было
Таб писал `model: "provider:model"` комбинированной строкой — рантайм T1.3 читает `config.provider`/`config.model` раздельно, т.е. старая запись в pin никогда бы не попала. Key pin отсутствовал вообще.

## Что сделано
1. **`AgentsPanelContext.ts`**: `Agent.keyId?: string` (опционально, non-breaking).
2. **`AgentsPanelContainer.ts`**: маппинг `keyId: node.config.keyId ?? undefined`.
3. **`AgentConfigTab.tsx`**:
   - Provider: `Auto (rotation)` + active providers из `useKeyStore`. `Auto` → `{provider:'auto', keyId:undefined, model:'auto'}` (снятие пина).
   - Key: только при пине, `Auto (pool)` + ключи провайдера; пишет `keyId` отдельно.
   - Model: опции из SSOT (мёртвые llama-3.x убраны).
   - Legacy-миграция на чтении: `model: "p:m"` → provider=`p`, model=`m`; следующий save пишет раздельно.
   - `keys`-prop больше не используется (данные из стора), из деструктуризации убран.

## Проверки (static)
| Check | Evidence | Result |
|-------|----------|--------|
| Запись ложится в node.config | `updateAgent` → `agentService.updateAgent` merge → рантайм читает те же поля | ✅ |
| Снятие пина чистое | `{provider:'auto', keyId:undefined, model:'auto'}` — рантайм игнорит | ✅ |
| Старые агенты | без provider/keyId → форма показывает Auto, поведение как раньше | ✅ |
| Legacy `"p:m"` | парсится на чтении, перезаписывается раздельно | ✅ |
| Контракты/таблицы/DI | не тронуты | ✅ |
