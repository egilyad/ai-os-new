## 0. Executive summary

OpenCode Desktop 1.19.4 — это не «устаревшее приложение», а **стабильное ядро (kernel)** с документированным контрактом: HTTP-сервер (OpenAPI 3.1), MCP-хост, файловые конвенции (`SKILL.md`, `commands/`, `plugins/`, `agents/`). Вся мощность выносится в периферию (userspace): MCP-серверы, кастомные tools, Skills, плагины, Sidekick.

На слабом железе (AMD E-350, 11.6 ГБ ОЗУ, Windows 10) единственно верная стратегия:

1. **Последовательность вместо параллельности** — один агент, одно действие.
2. **Вынос вычислений за пределы Electron** — всё тяжёлое живёт в внешних процессах.
3. **Ленивая загрузка** — MCP включаются по требованию, Skills подгружаются по контексту.
4. **Ядро не трогаем** — все расширения через штатные точки (MCP, plugins, Skills, custom tools).

Оптимальная конфигурация: **«маленькое ядро OpenCode + умный локальный Sidekick + включаемые по требованию MCP»**.

## 1. Методологическая рамка

### 1.1. Трёхслойная модель [Qwen]

```
L3 — Пользовательские пространства: Skills, Workflows, Sidekick (UI), мульти-агенты
L2 — Системные сервисы: MCP-серверы, Context Daemon, Memory Daemon, External Tools
L1 — Ядро (OpenCode 1.19.4): prompt engine, tool executor, MCP host, session — НЕ ТРОГАЕМ
```

Принцип: ядро остаётся нетронутым, вся мощь — в периферии.

### 1.2. Терминология

- **L1-Ядро**: неизменяемые примитивы OpenCode (промпт, tools, MCP-хост, сессии).
- **L2-Сервисы**: процесс-процесс демоны, MCP-серверы, индексаторы.
- **L3-Пространства**: Skills, workflow-оркестраторы, UI-надстройки, мультиагентные рои.

## 3. Архитектурные принципы экосистемы

1. **Всё тяжёлое — вне процесса OpenCode.** Плагины только перехватывают и сжимают; память, индексация, БД — в MCP-слоях.
2. **MCP-серверы выгружаемы.** Запуск по требованию (`enabled: false` по умолчанию), завершение после простоя.
3. **Sidekick — только оркестратор.** Хранит данные и не выполняет вычисления; вызывает API и управляет процессами.
4. **Один язык — один инструмент.** Rust для ресурсоёмких MCP, TypeScript для лёгких плагинов, PowerShell для системной автоматизации.
5. **Не более 3 активных MCP-серверов одновременно** — остальные по требованию [Qwen].

## 4. Skills — библиотека переиспользуемых знаний

### 4.1. Почему Skills

Skills — самый дешёвый механизм расширения: Markdown-инструкции, загружаемые только когда модель вызывает native `skill` tool. Заменяют «забывание» конвенций и не забивают контекст статикой [DeepSeek].

### 4.2. Рекомендуемая библиотека [Perplexity/ZAI]

```
.opencode/skills/
  superagents-os/          # архитектура SuperAgents OS
  windows-powershell/      # правила PowerShell 5.1
  node-service-patterns/   # паттерны Node-сервисов
  low-resource-optimization/ # оптимизация под слабое железо
  code-review/             # ревью кода
  security-audit/          # аудит безопасности
  release-checklist/       # чеклист релизов
  debugging-workflow/      # отладка
  docs-writing/            # документация
```

### 4.3. Организация

- **Доменные**: архитектура SuperAgents OS, Windows-ограничения, Node-сервисы, MCP.
- **Операционные**: отладка, релизы, тестирование, ревью, миграции.
- **Инструментальные**: как правильно вызывать конкретный custom tool или MCP.
- **Координационные**: декомпозиция задач, когда звать исследователя/ревьюера/тестировщика.

**Правило:** не делать «мега-Skill» — модель должна подгружать только нужную процедуру.

### 4.4. Дополнительные Skills [Qwen]

| Skill                  | Назначение                                             |
| ---------------------- | ------------------------------------------------------ |
| `self-reflection`      | Анализ своего вывода перед финализацией                |
| `architecture-guard`   | Проверка соответствия кода архитектурным принципам     |
| `memory-anchor`        | Явная пометка важных решений для долговременной памяти |
| `context-bridge`       | Связь текущей задачи с другими репозиториями           |
| `multi-model-delegate` | Пометка задач для передачи в SuperAgents OS            |

Skills могут ссылаться друг на друга (`см. также @skill:architecture-guard`) — примитивный механизм композиции.

### 4.5. Пример SKILL.md [Perplexity/ZAI]

```md
---
name: windows-powershell
description: Использовать при работе с PowerShell 5.1, путями Windows, процессами и сервисами SuperAgents OS.
---

# Правила PowerShell 5.1

- Не использовать синтаксис PowerShell 7, если он несовместим с 5.1.
- Для длинных команд использовать здесь-строки и отдельные `.ps1`-скрипты.
- Перед destructive-операциями выводить `WhatIf` или dry-run.
- Проверять свободное место и память перед запуском тяжёлых процессов.
- Не предполагать наличие Bun; использовать Node.js и npm.
```

## 5. Tools — расширение инструментального арсенала

### 5.1. Два пути добавления инструментов

1. **Кастомные инструменты через Plugins (in-process)** — лёгкие, не требуют отдельного сервера. Примеры: парсинг логов, запросы к SQLite, вызов PowerShell с валидацией аргументов [DeepSeek].
2. **Кастомные инструменты через MCP (out-of-process)** — предпочтительно для ресурсоёмких; изолированы от процесса OpenCode [DeepSeek].

### 5.2. Приоритетные custom tools [Perplexity/ZAI]

| Tool               | Назначение                                  | Реализация                                | Нагрузка       |
| ------------------ | ------------------------------------------- | ----------------------------------------- | -------------- |
| `sa_project_scan`  | Снимок структуры, зависимостей, точек входа | Node.js + `fast-glob`/`ignore`            | Низкая         |
| `sa_search_code`   | Поиск по индексу вместо повторного чтения   | SQLite FTS5 или ripgrep                   | Низкая/средняя |
| `sa_run_tests`     | Запуск только затронутых тестов             | Node.js wrapper над npm                   | Средняя        |
| `sa_git_snapshot`  | Безопасный commit/patch перед изменениями   | `simple-git` или PowerShell/git           | Низкая         |
| `sa_task_queue`    | Фоновая задача в Sidekick                   | HTTP API локального Node-сервиса          | Низкая         |
| `sa_memory_save`   | Сохранение решения, ADR, ошибки             | SQLite/JSONL                              | Низкая         |
| `sa_memory_search` | Поиск по прошлым решениям                   | SQLite FTS5                               | Низкая         |
| `sa_docs_query`    | Поиск по локальной документации             | Индекс Markdown + SQLite                  | Низкая         |
| `sa_windows_diag`  | CPU/RAM/диск/процессы/порты                 | PowerShell или Node `os`, `child_process` | Низкая         |
| `sa_mcp_toggle`    | Включение/выключение тяжёлых MCP            | Sidekick + реестр конфигов                | Низкая         |

### 5.3. Пример конфигурации

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "sa_project_scan": {
      "description": "Собирает безопасный обзор проекта: структура, стек, скрипты, точки входа.",
      "execute": { "command": ["node", "./sidekick/tools/project-scan.mjs"] },
    },
    "sa_memory_search": {
      "description": "Ищет прошлые архитектурные решения, ошибки и исправления.",
      "execute": { "command": ["node", "./sidekick/tools/memory-search.mjs"] },
    },
  },
}
```

> Точная схема custom tool зависит от V1-схемы; перед реализацией проверить через `$schema` [Perplexity/ZAI].

## 6. MCP — минимальный набор

### 6.1. Правила

- Каждый MCP-сервер добавляет инструменты в контекст LLM и увеличивает расход токенов — быть избирательным [Ф].
- Предпочтительны Rust-серверы (SQLite + sqlite-vec, потребляют на порядок меньше памяти) или Python без PyTorch (uv/pipx, `fastembed`) [DeepSeek].
- Один лёгкий демон с несколькими инструментами лучше десяти отдельных серверов [DeepSeek].

### 6.2. Стартовый профиль [Perplexity/ZAI]

| MCP                         | Роль                              | Тип    | Режим                    |
| --------------------------- | --------------------------------- | ------ | ------------------------ |
| Context7                    | Актуальная документация библиотек | Remote | Включать по запросу      |
| Grep by Vercel              | Поиск примеров в открытом коде    | Remote | Включать по запросу      |
| FileSystem / project tools  | Контролируемая работа с файлами   | Local  | Только при необходимости |
| SQLite MCP                  | Чтение проектной базы знаний      | Local  | Для задач анализа        |
| Playwright MCP              | UI-тестирование                   | Local  | Только для e2e           |
| Собственный SuperAgents MCP | Единый доступ к Sidekick          | Local  | Основной                 |

### 6.3. Категории по задачам [DeepSeek]

- **Память/контекст:** `opencode-semantic-memory` (FTS5 + вектор), `muninn` (ChromaDB + Ollama embeddings), `opencode-memtomem` (поддерживает 1.17.18+ / v1).
- **Индексация кода:** `codebase-index` (SQLite + Tree-sitter), `vibe-me` (SQLite + Qdrant, локальные embeddings), `opencode-codebase-index`.
- **Базы данных:** `@bytebase/dbhub` (Postgres/MySQL/SQLite, read-only), `postgres-mcp`.
- **GitHub:** официальный `@modelcontextprotocol/server-github` — с оговоркой о высоком расходе токенов.

### 6.4. Конфигурация

Remote:

```jsonc
{
  "mcp": {
    "context7": {
      "type": "remote",
      "url": "https://mcp.context7.com/mcp",
      "enabled": true,
    },
    "gh_grep": {
      "type": "remote",
      "url": "https://mcp.grep.app",
      "enabled": false,
    },
  },
}
```

Local (Node.js, без Bun):

```jsonc
{
  "mcp": {
    "superagents": {
      "type": "local",
      "command": ["node", "D:/SuperAgents/sidekick/mcp/server.mjs"],
      "cwd": "D:/SuperAgents/sidekick",
      "enabled": true,
      "timeout": 60000,
    },
  },
}
```

V1 поддерживает `command`, `cwd`, environment, `enabled`, `timeout` для local; URL, headers, OAuth, таймауты для remote [Ф].

## 7. Агенты и мультиагентность

### 7.1. Базовое

В V1 уже есть primary-агенты `Build` и `Plan`, subagents `General` и `Explore`; дополняются своими в `.opencode/agents/`. Subagents вызываются через `@имя` или автоматически; навигация parent/child — hotkeys [Ф].

### 7.2. Рекомендуемая команда агентов [Perplexity/ZAI]

| Агент          | Режим            | Права                                   | Задача                            |
| -------------- | ---------------- | --------------------------------------- | --------------------------------- |
| `architect`    | subagent         | `edit: deny`, `bash: ask`               | Проектирование, ADR               |
| `researcher`   | subagent         | `edit: deny`, `webfetch: ask`, MCP docs | Поиск решений                     |
| `implementer`  | primary/subagent | `edit: ask`, `bash: ask`                | Реализация ограниченных изменений |
| `reviewer`     | subagent         | `edit: deny`, `bash: deny`              | Ревью качества/безопасности       |
| `tester`       | subagent         | `edit: deny`, `bash: ask`               | Тест-планы, запуск тестов         |
| `windows-ops`  | subagent         | `bash: ask`, `edit: deny`               | Диагностика Windows               |
| `docs-writer`  | subagent         | `edit: ask`, `bash: deny`               | Документация                      |
| `orchestrator` | primary          | `task` только для разрешённых subagents | Декомпозиция и координация        |

### 7.3. Пример агента-reviewer

```md
---
description: Проводит безопасный code review без изменения файлов.
mode: subagent
temperature: 0.1
permission:
  edit: deny
  bash:
    '*': ask
    'git diff*': allow
    'git log*': allow
  webfetch: deny
---

Ты — reviewer SuperAgents OS.

Проверяй:

- корректность логики и граничные случаи;
- безопасность ввода, путей, команд и секретов;
- потребление памяти и CPU на Windows 10 / AMD E-350;
- совместимость с Node.js и PowerShell 5.1;
- полноту тестов и документации.

Не изменяй файлы. Возвращай конкретные findings с file:line и приоритетом.
```

### 7.4. Реалистичная мультиагентность на 1.19.4 [DeepSeek]

Полноценные оркестраторы (opencode-orchestrator, @moderndegree/opencode-agent-teams) заявляют поддержку V2 — совместимость с 1.19.4 требует проверки [Г]. Надёжный путь:

1. Роль-ориентированные агенты через `.opencode/agents/`.
2. Sidekick как координатор: последовательно запускает headless-сессии (`opencode run --attach ...`), передавая результат через файл/переменную.
3. Общая память: все агенты используют один MCP-сервер семантической памяти.

**Это последовательная специализация, а не параллельность** — AMD E-350 не потянет несколько одновременных LLM-сессий.

Альтернативный механизм [Qwen] — файловый протокол: `tasks/pending|in-progress|review|done/`; каждый агент читает свою папку. Плюс «дебаты агентов» через markdown-файл, куда каждый дописывает реплики.

## 8. Plugins

### 8.1. Доступные хуки [DeepSeek]

- `session.created`, `session.idle`, `session.deleted`
- `tool.execute.before` / `tool.execute.after`
- `chat.message`, `chat.params`

### 8.2. Практическое применение на слабом железе

| Хук                   | Назначение                                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `tool.execute.before` | «Предохранитель»: блокировать ресурсоёмкие операции (напр. `npm install` с сотнями зависимостей) или перенаправлять на лёгкий аналог |
| `session.idle`        | Триггер фоновой индексации (не конкурирует за CPU)                                                                                   |
| `tool.execute.after`  | Сжатие вывода bash-инструментов (оставлять только строки с ошибками)                                                                 |

Ограничение: плагины исполняются внутри процесса OpenCode, требуют аккуратности с памятью.

## 9. Sidekick — диспетчер экосистемы

### 9.1. Роль

Sidekick — **не «вторая IDE» и не «второй агент»**, а локальная операционная система вокруг OpenCode: оркестратор, который работает вне процесса и подключается к HTTP-серверу [Perplexity/ZAI].

### 9.2. Модули

| Модуль          | Функция                              | Технология                   | Приоритет        |
| --------------- | ------------------------------------ | ---------------------------- | ---------------- |
| `registry`      | Каталог Skills/tools/MCP с профилями | JSON + SQLite                | Высокий          |
| `indexer`       | Инкрементальный поиск по репозиторию | chokidar + SQLite FTS5       | Высокий          |
| `memory`        | Долговременная память решений        | SQLite + Markdown ADR        | Высокий          |
| `runner`        | Безопасный запуск команд и задач     | Node `child_process`         | Высокий          |
| `mcp-bridge`    | Собственный MCP-сервер для Sidekick  | `@modelcontextprotocol/sdk`  | Высокий          |
| `watcher`       | События файлов, git, тестов          | chokidar + git               | Средний          |
| `dashboard`     | Панель задач, статусов, логов        | Local web UI                 | Средний          |
| `desktop-panel` | Панель внутри OpenCode Desktop       | Plugin `gui-experimental`    | Экспериментально |
| `sandbox`       | Изоляция опасных команд              | PowerShell jobs / контейнеры | Средний          |

### 9.3. Технологический стек

- **Платформа:** Tauri (Rust + WebView2, ~30–50 МБ в простое) или PWA на локальном Node.js-сервере; Electron избыточен. WebView2 уже есть в Windows 10 [DeepSeek].
- **Бэкенд:** Node.js v24.20.0 (установлен, совместим).
- **Связь с OpenCode:** только HTTP к `http://127.0.0.1:4096`; никаких манипуляций с памятью/процессами OpenCode.
- **Бюджет памяти:** 50–100 МБ.

### 9.4. Собственный MCP-сервер Sidekick (SuperAgents MCP)

Ключевая идея [Perplexity/ZAI]: OpenCode видит один набор инструментов, за которым стоит вся инфраструктура Sidekick:

- `sidekick.status` — состояние проекта, памяти, диска, задач
- `sidekick.search` — гибридный поиск по коду, документации, памяти
- `sidekick.remember` / `sidekick.recall` — сохранение/поиск решений
- `sidekick.plan_task` — структурированная задача
- `sidekick.run_background` — тесты, линтер, индексация
- `sidekick.get_artifact` — отчёт, лог, diff
- `sidekick.profile_set` — переключение профиля MCP/tools

Это лучше, чем много отдельных MCP: меньше инструментов в контексте, тяжёлая логика остаётся в Sidekick.

## 10. Контекст, поиск и память

### 10.1. Проблема

На 11.6 ГБ ОЗУ и двухъядерном CPU контекстное окно LLM — дефицитный ресурс. Не строить тяжёлый embedding-индекс «на всё» [Perplexity/ZAI].

### 10.2. Двухуровневая стратегия [DeepSeek]

**Горячий контекст (в окне LLM):**

- Skills вместо документации (загрузка по требованию)
- Сжатие вывода инструментов через плагин `tool.execute.after`
- Подзадачи (`subtask: true`) для изоляции тяжёлых операций

**Холодный контекст (вне окна):**

- Семантическая память через MCP (opencode-semantic-memory / muninn)
- Индексация кодовой базы (codebase-index / vibe-me)

### 10.3. Трёхуровневая память [Qwen]

| Уровень       | Что                                      | Где                                         |
| ------------- | ---------------------------------------- | ------------------------------------------- |
| L1 — горячая  | Текущие файлы, открытый контекст         | Сам OpenCode                                |
| L2 — тёплая   | Ключевые решения, архитектурные принципы | SQLite-база + embeddings (MCP-memory)       |
| L3 — холодная | Весь репозиторий, документация           | ripgrep + SQLite FTS5 (MCP-codebase-search) |

### 10.4. Структурная память

Хранить не сырые чаты, а атомарные записи [Perplexity/ZAI]:

```json
{
  "type": "decision",
  "title": "Выбор SQLite вместо Postgres для Sidekick",
  "context": "Ограниченная RAM и локальный характер данных",
  "decision": "SQLite + WAL + FTS5",
  "consequences": "Нет сетевого сервиса БД; ограничение на одновременную запись",
  "files": ["sidekick/db/schema.sql"],
  "tags": ["architecture", "database", "low-resource"]
}
```

### 10.5. Этапы построения поиска

1. **Точный контекст:** ripgrep + SQLite FTS5 для Markdown/ADR/логов; `.opencode/rules/` или `AGENTS.md`; кэш сканирования.
2. **Структурная память:** атомарные записи (решения, инциденты, ADR).
3. **Семантический слой (экспериментально):** только после стабильного точного поиска; embeddings малой размерности; индексация только ADR/README/архитектуры/ключевых модулей; ночная пакетная обработка; отдельный процесс с лимитом памяти. На E-350 полезнее гибрид «FTS + структурные связи».

### 10.6. AGENTS.md как живой документ

Сделать `AGENTS.md` главным артефактом памяти: архитектурные решения, текущие задачи, контекст проекта, ссылки на внешние документы; агент читает его в начале каждой сессии [Qwen].

## 11. Автоматизация и workflow

### 11.1. Workflow «Исследование → план → реализация → ревью» [Perplexity/ZAI]

```
1. @researcher: собрать ограничения, варианты, риски
2. @architect: подготовить ADR и план изменений
3. Пользователь: утвердить план
4. @implementer: выполнить одну ограниченную задачу
5. @tester: сформировать и запустить проверки
6. @reviewer: проверить diff, безопасность и ресурсы
7. sidekick.remember: сохранить решение и результат
```

### 11.2. Полезные цепочки

- **Bug triage**: воспроизведение → логи → гипотезы → минимальный patch → regression test
- **Feature pipeline**: requirements → ADR → декомпозиция → реализация → тесты → docs → release notes
- **Performance audit**: измерение → профиль → узкие места → безопасная оптимизация → повторное измерение
- **Dependency audit**: список пакетов → лицензии/уязвимости → план обновления → тесты
- **Documentation sync**: изменение кода → обновление README/ADR/API docs → проверка примеров
- **Incident memory**: ошибка → причина → fix → guardrail → тест → запись в память

### 11.3. Механизмы автоматизации

- **ОС-планировщик:** Windows Task Scheduler запускает `opencode run` для ночных задач (рефакторинг, генерация тестов, обновление документации) [DeepSeek].
- **Файловые watcher'ы:** chokidar → триггер Skills при изменении критических файлов [Qwen].
- **Цепочки задач:** Sidekick последовательно вызывает `opencode run --attach http://localhost:4096 "prompt"`, проверяя результат каждого шага [DeepSeek].
- **Ограничение:** на E-350 не запускать параллельные headless-сессии; использовать `Start-Process -Priority BelowNormal` [DeepSeek].
- **Workflow-движок [Qwen]:** минимальный `workflow.json` (шаги: skill/tool + вход), запускаемый через MCP-tool `run_workflow`.

## 16. Нестандартные идеи (объединённый пул)

От DeepSeek:

1. **Skills как «генетический код» проекта** — версионируемые и наследуемые: базовый skill + проектные переопределения.
2. **MCP «цифровой двойник проекта»** — граф зависимостей и решений; инструмент `why_is_this_here(symbol)`.
3. **«Бюджетный» режим через прокси** — кэш идентичных запросов, роутинг простых запросов на маленькую модель, учёт токенов/стоимости.
4. **«Режим раскопок» /archaeology** — изолированная подсессия восстановления истории решений.
5. **Физический дисплей состояния** — ESP32/старый планшет с веб-интерфейсом к SSE-потоку.

От Perplexity/ZAI: 6. **Project Time Machine** — snapshot намерения, diff, тестов перед каждым существенным изменением. 7. **Context Budget Manager** — оценка размера контекста перед задачей, предложение отключить часть MCP. 8. **Tool Cost Ledger** — журнал вызовов tools (длительность, память, полезность). 9. **Failure Pattern Library** — «симптом → причина → fix → prevention». 10. **Agent Contracts** — machine-readable контракт для subagent (вход, artifact, ограничения, критерии приёмки). 11. **Resource Guardrail** — блокировка запуска при нехватке RAM/диска. 12. **Skill Compiler** — превращение длинных чатов в компактные Skills. 13. **MCP Circuit Breaker** — автоотключение зависшего MCP, fallback. 14. **Decision Graph** — причинно-следственная карта: ADR ↔ файлы ↔ тесты ↔ инциденты. 15. **Offline Research Cache** — кэш документации в SQLite.

От Qwen: 16. **«Символический слой»** — MCP-сервер, переводящий технические концепции в символические образы и обратно. 17. **«Теневой агент»** — второй пассивный экземпляр OpenCode, читающий действия основного и выдающий отчёты. 18. **«Контекстный оракул»** — внешняя модель оценивает «стоит ли это делать?» перед серьёзным действием. 19. **«Эволюционный репозиторий»** — решения как «гены», скрещивание лучших подходов. 20. **«Ритуальный слой»** — «активация контекста» в начале и «закрытие цикла» в конце работы.

## 19. Главный вывод

OpenCode Desktop 1.19.4 можно развивать практически до уровня полноценной AI-разработческой экосистемы, если воспринимать его не как конечную IDE, а как **агентное ядро с расширяемой периферией** [Perplexity/ZAI]. Все ограничения версии компенсируются через MCP, Skills, plugins и внешние сервисы [Qwen].

Реалистичный потолок — не «новая версия OpenCode», а собственная система: Sidekick хранит знание и управляет ресурсами, MCP даёт доступ к внешним системам, custom tools выполняют доменную логику, Skills передают процедуры, agents распределяют работу.

Ключевое ограничение — AMD E-350 — диктует стратегию: **последовательность, вынос вычислений, ленивая загрузка**. Это даёт современную функциональность (память, поиск, автоматизацию, мультиагентность, UI) без апгрейда OpenCode и без перегрузки машины.
