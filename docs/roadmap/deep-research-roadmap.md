# Roadmap: глубокие исследования и мультиагентные паттерны

> Составлено на основе исследования `docs/research/multiagent-os-patterns.md` и вики-статьи `research-multiagent-patterns`.
> Логика: сначала — то, что критично и дёшево (безопасность, доверие); затем — то, что даёт глубину и обучаемость; затем — крупные архитектурные паттерны.

## П0 — срочно, безопасность и доверие (без этого нельзя усиливать глубину)

| #    | Задача                                                               | Паттерн       | Объём   | Риск    | Критерий готовности                                                |
| ---- | -------------------------------------------------------------------- | ------------- | ------- | ------- | ------------------------------------------------------------------ |
| П0-1 | Подключить KeyVault (шифрование ключей AES-GCM + миграция plaintext) | Vault         | Средний | Средний | Ключи не лежат в открытом виде; миграция с обратной совместимостью |
| П0-2 | Песочница с отрезанной сетью для кода (connect-src 'none')           | Sandbox       | Средний | Средний | Выполнение кода изолировано, сеть закрыта                          |
| П0-3 | Claim-centric evidence: выводы строятся из crystal-claims с цитатами | Claim-centric | Средний | Низкий  | Каждое предложение вывода опирается на источник                    |
| П0-4 | Маскировка секретов в логах и экспорте (уже частично есть — довести) | Security      | Малый   | Низкий  | Секреты не попадают в логи/экспорт                                 |

## П1 — глубина и доверие

| #    | Задача                                                     | Паттерн           | Объём   | Риск    | Критерий                                          |
| ---- | ---------------------------------------------------------- | ----------------- | ------- | ------- | ------------------------------------------------- |
| П1-1 | Sub-agent spawn с изоляцией контекста и бюджета            | Sub-agent         | Средний | Средний | Дочерние агенты с собственным контекстом/бюджетом |
| П1-2 | Дебаты: запрет одного семейства моделей у участников/судей | Debate-constraint | Малый   | Низкий  | Модели в дебате обязательно из разных семейств    |
| П1-3 | Eval harness + regression gate (faithfulness, coverage)    | Eval              | Средний | Низкий  | CI-гейт по качеству и faithfulness                |
| П1-4 | «Почему такой ответ» для исследования (источники/claims)   | Provenance-UX     | Средний | Низкий  | В выводе исследования видны источники             |

## П2 — обучаемость и память

| #    | Задача                                              | Паттерн              | Объём   | Риск    | Критерий                                   |
| ---- | --------------------------------------------------- | -------------------- | ------- | ------- | ------------------------------------------ |
| П2-1 | Record a Skill / процедурная память                 | Skill                | Большой | Средний | Система записывает и переиспользует навыки |
| П2-2 | Консолидация памяти + забывание                     | Memory-consolidation | Большой | Средний | Похожие эпизоды сжимаются, вес затухает    |
| П2-3 | Двойное время фактов (valid_from/to vs recorded_at) | Time                 | Средний | Низкий  | Факты отличают «устарело» от «было ложным» |

## П3 — крупные архитектурные паттерны

| #    | Задача                                         | Паттерн       | Объём   | Риск    | Критерий                       |
| ---- | ---------------------------------------------- | ------------- | ------- | ------- | ------------------------------ |
| П3-1 | Blackboard / Global Workspace                  | Workspace     | Большой | Высокий | Общий «фокус внимания» агентов |
| П3-2 | Long-horizon state machine с checkpoint/resume | State-machine | Большой | Высокий | Задачи переживают перезагрузку |
| П3-3 | Само-рефлексия (Reflexion) после задач         | Reflexion     | Средний | Средний | Короткий разбор после задач    |

## Порядок и измерение

- Выполнять строго P0 → P1 → P2 → P3: без безопасности нельзя «углублять», без контроля качества нельзя «обучать».
- Метрики успеха:
  - Безопасность: 0 секретов в открытом виде; 0 случаев утечки через fallback/логи.
  - Глубина: рост числа уникальных источников на исследование; рост faithfulness.
  - Обучаемость: рост числа навыков и их успешности.
- Каждый пункт заканчивается коммитом + CI-прогоном.
