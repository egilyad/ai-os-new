# Верификация и уверенность (Verification & Confidence)

> **Формат:** скелет — наполняется из аудитов/фактов. Парные: карты 1–10 + wave-аудиты.
> **Покрывает исходные идеи списков:** Уровень доверия к каждому компоненту: автотесты/вручную/по ощущениям/не проверялось; покрытие; качество результатов агентов.

---

## Назначение

Уровень доверия к каждому компоненту: автотесты/вручную/по ощущениям/не проверялось; покрытие; качество результатов агентов.

## Методология

Анализ тестов/CI + карты: Verification&Confidence, Audit Coverage, Output Quality, Agent Quality.

## Что уже есть (факты из аудитов)

- Тесты: 514 (486 unit + 17 e2e + 8 server + 3 scripts); 104/180 каталогов панелей имеют тест.
- W2-008/035: ключевые сервисы (key-management и др.) без юнит-тестов.
- W3-010/011: a11y не в lint-гейте; 5 UI-нарушений.
- W4-002: CI гоняет только `test:stable` (44 пути из 596 тест-файлов); полный прогон не в гейте.
- W6-034: перцентили исправлены (линейная интерполяция) + юнит-тесты.
- W7-ANA-013 / W6-003: фабрикация метрик в UI исправлена.
- Coverage threshold не задан в CI (test:coverage без gate).

## Пробелы / риски

- Покрытие тестами не является гейтом для большинства панелей/сервисов.
- Нет уровня доверия «проверено вручную vs тестами».
- Значимая часть тестов вне `test:stable` не гоняется в CI.
- Качество результата агентов не верифицируется автоматически.

## Рекомендации

1. Ввести coverage-threshold в CI (lines/branches).
2. Расширить `test:stable` стабильными путями (по разделам).
3. Матрица доверия «автотесты/вручную/не проверялось» на панели/сервисы.
4. Добавить eval/верификацию качества выводов агентов.
5. Включить a11y-правила в lint.
