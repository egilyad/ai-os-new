## Назначение

Частота изменений (git), горячие зоны, возраст кода; что ломается при изменении; стоимость добавления фичи; владение/bus factor.

## Методология

git log --stat + blame + анализ зависимостей + карты: Evolution, Churn/Hotspot, Change Impact/Cost/Safety, Ownership.

## Что уже есть (факты из аудитов)

- W4-001/002: deploy-гейт не включал тесты/coverage/audit (исправлено: `deploy.needs` расширен); `test:stable` — подмножество.
- W4-005/006: sourcemaps условно, без zero-downtime deploy.
- W6-025/027: unpinned npx в deploy; `engines.node` >=22 без `.nvmrc`.
- W3-013: build target es2023 (progressive enhancement).
- Техдолг: 18 файлов >1000 строк (hotspots), 169 >500; 62 идентичные TechniquePanels.
- Возраст: `@google/generative-ai@^0.24.1` pre-1.0; `lucide-react@^1.14.0` нестандарт.
- Легенда: 26 zone-audits, 199 зафиксированных исправлений — активная эволюция.

## Пробелы / риски

- Высокий churn в горячих зонах (ядро — главный кандидат на рефакторинг).
- Нет карты «что меняется чаще всего» (git) для приоритизации.
- Нет владения/bus factor по модулям.
- Смена версий провайдеров ломает API без раннего предупреждения.

## Рекомендации

1. Ввести churn/hotspot-анализ (git log --stat) в CI/отчёт.
2. Ограничение размера файлов (<1000 строк) с ADR.
3. GitHub CODEOWNERS + pre-push typecheck.
4. Пиннинг версий + dependabot + тест совместимости провайдеров.
5. Плановое сокращение техдолга (по неделям).
