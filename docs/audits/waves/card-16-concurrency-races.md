## Что уже есть (факты из аудитов)

- W6-013: `AbortSignal.any()` в race-executor — баг сборщика мусора Chrome (исправлено: ручной контроллер).
- W6-011: `isStaleSessionWrite`/writeGuarded обходится через `SessionRepository.save` → LWW-перезапись сессии (cross-tab).
- W6-014: `ArgumentGraphService` — DI-singleton, `build()` зовёт `clear()` → конкурентные дебаты затирают граф.
- W6-019: cross-session чат — глобальный `activeRequestIds`, сообщения теряются при параллельных сессиях.
- W6-007/009: нет fencing-токена у локов; `POST /api/runs/:id/execute` допускает дубль-запуск.
- W7-ANA-007: multi-tab потеря данных (per-tab in-memory + LWW).
- W8-017/022: ExecutionQueue + in-memory очереди — без блокировок, теряют состояние при краше.
- W6-008: нет Idempotency-Key на LLM-постах → ретраи дублируют сайд-эффекты (W6-040).
- W2-016: гонка голосования (исправлено: запрет двойного голоса).

## Пробелы / риски

- Общее мутабельное состояние без блокировок/идемпотентности.
- Очереди/задачи без атомарных переходов состояний.
- Cross-tab гонки (LWW, нет CRDT/HLC).
- Дедлоки/бесконечные ожидания на общих ресурсах.
- Double-execution при ретраях и параллельных вызовах.

## Рекомендации

1. Per-session изоляция (граф, сессия, очередь).
2. Атомарные CAS-переходы состояний + fencing-токены.
3. Idempotency-Key + дедупликация.
4. Правильная реализация writeGuarded/merge по entry-id для сессий.
5. CRDT/HLC для multi-tab/multi-device.
