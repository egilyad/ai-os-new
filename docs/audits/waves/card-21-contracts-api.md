## Пробелы / риски

- Нет формального реестра контрактов (API/события/схемы).
- Изменение контракта не уведомляет потребителей (silent break).
- Схемы без версий/миграций; откат невозможен.
- Нетипизированные касты (`as never`/`as any`) в нескольких слоях.

## Рекомендации

1. Реестр контрактов + автоматическая проверка совместимости.
2. Версионирование схем/API/событий с миграциями.
3. Валидация входов на границах (Zod/schema).
4. Авто-детекция поломки контракта при смене (тесты/CI).
5. Откат + бэкап перед миграцией.
