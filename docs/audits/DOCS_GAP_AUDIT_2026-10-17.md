## 3. Подтверждённые пробелы

### 3.1. Охват инвентаризации (P2)
Учитывается только `docs/**/*.md` (минус `docs/new`, минус self-reports).
Вне учёта 12 markdown-файлов: `AGENTS.md`, `CHANGELOG.md`, `CHANGELOG_RU.md`,
`evgenyroadmap.md`, `README.md`, `README_EN.md`,
`SELF_IMPROVEMENT_AUDIT_2026-09-22.md`, `.superagents/{ARCHITECTURE,CODING,README,RULES}.md`,
`src/kernel/DEPENDENCY_MAP.md`.

### 3.2. Цепочка аудит → проблема → исправление → тест (P1)
В графе есть только `documents/source/test/related`; нет узлов/рёбер аудитов,
коммитов и регрессионных тестов. Статья истории перечисляет 66 аудитов ссылками,
но восстановить по конкретной проблеме коммит и тест автоматически нельзя.
Это главный несделанный пункт исходной программы.

### 3.3. Поиск (P3)
`search-index.json` строится только из 144 статей вики. Не индексируются:
`docs/audits`, `docs/history`, сервисы, события, тесты, коммиты, известные проблемы.

### 3.4. Достоверность статусов (P1)
126 статей помечены `verified`, 17 `documented`, 1 `needs-check`.
`docs:health` проверяет структуру (ссылки, источники, схему, размер), но не истинность
утверждений. «Ссылка существует» ≠ «поведение описано верно».

### 3.5. Медиа (P3)
В `docs/` нет ни одного изображения или видео. Макеты/диаграммы истории не являются
скриншотами работающего интерфейса. Демонстраций, расшифровок и версий записи нет.

### 3.6. Сущности вне манифеста (P2)
Манифест описывает статьи и панели. Сервисы, стратегии дебатов, события,
провайдеры/адаптеры, ADR и аудиты не представлены как сущности с жизненным циклом.
Часть из них есть в авто-каталогах, но без единой модели и перекрёстных ссылок.

### 3.7. Точечные пробелы
- `dashboard` — единственная панель без статьи.
- 26 статей без источников; статьи с тестами — 33%.
- Реестр ADR не выделен; каталога внешних библиотек нет.

## 4. План (минимальные изменения, без переписывания)

### Этап A (P1) — достоверность и связность
1. Добавить в манифест сущность `audit` (id, путь, дата, статус, затронутые файлы)
   и ребро `audit --fixes--> code`, `audit --verified-by--> test`.
   Источник — ручной фронтматтер в отчётах + автодополнение по `git log`.
2. В статьях различать `verified` (структура) и `reviewed` (содержание):
   добавить поле `reviewedAt`/`reviewedBy` в корпус и вывести в `docs-health`.
3. Закрыть `dashboard`: статья-карточка (назначение, маршрут, компонент, тесты).

Проверки: `docs:health` (схема манифеста), `gate`, точечный `tsc`/ESLint;
по 3 примерам вручную пройти цепочку статья → исходник → тест → отчёт.

### Этап B (P2) — полный охват
1. Расширить инвентарь на root и `.superagents` (явный allowlist, без секретов).
2. Добавить в манифест `service`, `event`, `strategy`, `provider` из существующих
   каталогов (не дублировать данные — ссылаться на сгенерированные списки).
3. Собрать каталог внешних библиотек из `package.json` и реестр ADR.

Проверки: инвентарь идемпотентен, `gate`, число сущностей совпадает с каталогами.

### Этап C (P3) — доступность и поиск
1. Расширить `search-index.json`: статьи + аудиты + dev-документы + сервисы/тесты.
2. Добавить в сайт переходы «источник/тест/история» из статьи.
3. Записать 5 приоритетных демонстраций (чат, дебаты, провайдеры, память, диагностика)
   со скриншотами и версией; хранить в `docs/demos/`.

Проверки: `gen-wiki-site` собирает индекс > статей, битых ссылок 0.

2. Цепочка аудитов: ручной фронтматтер (точнее) или эвристика по `git log` (быстрее)?
