# 10 — Фреймворк экспериментов

## Концептуальный уровень

Фреймворк экспериментов позволяет систематически сравнивать конфигурации дебатов. Он построен на `AutoDebateService`, который оборачивает `DebateSyncManager.startDebate()` и записывает результаты. Фреймворк предназначен для A/B-тестирования стратегий, архетипов, ограничений и настроек температуры.

## Уровень системного отображения

### AutoDebateService

**Расположение**: `src/kernel/services/auto-debate/auto-debate-service.ts`

**Зависимости**: `keyService`, `DebateSyncManager` (через `startDebate`)

**Методы**:

| Метод                     | Назначение                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `runAutoDebate(options?)` | Одиночные дебаты с авто-выбранными участниками и случайной темой                          |
| `runQuickTest()`          | Быстрые одиночные дебаты с настройками по умолчанию                                       |
| `stressTest(count)`       | Запустить N дебатов последовательно, измерить пропускную способность и процент ошибок     |
| `batchTest(topic, runs)`  | Запустить N дебатов на одну тему, сравнить результаты                                     |
| `getResults()`            | Вернуть `AutoDebateResult[]` с временными замерами для каждых дебатов                     |
| `getWinRates()`           | Вычислить `ProviderWinRate[]` — как часто каждый провайдер появляется в тексте консенсуса |
| `clearResults()`          | Сбросить накопленные результаты                                                           |

**Темы**: 25 тем в 5 категориях (Технологии, Наука, Философия, Бизнес, Общество).

**Генерация участников**: Циклическое назначение ролей «за»/«против»/«нейтрально» по активным API-ключам.

## Уровень поведения

### Как выполнять сравнение

1. **Выберите независимую переменную**: стратегию, архетип, ограничение, температуру или набор агентов
2. **Оставьте всё остальное постоянным**: ту же тему, то же количество раундов, того же провайдера
3. **Запустите несколько дебатов**: используйте `batchTest(topic, N)` для статистической значимости
4. **Прочитайте метрики**: сравните `convergenceScore`, `qualityMetrics.depth.depthScore`, `qualityMetrics.originality.noveltyScore`, `qualityMetrics.usefulness.usefulnessScore`
5. **Прочитайте интерпретацию**: сравните `disagreementPeak.intensity`, `trajectoryChangers.length`, `insights[]`

### Что измерять

| Вопрос                                              | Метрика для проверки                                       |
| --------------------------------------------------- | ---------------------------------------------------------- |
| Какая стратегия даёт самое глубокое рассуждение?    | `graphMetrics.maxDepth`, `qualityMetrics.depth.depthScore` |
| Какой архетип создаёт самые оригинальные аргументы? | `qualityMetrics.originality.noveltyScore`                  |
| Снижают ли ограничения релевантность?               | `qualityMetrics.usefulness.relevanceScore`                 |
| Влияет ли температура на конвергенцию?              | `convergenceScore` на раунде 5 против раунда 10            |
| Какой провайдер самый надёжный?                     | `getWinRates()` из AutoDebateService                       |
| Влияет ли размер команды на качество?               | Сравнить 5 против 10 против 20 агентов на одной теме       |

### Известные ограничения

- Метрики качества эвристические — они измеряют поверхностные признаки (лексическое разнообразие, паттерны свидетельств), а не фактическое качество рассуждения
- Соблюдение ограничений ухудшается после 3–4 раундов (подходы на основе сопоставления шаблонов расходятся)
- Качественный шлюз сократического метода ещё не реализован — синтаксические вопросы («Не могли бы вы уточнить?») не фильтруются
- Оценка конвергенции использует сходство Жаккара, а не семантическое сходство (пересечение слов, а не пересечение смыслов)
- Существует резерв на HuggingFace `Xenova/all-MiniLM-L6-v2` для семантического сходства, но при ошибке он переключается на сходство Жаккара
