# Topic Graph — концепт-дизайн

> Отдельная когнитивная система SuperAgents OS: граф знаний темы.
> НЕ является частью Projects (граф развития проекта) и НЕ смешивается
> с Wiki-Brain (хотя переиспользует общие примитивы и идеи).

## 1. Задача

Постоянно расширяемая модель предметной области («темы»), строящаяся из
документов, ответов моделей и исследований:

- читает большой массив материалов;
- извлекает информацию;
- убирает смысловые повторы;
- сохраняет уникальные факты;
- находит противоречия;
- обнаруживает связи;
- показывает полноту изучения темы.

Центральный объект — **знания о теме**.

## 2. Принципы

1. **Тема — первоклассная сущность** (Topic). Граф живёт вокруг темы.
2. **Факт/Claim — главный узел.** Не страница, не документ: компактное
   утверждение со стабильным id и источником.
3. **Отдельное хранилище** — `aios-topic-graph` (Dexie), независимое от
   Wiki-Brain и ProjectGraph.
4. **Семантические рёбра** — таксономия отношений между фактами
   (supports / contradicts / refines / depends_on / example_of / ...).
5. **Смысловая дедупликация** — хэш + эмбеддинг-близость.
6. **Противоречия** — детекция и явная разметка.
7. **Полнота** — метрика покрытия: сколько ожидаемых подтем раскрыто.

## 3. Модель данных

```
Topic {
  id, title, description, status (active/paused/archived),
  createdAt, updatedAt
}

TopicFact {
  id, topicId, text (claim), source (doc/answer/research),
  confidence, status (extracted/validated/contradicted/superseded),
  createdAt, embeddings?: number[]
}

TopicRelation {
  id, topicId, fromFactId, toFactId,
  relation: 'supports'|'contradicts'|'refines'|'depends_on'|
            'example_of'|'same_as'|'cites',
  weight, createdAt
}

TopicSource {
  id, topicId, kind (document/model-answer/research), ref, title,
  sha256, importedAt
}
```

## 4. Жизненный цикл

```
Ingest → Normalize → Dedupe → Link → Verify (contradictions)
       → Query/Explore → Export (topic map / MD report)
```

1. **Ingest**: приём документов, ответов моделей, исследовательских отчётов.
2. **Normalize**: извлечение фактов (см. алгоритмы). (3. **Dedupe**: смысловое схлопывание повторов.
4. **Link**: построение рёбер (таксономия).
5. **Verify**: поиск противоречий; разметка.
6. **Query**: поиск по теме, подтемам, фактам, полноте.
7. **Export**: топик-карта/отчёт (MD), опционально в проект.

## 5. Алгоритмы

- **Извлечение фактов**: LLM-извлечение (или правило-фильтры на старте)
  из фрагментов в компактные утверждения; стабильный id.
- **Смысловая дедупликация**: `fnv1a`-хэш + косинусная близость
  эмбеддингов (>0.92 → кандидат same_as).
- **Противоречия**: переиспользование подхода `WikiContradictionDetector`
  (общие термины + контрарный маркер).
- **Связи**: эвристики (совпадение сущностей, характер утверждений) +
  опциональное LLM-связывание.
- **Полнота**: декомпозиция темы на подтемы (LLM/шаблон), для каждой —
  подсчёт покрытых фактов.

## 6. API / сервис

```
TopicGraphService
  createTopic(title, description)
  ingest(topicId, sources)           // -> новые факты/источники
  facts(topicId, filter?)
  relations(topicId)
  contradictions(topicId)
  completeness(topicId)              // полнота по подтемам
  search(topicId, query)
  exportReport(topicId)              // MD
```

Регистрация: `phase86-topic-graph.ts`.

## 7. Интерфейс

- Панель **Topic Graph**: список тем; внутри темы — граф фактов
  (визуализация типа KnowledgeGraphView), список противоречий, полнота.
- Действие ассистента: `topic.graph_query`, `topic.ingest`, `topic.export`.
- Опциональный экспорт в проект (как результат), но не обязательная связь.

## 8. Отличия от соседних систем

| Система | Центральный объект | Цель |
| --- | --- | --- |
| TopicGraph | знания о теме | накопление/структурирование знаний |
| Projects | проект и его развитие | применение знаний к проекту |
| Wiki-Brain | вики/корпус | документирование и справка по системе |

## 9. Этапы реализации

- **Этап A (MVP)**: схема Dexie, TopicGraphService (createTopic/ingest/
  facts/relations/completeness), фаза 86, тесты ядра.
- **Этап B**: LLM-извлечение, дедупликация, противоречия, экспорт MD.
- **Этап C**: панель + действие ассистента + (опционально) экспорт в проект.

## 10. Открытые вопросы

- Хранить ли эмбеддинги прямо в БД темы (переиспользовать providerEmbeddings).
- Кто «владеет» темой: пользователь, ассистент, автоматический исследователь.
- Порог смысловой дедупликации и точность противоречий (ложные срабатывания).
