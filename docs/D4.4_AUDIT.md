# D4.4 — Evaluator Wiring & Persistence Design Audit (без кода)

> Дата: 2026-09-07. Scope: `WeightedJudgeEvaluator` (facade private Map in-memory) → `DebateEngine` canonical `IDebateEvaluator` via `topology.metadata.councilMode` without hidden second runtime; где persitить голоса.

---

## 1) Current wiring — single `IDebateEvaluator`, но не selectable

- DI `phase3-debate-runtime:223` `register('debateEvaluator', () => new DebateEvaluator)` — **only** `DebateEvaluator`; `WeightedJudgeEvaluator` **not registered** (grep 0 `councilMode` in phase3).
- `DebateEngineDeps evaluator?: IDebateEvaluator` `debate-engine-types:100` optional singleton; `DebateEngine 114` stores `evaluator: deps.evaluator` in `PersistenceDeps`; `createSession handler 280` captures `evaluator` by closure from deps (not per-session).
- `Phase handler 18` `PhaseHandlerDeps {evaluator?: IDebateEvaluator, blindEval, bayesianJudge}` — one evaluator; `89` `if(to==='completed') if(deps.evaluator) claims→scoreArguments 177` + `blindEval` branch `101` → `bayesianJudge` + `qualityCollector 148`. **No `councilMode` branch**, `getEvaluator` does not exist, `rankParticipants` never called (dead code).
- Facade `council-service-facade:20` `private weightedJudge = new WeightedJudgeEvaluator()` — **second private instance**, not engine's; `submitJudgeScore 101` writes only to `weightedJudge.recordJudgeVote` when `debateEngine` exists, comment `old NOT called`; `getSession 59` merges `weightedJudge.votes` into `base.scores` for UI, but `votes Map` lost on reload (in-memory).

**Gap:** `WeightedJudgeEvaluator` **does implement `IDebateEvaluator` but is NOT engine's evaluator** → `DebateEngine` still `standard`/`blindEval` path, facade votes volatile. Cutover → потеря голосов.

## 2) CouncilMode flag readable — topology.config, not participant

- Writer `council-to-debate-mapper:30` `config:{lensId,polarityId,councilMode:true,doubleBlind,aliases,allowAudienceVoting}` per `TopologyNode.config`, `type:'roundtable' 41`, `maxRounds 45` — **per-node**, not top-level `metadata` (no `topology.metadata` field exists `debate-runtime:24`).
- Contract `TopologyNode {id,label,role,config?:Record}` `8`, `DebateTopology {id,type,nodes,edges,maxDepth?,maxRounds?} 24` — **no metadata**, snapshot carries `topology` verbatim `debate-session:222,238`.
- Engine access: `DebateEngine.getSession(sessionId):684` `snapshot.topology.nodes[0].config.councilMode` survives; `sessions.get(sessionId)` Map `50` → `getContext`/`getMemory` can read `session.topology.nodes[0].config.councilMode` inside `createSession` handler `280` (session passed).
- Plan `D3 89` says `topology.metadata.councilMode` — but code has **per-node**, not top-level — adapt to per-node flag.

**Design without second runtime:** `phase3` factory should **not** hardcode `evaluator: c.get('debateEvaluator') 588`. Make `DebateEngineDeps.evaluator` a **getter** or `getEvaluator(sessionId) => getSession(sessionId)?.topology.nodes[0].config.councilMode ? weightedJudge : debateEvaluator` — same getter pattern as `getRouterService` `537`. Simplest: register `weightedJudgeEvaluator` lazily and make `DebateEngineDeps.getEvaluator` optional.

## 3) Persistence for votes — DebateStore vs Council 3 tables vs other stores

- **Council 3 tables:** `council-types:9` `councilSessions|Messages|Votes` v24, `council-repository:56` judge `kind:'judge' voterId:judgeId pickId:winnerId payload:{scores,rationale,blind}`; `audienceVotes` `67`.
- **DebateStore canonical SSOT:** `storage/debate-store:8` `DebateSessionRecord {id,topic,topologyType,phase,round,totalTokens,Cost,agentStates:string,topology:string,participants:string,memory:string,startedAt,updatedAt,createdAt,version?,language}` — **no `judgeVotes` column** `39` `DebateVerdictRecord {sessionId,topic,summary,conclusionType,stanceResult,keyArguments:string,reasoning,confidence}` summary-level, not per-judge.
- **DebateStore save path stringified** `persistence-manager:233` `arguments:JSON.stringify(prunedArgs)` where `Claim speaker/role/confidence/evidence/citations` + `participants:JSON.stringify` + `topology:JSON.stringify` + `memory:memJson` — version CAS `attemptSave 137` `safeParse 142` + `MAX_RETRIES=3` + `newVersion=saveSnapshot 154` → `incrementVersion 157` + heap prune `27` + `Bucket RESEARCH slice(-500)` `62` + `timeline.persist 158`.
- **Timeline:** `debate-runtime:318 TimelineEntry {id,sessionId,timestamp,type,payload:unknown}`, `debate-timeline-repository:11` `put(entry)` → `debateTimeline` Dexie + `Bucket RESEARCH` `superagents:research:debate_timeline_${id} 44`. Handler emits `DEBATE_AGENT_SCORED:138` already, not judge vote.
- **keyValue:** `database-service:589 getKv/getKvCas/setKvCas 614` CAS with `throw Version conflict` inside transaction, backed by `keyValue` Dexie `454` — used for `sim:world` etc., not yet votes. Proposed `keyValue council:judge:<sessionId>` with checksum `docs/MIGRATION_SAFETY_AUDIT:66`.
- **debateVerdicts:** `dexie-storage:556 saveVerdict` separate table `database-service:324`, not per-judge.

### Options (no new engine):

- **A — `debateSessions.arguments` stringified** (least migration, already `string` `562`): synthetic `Claim speaker=judgeId role='judge' text=winnerId confidence=weight/maxWeight` plus `payload` via `Timeline`. Pro: no schema migration, version CAS guards. Con: pollutes argument stream, needs `role='judge'` filter.
- **B — `debateVerdicts` table** verdict-level: `keyArguments:string` or `reasoning` JSON per-judge breakdown. Pro: separate, no snapshot bloat. Con: not live ballot log, loses `scores Map/rationale/blind`.
- **C — `keyValue` with checksum/CAS** `key council:judge:<sessionId> {votes:Map, audience:Map, checksum}` via `setKvCas` `614`. Pro: no `DebateStore` schema change, CAS prevents lost update, `TimelineEntry` can reference checksum. Con: not co-located with snapshot → extra fetch in `restoreSession`.
- **D — `TimelineEntry` additive** `type council:judgeVote` `payload:{judgeId,winnerId,weight,blind,rationale}` + `council:audienceVote` replayable via `tallyWinner` from timeline `loadPersisted 346`. Pro: additive, preserves `blind`+`scores`, aligns with existing `TimelineEntry payload:unknown`. Con: replay cost, needs `timeline.loadPersisted` in `getContext:346` already present.

**Recommended without hidden second runtime:** Register **one** `WeightedJudgeEvaluator` as DI singleton (`phase3`) via factory reading `topology.nodes[0].config.councilMode` (`getEvaluator(sessionId)`), then persist votes via **TimelineEntry + keyValue checksum + snapshot arguments** (combination D+C+A). `facade:101` already `recordJudgeVote` with weight from `oldSession.judges` — should delegate to `DebateEngine` + `DebateStore.saveSnapshot` version CAS instead of `councilVotes`, but keep `councilVotes` read-only fallback until D4.5.

---

## Verdict

**Design: REGISTER one `WeightedJudgeEvaluator` as selectable `IDebateEvaluator` in `phase3` via `topology.config.councilMode` getter** — no second engine, one `Evaluator` interface, two strategies selectable per session. Persist via **TimelineEntry + keyValue checksum** (no new table, not `councilVotes`), keep `CouncilServiceFacade` as thin facade delegating `submitJudgeScore/castAudienceVote/conclude` to `DebateEngine` consensus pipeline (not `old.*`).

**Next:** Need `DebateEngineDeps.getEvaluator(sessionId)` or make `evaluator` getter, plus `WeightedJudgeEvaluator` DI registration, before `DebateStore` can be SSOT.

С богом — audit без кода, только контракт. Следующий этап — реализовать `getEvaluator` + TL persistence (one method at a time) — после твоего вердикта.
