## 1) Можно ли идемпотентно перенести `councilSessions/Messages/Votes`?

- **Council put non-transactional N+1:** `dal/council-repository:31` destruct `{facts,messages,scores,votes,...rest} 32` → `await db.councilSessions.put(record) 34` → loops `for f of facts await councilVotes.put 37`, `for m 53`, `for s 56`, `for v 67` — **no `db.transaction('rw',...)`**, crash mid-loop = partial aggregate. `deleteSession 143` `Promise.all(delete messages/votes)+delete session 148` non-atomic. `listSessions:132` `rows.toArray 133` + `for r await getSession(r.id) 136` → `2*N` queries (N+1) — не bulk, не лимит.

- **Mapper pure id same:** `services/council/council-to-debate-mapper:1` header *Pure mapper: CouncilSession → DebateSessionSnapshot, No save* `71` `councilToDebateSnapshot` pure `topology 72 + participants 73, argsFromFacts 76 + argsFromMessages 87 sorted timestamp 99` → `101` object `id: session.id 102` + `topology.id council-${id} 41` + `version:1 106` + `phase councilPhaseToDebatePhase 105` + `qualitySettings undefined 116`. **Same `id council-abc`** → natural idempotency via `Dexie put` overwrites `debateSessions:'id,phase,updatedAt,topic,folder,isArchived' 927` primary `id`.

- **DebateStore saveSnapshot same id + version CAS:** `storage/debate-store:54` `saveSnapshot(record): Promise<number>` returns new version, `DebateSessionRecordSchema:553` `version default 1 569` validated at `dexie-schema:1882` hook `creating/updating rejectHook`, `persistence-manager:137` `attemptSave safeParse 142` + `MAX_RETRIES=3 151` + `newVersion=saveSnapshot 154 → incrementVersion 157` + `HEAP prune 27` + `Bucket RESEARCH slice(-500) 62` + `catch version conflict 173` → `getSnapshot 181` + `parsed.data.version=dbVersion 184` + backoff `100*2^attempt 186` — safe only if `StorageLayer.debates.saveSnapshot` throws `version conflict` string (contract не enforce).

- **bulkPut vs single:** `grep bulkPut` only `key-migration/memory`, no `council→debate bulkPut` `MIGRATION_SAFETY:39`; `D3 plan:17` claims `migrateHistories bulkPut batched Promise.all not N+1` — **plan only, not implemented**. Current persistence single `saveSnapshot` per session via `attemptSave` — historical would be `for(session) { mapper→record stringified JSON 227: arguments/topology/participants/agentStates 233} → saveSnapshot` loop N× `JSON.stringify` + `safeParse`.

- **Idempotency via Map same id:** Mapper `id same council-abc → DebateStore id council-abc 102`, so natural `put` overwrites. **But** `facade:32` dual-write bug `old.createSession genId council-abc → snapshot.id same → debateEngine.createSession(topology,topic,…) → genId debate-xyz IGNORES snapshot.id 261` — return discarded, no `Map council:map:<id>` persisted → split-brain `old debare vs created` (`D4.3 PRE-FLIGHT:98`). Intended `Map keyValue council:map:<councilId>=debateId database-service:589 getKv/setKv/setKvCas 614` **grep 0 results** — not implemented. `keyValue flag council:migrated:batch` pattern exists `keys:migrated:v12` but **0 hits** for council.

**Conclusion:** Idempotent **possible only after** `createSessionWithId` same-id (D4.3 P0 fix) + `keyValue council:migrated:batch` CAS flag (not yet) + `saveSnapshot` loop with `version:1` + `safeParse` — today mapper pure but facade id-mismatch blocks idempotency.
