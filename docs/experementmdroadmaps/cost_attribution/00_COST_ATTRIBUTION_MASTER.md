# 00_COST_ATTRIBUTION_MASTER.md

## Vision

The goal of this cost attribution prototype is to provide granular visibility into the LLM usage costs generated by individual invocations within the SuperAgents OS ecosystem. By correlating token consumption data (`UsageTracker`) with real-time pricing (`PricingService`) and aligning them with the `InvocationEngine` context, we can unlock actionable insights into resource utilization, agent efficiency, and budget adherence.

## Architectural Anchors

- **Invocation Engine (`src/kernel/service-registration/phase21-invocation.ts`):** Acts as the primary correlation key. Invocations provide the `invocationId` necessary to link disparate events.
- **Usage Tracker (`src/kernel/services/usage-tracker.ts`):** The source of truth for token telemetry.
- **Pricing Service (`src/kernel/services/pricing-service.ts`):** Provides the unit costs applied to token consumption.
- **Budget Service (`src/kernel/services/budget-service.ts`):** Consumes aggregated cost events for monitoring and threshold alerting.

## Summary of Findings

Currently, token events (e.g., `EVENTS.STREAM_END` at `BudgetService:192`) carry metadata like `requestId` and `tokens`, which are sufficient for tracking global or provider-level spend, but they lack a robust, ubiquitous `invocationId` linkage. The `PricingService` provides accurate per-token calculations, but the association between a specific "stream end" event and its parent "invocation intent" is not explicitly maintained across the kernel boundary.

## Recommended Roadmap

1. **Infrastructure:** Enrich token usage events with `invocationId` at the boundary of `ChatExecutionEngine`.
2. **Correlation:** Build a passive listener to map `requestId` (from usage) to `invocationId` (from intent).
3. **Attribution:** Attribute costs directly to invocation records via the `InvocationRepository`.
4. **UX:** Expose cost metadata in the Room/Director UI.
