# 13_UI — `agent-doc-auditor` in the UI

**VERIFIED.** Doc-auditor is rendered by the **generic** Agents UI and the RoomPanel; there is no agent-specific component for it.

## AgentsPanel (`src/components/AgentsPanel/`)

- `AgentsPanelContainer.tsx:78-94` loads agents via `getAgentsFromTopology()` (the topology-backed list → `agentService.getAgents()`). Doc-auditor appears as a card.
- `AgentCard.tsx` renders name/role/status/stats/tags generically — for doc-auditor: name "Felix Moreau" (or label "Auditor Agent" if displayName not applied at UI layer), role "Documentation Auditor", 🔍 avatar (`#ec4899`), status from lifecycle, stats from `AgentStats`. `agents.pause_agent_title` etc. i18n (`i18n/translations/{en,ru}/agents.ts`).
- `AgentDetailPanel.tsx`, `AgentIdentityEditor.tsx`, `AgentWizard.tsx`, `AgentAvatar.tsx` are all generic. `AgentAvatar` resolves emoji/color from the identity (doc-auditor → 🔍). `AgentIdentityEditor` would let a user edit doc-auditor's prompt/role (data-only change).
- `EloLeaderboard.tsx` (`components/AgentsPanel/EloLeaderboard.tsx:111`) ranks doc-auditor if it has debated.
- `AgentComparisonPanel.tsx` / `AgentComparison.tsx` allow side-by-side compare — doc-auditor vs any other agent.

## Other surfaces reusing `AgentsPanel/AgentAvatar`

- `DebatePanel/DebateAnalytics.tsx`, `DebateRuntimePanel/AgentControlPanel.tsx`, `DashboardPanel/AgentLiveBoard.tsx` (`getAgentsFromTopology()`, `:64`), `DirectorPanel/AgentIdentityChip.tsx`, `ForumPanel/AuthorBadge.tsx`, `components.tsx`. All render doc-auditor identically via shared `AgentAvatar` + `resolveAgentIdentity`.

## RoomPanel (`src/components/RoomPanel/RoomPanel.tsx`)

- `:89` builds agent options from `agentService.getAgents()`; doc-auditor listed as "Felix Moreau — Documentation Auditor" (id→name map `:117`). The Invoke form submits to `invocationEngine.invoke` (`06_INVOCATION.md`). No doc-auditor-specific control.

## i18n

- `nav.agents` (`i18n/translations/{en,ru}/nav.ts:33`), `agents.*` (`i18n/translations/{en,ru}/agents.ts`). No `agent-doc-auditor`-specific translation keys (would be data, not UI code).

## OPINION

Doc-auditor is fully "UI-complete" through generic components — no bespoke panel is needed or exists. Any auditor-specific UX (e.g. a "show contradictions found" view) would require new UI + a backing store (see `15_DO_NOT_BUILD_YET.md`), not just config.
