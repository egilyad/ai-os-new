## Explicit assessment per integration axis

### Agent → Debate (VERIFIED)

- Participates as a node/participant. Side (pro/con/neutral) from debate config, NOT specialization. Persona selected by topic keywords (`persona-selector.ts:251`). The invocation delegate forces `neutral` for debate mode (`phase21-invocation.ts:81`).
- **Gap:** no networking-aware stance; TCP/IP/SDN never influence argument framing.

### Agent → Cognitive (VERIFIED + INFERRED)

- Visible only via `COGNITIVE_STEP_COMPLETED` (stats + journal). Debate path emits none. `cognitive:decision:made` is dead-at-consumer. `cognitive:trace:updated` / `cognitive:step:active` exist but AgentService consumes only COMPLETED.
- **Gap:** during a debate Nadia is cognitively invisible (no step events).

### Agent → Memory (VERIFIED + INFERRED)

- Generic stores support `agentId` queries (`episodic-memory.ts:53`, `social-memory.ts:33`, `service-backed-memory.ts:46`) but nothing seeds network-specific memory. Only the Agent Journal records per-agent activity.
- **Gap:** no continuity; each session starts cold.

### Agent → Invocation (VERIFIED)

- Human-invokable via RoomPanel (chat/debate/director-scenario). Expertise/role/scheduler invocation supported by engine but unused (`invocation-engine-service.ts:158-173`).

### Agent → Research (INFERRED)

- No agent-specific research wiring. Research algorithms/service are cross-cutting; `agent-network` not referenced.

### Agent → Workflow / Builder (INFERRED)

- No agent-specific workflow. Builder generates topologies; `agent-network` is a static seed node, not generated by it.

### Agent → Knowledge / Crystal (INFERRED)

- Cross-cutting. `agent-network` has no seeded crystal/knowledge contribution. Could appear as a crystallized perspective author indirectly.

### Agent → Forum (VERIFIED/POTENTIAL)

- Can appear as `AuthorBadge` if it posts. No seeded network topic.

### Agent → Scheduler (INFERRED)

- Invocation engine supports `module-event` source + `allowAgentInitiatedInvocation` (`invocation-engine-service.ts:124-144`); no policy enables scheduled/agent-initiated Nadia invocation.

### Agent → ConversationCore (VERIFIED)

- Full participant: persona + pinned model injected (`conversation-execution-engine.ts:40-73`). Emits `conversation:*` + `cognitive:step:completed`.

## Other agents it touches (VERIFIED)

- `router` (upstream, `topology-defaults.ts:471`), `aggregator` (downstream, `:523`).
- Collaboration candidates (INFERRED): `agent-architect`, `agent-security`, `agent-devops`.

## Reuse summary

Every capability reuses an **existing** service. The only missing pieces are _wiring_ (policy, lens, group, memory-seed, journal UI), not new engines. This strongly favors Quick Wins over new frameworks (see 11/13/14).
