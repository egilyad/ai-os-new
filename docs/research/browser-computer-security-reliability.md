# Исследование (сессия 4): безопасность и устойчивость браузерных/компьютерных агентов

> Тема: как защитить и сделать надёжным управление браузером/компьютером: песочница, сеть, разрешения, retry, восстановление.

## 1. Угрозы

| Угроза                   | Пример                                   | Последствие       |
| ------------------------ | ---------------------------------------- | ----------------- |
| Prompt injection с сайта | Контент страницы инструктирует агента    | Опасные действия  |
| SSRF                     | Запрос к внутренним сетям/cloud metadata | Утечка/доступ     |
| Опасные действия         | Отправка данных, покупка, загрузка       | Реальный ущерб    |
| Утечка секретов          | Куки/токены попадают в логи              | Компрометация     |
| Атака на сессию          | Подмена контекста                        | Неверные действия |

## 2. Безопасность

| Механизм               | Суть                                | Статус рекоменд. |
| ---------------------- | ----------------------------------- | ---------------- |
| Изоляция контекстов    | Каждая сессия — отдельный профиль   | Да               |
| Сетевая политика       | Блокировка внутренних/cloud-адресов | Да               |
| Разрешения на действия | Подтверждение опасных операций      | Да               |
| Guardrails             | Проверка намерения перед действием  | Да               |
| Маскировка секретов    | Куки/токены не в логах              | Да               |
| Аудит                  | Полный след действий                | Да               |

## 3. Устойчивость

| Механизм              | Суть                                        |
| --------------------- | ------------------------------------------- |
| Retry с backoff       | Повтор при временных сбоях                  |
| Timeout               | Зависшие действия                           |
| Восстановление сессии | Перезапуск браузера с сохранением состояния |
| Fallback методов      | DOM → vision → координаты                   |
| Идемпотентность       | Повторные действия безопасны                |
| Snapshot/rollback     | Откат к предыдущему состоянию               |

## 4. Проектирование

- **Сетевая политика**: в `BrowserHarness` — перехват запросов и блокировка запрещённых адресов (private/cloud metadata).
- **Разрешения**: перед деструктивным действием — вызов политики/подтверждение человека.
- **Аудит**: каждое действие записывается (скриншот + выбранный метод + результат) для replay.
- **Устойчивость**: обёртка действий с retry/timeout/fallback.

## 5. Вывод

Безопасность и устойчивость — обязательные слои. Минимальный набор: **изоляция контекстов**, **сетевая политика (блокировка SSRF)**, **разрешения на деструктивные действия**, **аудит**, **retry/timeout/fallback**, **восстановление сессии**.
