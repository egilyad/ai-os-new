# Исследование (сессия 1): Browser automation-фреймворки

> Тема: какие фреймворки управляют браузером, их возможности, сравнение, и как спроектировать абстракцию для SuperAgents OS.

## 1. Основные фреймворки

| Фреймворк          | Движок                  | Сильные стороны                                                             | Ограничения                         |
| ------------------ | ----------------------- | --------------------------------------------------------------------------- | ----------------------------------- |
| Playwright         | Chromium/Firefox/WebKit | Кросс-браузерность, автовейт, сетевой перехват, traces, изоляция контекстов | Тяжелее Puppeteer                   |
| Puppeteer          | Chromium                | Простой API, быстрый старт                                                  | Только Chromium, меньше встроенного |
| Selenium WebDriver | Все браузеры            | Зрелость, экосистема, WebDriver                                             | Медленнее, сложнее                  |
| Cypress            | Chromium                | Отличный DX для e2e                                                         | Ограничен браузером/домен           |
| WebDriver BiDi     | Стандарт                | Протокол двусторонний, будущее кросс-браузерности                           | Молодой                             |

## 2. Что важно для агента (не для тестов)

- **Сетевой перехват**: видеть запросы/ответы, мокать, блокировать.
- **Автовейт**: ожидание появления элементов (важно для медленных страниц).
- **Изоляция контекстов**: отдельные «вкладки/сессии» без пересечения.
- **Скриншоты**: захват экрана/элемента.
- **Traces**: воспроизводимый след действий.
- **Заполнение форм/клики/навигация**: базовые действия.
- **Извлечение DOM**: получение данных/структуры страницы.

## 3. Выбор для SuperAgents OS

**Рекомендация: Playwright.** Причины:

- Встроенная изоляция контекстов (важно для нескольких параллельных сессий/агентов).
- Перехват сети и мокание (для безопасного тестирования).
- Возможность авто-ожидания и перехвата ошибок.
- Поддержка всех основных браузеров.

Создать абстракцию `BrowserHarness` поверх Playwright, чтобы позже подменить движок (например, добавить WebDriver BiDi или виртуальный браузер).

## 4. Проектирование BrowserHarness (абстракция)

```ts
interface BrowserHarness {
  newContext(opts): Promise<BrowserContextSession>; // изолированная сессия
  navigate(url): Promise<void>;
  click(selector): Promise<void>;
  fill(selector, value): Promise<void>;
  extract(selector?): Promise<string>; // текст/DOM
  screenshot(): Promise<Buffer>;
  waitFor(selector): Promise<void>;
  interceptRoute(pattern, handler): Promise<void>;
  close(): Promise<void>;
}
```

- Контекст = изолированная «вкладка» с собственными cookies/состоянием.
- Все действия возвращают результат + метаданные (для трасс).
- Ошибки → типизированные (timeout, element-not-found, navigation-blocked).

## 5. Связь с безопасностью

- Сetroвой перехват позволяет блокировать опасные URL (metadata, внутренние сети).
- Контексты изолируют сессии друг от друга.
- Все действия записываются для аудита.

## 6. Вывод

Для агента оптимален **Playwright** как движок. Ключевое — спроектировать `BrowserHarness`-абстракцию: изолированные контексты, перехват сети, автовейт, скриншоты, трассы и безопасность. Это фундамент всех последующих шагов (computer use, скрейпинг, автономные сценарии).
