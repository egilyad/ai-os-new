> Метод: аналитический обзор открытых архитектур (без API-запросов). Границы: многоагентные фреймворки, «агентные ОС», субагентные режимы и исследовательские системы.

## 2.1. Системы и их уникальные паттерны

Детальный разбор того, чем конкретные проекты отличаются друг от друга (и какие паттерны каждый из них «изобрёл» первым или лучшим).

| Система                  | Тип                        | Уникальное / редкое                                                     | Какой паттерн даёт нам                                               |
| ------------------------ | -------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| MetaGPT                  | Роли-агенты                | «Компания» ролей (PM, архитектор, инженер, QA) с чёткими deliverable    | Многостадийный конвейер ролей, строгий контракт вывода между ролями  |
| AutoGen                  | Group chat                 | Динамические групповые беседы агентов, завершение по критерию           | Оркестрация group chat + консенсус; «спикер-селекция»                |
| CrewAI                   | Крев-оркестрация           | Команды агентов с задачами и «процессами» (sequential/hierarchical)     | Декларативное описание команды → исполнение                          |
| LangGraph                | Граф состояний             | Явный граф с checkpoints, cycle, conditional edges                      | **Long-horizon и машина состояний с checkpoint (паттерн 9)**         |
| OpenAI Agents SDK        | Лёгкий субагент            | Ручная передача управления между агентами, guardrails                   | Лёгкая иерархия агентов + guardrails                                 |
| OpenHands / OpenDevin    | Виртуальный инженер        | Песочница для кода, события среды, агент-щит                            | **Sandbox (паттерн 8)** и адаптация к среде                          |
| Claude Code / Codex      | Субагентный режим          | Spawn субагентов, запись навыков (record a skill), файловые разрешения  | **Record a Skill (паттерн 3)**, sub-agent spawn, permission-политики |
| Anthropic Research       | Многоагентное исследование | Orchestrator-worker, отдельный citation-агент, глубинный синтез         | **Claim-centric synthesis (паттерн 1)**, citation-агент              |
| Perplexity Deep Research | Один итеративный агент     | Test-time compute, десятки параллельных поисков, прозрачное цитирование | **Конвергенция по маргинальной отдаче**, дедупликация                |
| AIOS                     | Агентная ОС                | ОС-слой: планировщик агентов, аллокация памяти, «кольцо защиты»         | Выделение планировщика/памяти/безопасности как подсистем ОС          |
| Reflexion                | Самокоррекция              | Вербальная рефлексия → обновление памяти                                | **Само-рефлексия (паттерн 15)**                                      |
| Voyager                  | Обучение навыкам           | Библиотека навыков, автономное исследование в Minecraft                 | Навыки как расширяемый реестр                                        |
| smolagents               | Минимализм                 | Агент с «кодом как действием»                                           | Компактность, вывод действий кодом                                   |
| CAMEL                    | Многоагентная ролевая игра | «Inception prompting»: роль-инициатор + роль-помощник                   | Длинный диалог без деградации (контекстное управление)               |
| AutoGPT / BabyAGI        | Автономный цикл            | Циклы: цель → задача → действие → память                                | Замкнутый контур «цель-действие-память»                              |

### Ключевые выводы из сравнения

1. **Linearity против графа.** Большинство систем идут «линейно» (AutoGPT, smolagents). Лишь LangGraph и редкие проекты дают явный граф состояний с checkpoint — это самый ценный паттерн для долгих задач.
2. **Память как чёрная доска vs. память как хранилище.** Blackboard/Global Workspace встречается реже всего и даёт «общий фокус внимания» — мы его пока не имеем.
3. **Навыки — новейший тренд.** Codex/Claude (record a skill) и Voyager показывают, что «система учится процедурам» — это редкое и очень полезное свойство.
4. **Доверие/доказательства.** Только исследовательские системы (Anthropic, Perplexity) доводят claim-centric evidence до уровня «каждое предложение = цитата». У нас для этого есть Crystal Vault — уникальная основа.
5. **Песочница** — обязательное условие для запуска кода/инструментов с побочными эффектами; у многих она вынесена в отдельный сервис (E2B, OpenHands sandbox).

## 2.3. Субагентные режимы: OpenHands и Codex/Claude (углублённо)

Эти две системы ближе всего к «агентному инженеру», который реально работает с кодом — наиболее релевантны SuperAgents OS как источники паттернов.

### OpenHands (OpenDevin)

Ключевые идеи:

- **Агент-щит (agent shield)** — защита от опасных действий; «второй агент» проверяет действия первого.
- **События среды (event stream)** — каждая операция в sandbox записывается как поток событий; состояние сессии воспроизводимо.
- **Песочница (Docker)** — изоляция выполнения кода, файлов, сетей.
- **Адаптация к среде** — агент учится работать с реальным репозиторием (git, тесты, редактор).

Полезное для нас:

- Поток событий среды (событийная модель) — уже близко к нашему EventBus; можно усилить воспроизводимость сессий.
- «Агент-щит» — паттерн критики/guardrail отдельных шагов.

### Codex / Claude Code

Ключевые идеи:

- **Sub-agent spawn** — запуск дочерних агентов с собственным контекстом и бюджетом токенов; результат возвращается родителю.
- **Record a skill** — запись выполненной процедуры как повторяемого навыка.
- **Файловые/инструментные разрешения** — подтверждение на запись/чтение/выполнение.
- **Человек-в-цикле** — пауза на утверждение опасных операций.
- **Мониторинг активных процессов** — список параллельно работающих задач.

Полезное для нас:

- Sub-agent spawn с изоляцией контекста (паттерн 2).
- Record a skill / процедурная память (паттерн 3).
- Permission-политика (паттерн 7).

### Что заимствовать в первую очередь

| Из OpenHands                        | Из Codex/Claude            |
| ----------------------------------- | -------------------------- |
| Воспроизводимый поток событий среды | Sub-agent spawn с бюджетом |
| Агент-щит (guardrail на шаге)       | Record a skill (навыки)    |
| Песочница с изоляцией               | Разрешения на инструменты  |

## 2.4. Безопасность и доверие (углублённо)

Для мультиагентной ОС, работающей с реальными инструментами и секретами, безопасность — не опция, а фундамент.

| Паттерн                             | Что даёт                             | Реализация в известных системах     | Статус у нас                |
| ----------------------------------- | ------------------------------------ | ----------------------------------- | --------------------------- |
| Vault секретов (шифрование at-rest) | Ключи не лежат plaintext             | KeyVault-паттерн (AES-GCM)          | Написан, не подключён (C-7) |
| Sandbox с отрезанной сетью          | Код не имеет доступа в сеть          | OpenHands, E2B (connect-src 'none') | Нет (BLOCKED-RUNTIME)       |
| Permission-политика инструментов    | Человек подтверждает side-effect     | Claude, OpenHands                   | Частично (Governance)       |
| Guardrails I/O                      | Валидация ввода/вывода LLM           | OpenAI Agents SDK                   | Частично                    |
| Provenance/trust-score              | Ранжирование по надёжности источника | Deep Research                       | Частично (trust)            |
| Изоляция контекста субагентов       | Дочерний агент не видит лишнего      | Codex                               | Нет                         |

### Выводы для нас

- Самый критичный разрыв — **Vault не подключён** (ключи в открытом виде) и **песочница не реализована**. Это P0.
- Реализуемо поэтапно: сначала подключить KeyVault + маскировку секретов, затем песочницу, затем permission-политику инструментов.

## 3. Топ-8 редких паттернов, которые стоит внедрить

По сочетанию «редкость × полезность для нам»:

1. **Claim-centric evidence** — сделать выводы строго из проверяемых утверждений с цитатами (Crystal Vault → од разработки).
2. **Record a Skill / процедурная память** — превращать удачные цепочки действий в повторяемые навыки.
3. **Blackboard / Global Workspace** — общий «фокус внимания» для агентов вместо разрозненного контекста.
4. **Sub-agent spawn с изоляцией** — запуск субагентов со своим контекстом и бюджетом.
5. **Cross-session memory consolidation** — фоновая консолидация и забывание.
6. **Sandbox с отрезанной сетью** — защита выполнения кода.
7. **Long-horizon state machine с checkpoint/resume** — переживание перезагрузки.
8. **Multi-agent debate с ограничением семейств** — снижение подстройки и предвзятости судей.

## 4. Что в SuperAgents OS уже сильно (не нужно «изобретать»)

- **Дебаты**: 33+ стратегии, живые графы, вердикты — это уже целевая зона поверх многих фреймворков.
- **Crystal Vault + Junction + Synthesis**: ядро claim-центричной работы уже заложено.
- **Маршрутизация UCB1/broadcast/race** и декораторы (circuit breaker, retry, rate-limit, cost manager).
- **Знаниевый конвейер** и гибридный поиск (BM25 + семантика).

## 6. Вывод

Мультиагентные ИИ-ОС уже выработали несколько «редких» паттернов, которых у SuperAgents OS пока нет, но которые дают наибольший рывок в глубине и надёжности. Лучший ROI — **claim-centric evidence**, **процедурная память (навыки)** и **песочница**. При этом значительная часть фундамента (дебаты, Crystal Vault, маршрутизация) уже сильнее, чем у большинства открытых систем — поэтому усилия стоит вкладывать не в «догнать», а в «замкнуть цикл» и «углубить доверие».
