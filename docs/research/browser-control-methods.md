# Исследование (сессия 2): способы управления браузером

> Тема: как агент «видит» и «действует» в браузере — DOM-селекторы, визуальные (скриншоты/зрение), accessibility-tree, координаты. Когда что использовать.

## 1. Способы восприятия страницы

| Способ                     | Как работает                     | Плюсы                             | Минусы                            |
| -------------------------- | -------------------------------- | --------------------------------- | --------------------------------- |
| DOM (HTML)                 | Доступ к элементам/структуре     | Точность, скорость, дёшево        | Не видит рендер/визуальные нюансы |
| Accessibility tree         | Семантическое дерево доступности | «Чистые» элементы (кнопки, поля)  | Не всё покрыто                    |
| Скриншот + зрение (vision) | Изображение → анализ LLM         | Как «видит» человек, универсально | Дорого, медленно                  |
| Координаты (click by xy)   | Клик по координатам              | Когда нет селектора               | Хрупко, зависит от макета         |

## 2. Когда что использовать

- **DOM**: для точных действий (формы, списки, ссылки) — дёшево и надёжно.
- **Accessibility tree**: для «сервисных» элементов (кнопки, поля ввода, диалоги).
- **Vision (скриншот)**: для сложных/каптивных UI, канвасов, изображений, визуальных проверок.
- **Координаты**: как последний резерв, когда ничего больше не сработало.

## 3. Гибридный подход (рекомендация)

1. Попробовать DOM/accessibility (быстро и дёшево).
2. Если не удалось → скриншот + vision, LLM выбирает цель (по описанию и координатам).
3. Всегда сохранять результат и «почему выбран селектор/координаты» (для трасс и обучения).

Это сочетает скорость DOM и универсальность vision.

## 4. Что нужно от LLM-агента

- Умение «читать» DOM/accessibility и выбирать действия.
- Умение «смотреть» скриншот (vision-модель).
- Принятие решения: когда селектор, когда координаты.
- Запоминание рабочего селектора для повторного использования (обучение).

## 5. Связь с безопасностью и устойчивостью

- Селекторы можно валидировать (безопасные символы).
- Vision-анализ может блокироваться политикой.
- При ошибке — fallback между методами (DOM → vision → координаты).

## 6. Вывод

Оптимально — **гибрид**: сначала DOM/accessibility (дёшево), при неудаче — скриншот+vision. Это даёт и скорость, и универсальность. В `BrowserHarness` заложить переключатель методов и логирование выбора.
