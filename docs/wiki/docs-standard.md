# Стандарт документации

> Автосгенерировано `scripts/gen-wiki-docs-standard.mjs` из `scripts/lib/entity-model.mjs`.
> Не редактировать вручную — правьте источник и перегенерируйте.

Это логика документации проекта: что мы считаем фактом, откуда берём данные и как
различаем реализованное, проверенное и запланированное. Остальные статьи и каталоги
опираются на этот стандарт. Он отражает текущую систему (вики, manifest, генераторы),
а не вводит параллельную инфраструктуру.

Версия стандарта: **1**. Машиночитаемая форма — `docs/entity-model.json` (для агентов и инструментов).

## Категории документации

| Категория | Где | Назначение | Генерируется |
| --- | --- | --- | --- |
| wiki | `docs/wiki/ + панель Wiki` | Полная документация: гайды, домены, панели, зоны, каталоги | да |
| top | `docs/*.md` | Крупные описания (архитектура, сервисы, манифест, реестр) | нет |
| reference | `docs/reference/` | Нормативные справочники, матрицы, контракты | нет |
| roadmap | `docs/roadmap/` | Планы и направления (не текущее состояние) | нет |
| audits | `docs/audits/` | Отчёты проверок; хранятся как история | нет |
| history | `docs/history/` | Архив старого с исторической ценностью | нет |
| superseded | `docs/superseded/` | Заменённое другим документом | нет |
| active | `docs/active/` | Текущая рабочая документация | нет |
| new | `docs/new/` | Черновики (в основном вне git) | нет |

## Карточка сущности

Единый набор полей для любой сущности (статья, панель, сервис, событие).
«Авто» — поле заполняется генератором; остальные — вручную и не стираются.

| Поле | Обязательное | Авто | Что содержит | В вики-манифесте |
| --- | --- | --- | --- | --- |
| `id` | да | да | Стабильный идентификатор: wiki:<slug>, panel:<id> | `id` |
| `title` | да | да | Человекочитаемое название | `title` |
| `type` | да | да | Тип сущности: article | panel | service | event | … | `type` |
| `summary` | нет | нет | Краткое назначение в одну строку | `—` |
| `purpose` | нет | нет | Зачем сущность существует | `—` |
| `status` | да | да | Статус достоверности (см. ниже), не путать с реализацией | `status` |
| `language` | нет | да | Язык материала: ru | en | mixed | `—` |
| `audience` | нет | нет | Для кого: новичок, пользователь, разработчик… | `—` |
| `source_files` | нет | да | Файлы-источники утверждения | `sources` |
| `test_files` | нет | да | Проверяющие тесты | `tests` |
| `related_docs` | нет | да | Связанные статьи вики | `related` |
| `related_entities` | нет | да | Связанные сущности (панели, сервисы) | `—` |
| `related_commits` | нет | нет | Ссылки на коммиты | `—` |
| `related_audits` | нет | нет | Связанные аудиты | `—` |
| `known_issues` | нет | нет | Известные проблемы | `—` |
| `evidence` | нет | да | Чем подтверждено (файл/тест/запуск) | `tests` |
| `verification_method` | нет | нет | Как проверить утверждение | `—` |
| `confidence` | нет | нет | Степень достоверности | `status` |
| `generated` | да | да | Собрано генератором (да) или написано человеком (нет) | `—` |
| `manual_sections` | нет | нет | Ручные разделы, которые генерация не стирает | `—` |
| `history` | нет | нет | История изменений сущности | `—` |

## Статусы достоверности

**Статус реализации ≠ статус проверки.** «Реализовано» и «проверено» — разное,
и смешивать их нельзя. Поэтому статусы разделены по измерениям.

| ID | По-русски | Измерение | Смысл |
| --- | --- | --- | --- |
| `verified` | Проверено | verification | Подтверждено указанным способом (код + тест/запуск). |
| `unverified` | Требует проверки | verification | Сведения есть, но подтверждения нет. |
| `unknown` | Неизвестно | verification | Достоверных сведений недостаточно. |
| `implemented` | Реализовано | implementation | Реализация найдена, тесты не гарантированы. |
| `partially_implemented` | Частично | implementation | Реализована только часть заявленного. |
| `planned` | Запланировано | implementation | Заявлено, но не реализовано. |
| `experimental` | Экспериментально | implementation | Опытная реализация. |
| `simulated` | Симуляция | implementation | Демонстрационный/симулированный режим. |
| `deprecated` | Устарело | lifecycle | Механизм выводится из употребления. |
| `historical` | Историческое | lifecycle | Материал о прошлом состоянии. |

### Соответствие текущим статусам вики

В корпусе вики поле статуса (freshness) уже используется; оно отображается так:

| Значение в вики | По-русски | Статус достоверности |
| --- | --- | --- |
| `verified` | Подтверждено кодом | `verified` |
| `documented` | Из документов | `implemented` |
| `needs-check` | Требует проверки | `unverified` |
| `not-implemented` | Не реализовано | `planned` |

## Источники истины

Что считается первоисточником по каждому типу утверждений.

| О чём | Источник | Как проверить |
| --- | --- | --- |
| Существование кода, сервиса, панели | Исходники репозитория | Файл/символ резолвится (docs:health resolveModule) |
| Панель → маршрут → компонент | src/route-registry-*.ts, src/route-imports.ts | Каталог панелей / manifest |
| Успешность теста | Результат запуска в CI | Зелёный job, не «тест существует» |
| Текущее устройство системы | Код + вики-корпус (wiki-articles.ts) | docs/wiki и manifest |
| Историческое решение/проблема | Исходный отчёт (audits/, zones) | Файл отчёта, не его пересказ |
| План/будущее | docs/roadmap/ и раздел «История» | Не выдаётся за реализованное |
| Состояние документации | docs:health + docs/inventory.json | Реальный прогон проверок |
| Связи сущностей | Генераторы связей (manifest, wiki-connections) | Подтверждаются кодом, не совпадением имён |

## Идентификаторы

| Тип | Схема | Пример |
| --- | --- | --- |
| Статья вики | `wiki:<slug>` | `wiki:panel-chat` |
| Панель | `panel:<nav-id>` | `panel:chat` |
| Документ вне вики | `путь от корня` | `docs/audits/…md` |

## Политика языков

- **Основной язык:** `ru`. Основной язык подробной документации — русский. Английские названия сущностей, библиотек и API сохраняются как есть.
- **Английский:** `README_EN.md` — статус `mirror`.
  Английский README — зеркало входа: те же ссылки в вики, что и в русском (паритет проверяет docs:health). Сами статьи вики — русскоязычные; статус EN — «вход синхронизирован, содержимое вики на русском».

## Правила истории

- Оригинальные отчёты (audits/, history/, зоны) сохраняются без смысловой переписи.
- Устаревшее переносится в архив, а не удаляется.
- Исправление очевидной ошибки в историческом отчёте помечается явно с сохранением происхождения.
- Текущее состояние не смешивается с историей: зона — это запись о прошлой работе, а не описание сегодняшнего кода.
- Каждый значимый показатель имеет источник и метод подсчёта.
