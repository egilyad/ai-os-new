Гляну, что внутри `.opencode` и как он в `.gitignore`, чтобы аккуратно закоммитить плагин.

Судя по всему, `.opencode` игнорируется общим паттерном. Закоммичу только файл плагина принудительно (`-f`), не трогая остальное содержимое.

Готово — запушено `e753514`. Плагин теперь в git (принудительно, т.к. `.opencode` в ignore), так что он сохранится в репозитории.

Итог автосохранения ответов:
- `.opencode/plugins/session-wiki.js` — ловит `session.idle` (завершение ответа) и запускает экспорт.
- `npm run session:turns` — читает `opencode.db`, пишет каждый ответ ассистента отдельным `.md` в `docs/sessions/turns/` + зеркало `docs/wiki/sessions/turns/`.
- `scripts/gen-wiki-docs.mjs` — рекурсивно зеркалит `docs/sessions` → `docs/wiki/sessions`.

**Что нужно сделать тебе:** перезапустить opencode (плагины грузятся при старте). После этого каждый новый ответ будет сохраняться автоматически — без команд. Проверить можно после следующего ответа: файл появится в `docs/sessions/turns/`.

Одна деталь: плагин пишет файлы, но не коммитит их сам — при желании могу добавить в плагин также автокоммит (git add/commit/push после экспорта), чтобы ответы не только писались, но и улетали в репозиторий. Добавить автокоммит?
