# 00 — Обзор системы

## Концептуальный уровень

SuperAgents OS — это **многоагентная когнитивная оркестровая система**. Это не платформа для чат-ботов, не агентный фреймворк и не движок рабочих процессов. Это среда выполнения, которая управляет структурированным рассуждением через множество агентов на базе LLM — обеспечивая порядок ходов, отслеживая утверждения, измеряя конвергенцию и интерпретируя результат.

Система существует для решения одной ключевой проблемы: **ответы LLM неструктурированы, невоспроизводимы и неизмеримы**. SuperAgents OS накладывает структуру на многоагентное взаимодействие, чтобы рассуждение стало отслеживаемым артефактом — графом утверждений с измеримыми свойствами (глубина, разнообразие, конвергенция, оригинальность).

## Уровень системного отображения

Система организована как многоуровневая среда выполнения:

- **Ядро** (`src/kernel/`) — DI-контейнер, шина событий, контракты, управление жизненным циклом
- **Сервисы** (`src/kernel/services/`) — оркестрация дебатов, губернатор, интерпретация, метрики, маршрутизация провайдеров
- **UI** (`src/components/`) — React-панели для настройки дебатов, отслеживания в реальном времени, посмертного анализа
- **LLM** (`src/llm/`) — адаптеры провайдеров с декораторами (автоматический выключатель, повторные попытки, лимит запросов, кэширование)

В системе существует **два параллельных движка дебатов**:

| Движок              | Файл                                    | Назначение                                                                                           |
| ------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `DebateSyncManager` | `debate-runtime/debate-sync-manager.ts` | Высокоуровневый, синхронный, одиночная сессия. Используется UI. Имеет метрики и интерпретацию        |
| `DebateEngine`      | `debate-runtime/debate-engine.ts`       | Управляемый контрактами, DAG-топология, формальный фазовый жизненный цикл. Бюджет, память, консенсус |

Документация фокусируется на `DebateSyncManager` — основном движке, используемом для интерактивных дебатов.

## Уровень поведения

Во время выполнения система:

1. **Получает тему** и список участников от пользователя
2. **Отправляет вызовы LLM** каждому участнику последовательно (для вступительных заявлений), а затем в порядке, определённом стратегией (для последующих раундов)
3. **Отслеживает каждый аргумент** как структурированный `DebateArgument` с метаданными (источник, уверенность, ссылка на родителя, используемый провайдер)
4. **Питает губернатора** (`DebateGovernor`), который извлекает утверждения, строит граф утверждений, обнаруживает противоречия и вычисляет конвергенцию
5. **Измеряет** дебаты с помощью графовых метрик, метрик активности и метрик качества
6. **Интерпретирует** результат — пик разногласий, точки изменения траектории, инсайты
7. **Генерирует события** на каждом шаге, чтобы UI мог реагировать в реальном времени

Система НЕ:

- Притворяется, что вывод LLM надёжен (всё измеряется и существуют резервные цепочки)
- Использует один вызов LLM для сложных задач (встроено многоагентное разбиение)
- Предполагает, что первый провайдер сработает (повторные попытки с переключением провайдера до 3 попыток)
- Хранит мутируемое состояние (глубокая заморозка + структурированное клонирование для чтения состояния)
