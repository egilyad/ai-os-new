# 02 — Основные концепции

## 2.1 Агенты

### Слой концепций

**Агент** в SuperAgents OS — это не постоянная сущность с памятью и идентичностью. Это **слот участника** в дебатах — роль (за/против/нейтральный/Сократ) с системным промптом, опциональной привязкой к провайдеру, опциональным ограничением и опциональным архетипом. Агенты не имеют состояния между дебатами; их «личность» исходит из промпта, а не из постоянного состояния.

### Слой системного отображения

```
DebateParticipant {
  id: string;
  name: string;
  role: 'pro' | 'con' | 'neutral';
  systemPrompt?: string;     // Переопределение по умолчанию
  provider?: string;          // Предпочтительный провайдер (напр. "groq")
  modelId?: string;           // Предпочтительная модель
  constraint?: DebateConstraint;
}
```

25 агентов по умолчанию берутся из `topology-defaults.ts`:

| Категория                  | Агенты                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Технические (6)**        | Системный архитектор, Инженер безопасности, DevOps-инженер, Инженер баз данных, Сетевой инженер, Инженер производительности |
| **Аналитические (5)**      | Критический аудитор, Дата-сайентист, Аналитик рисков, Исследователь, Инженер качества                                       |
| **Креативные (4)**         | Креативный визионер, Продуктовый дизайнер, Контент-стратег, UX-исследователь                                                |
| **Управленческие (3)**     | Проектный менеджер, Владелец продукта, Тимлид                                                                               |
| **Специализированные (2)** | Технический писатель, Специалист по этике                                                                                   |
| **Документационные (5)**   | Агент-архитектор, Агент-аудитор, Агент-упроститель, Агент-историк, Проверяющий согласованность                              |

### Слой поведения

- Агенты выступают в порядке, определяемом стратегией, а не все сразу
- Для каждого агента формируется промпт из: контекста роли + блока архетипа + блока ограничений + тона температуры + контекста состояния дебатов
- Агент, у которого произошёл сбой (ошибка провайдера, тайм-аут), повторно вызывается до 3 раз через разных провайдеров
- После выступления аргумент агента оценивается на уверенность, передаётся управляющему для извлечения утверждений и проверяется на наличие родительских ссылок (дерево аргументов)

## 2.2 Дебаты

### Слой концепций

**Дебаты** — это структурированный многораундовый разговор между агентами на заданную тему. Система обеспечивает порядок ходов, отслеживает аргументы, измеряет конвергенцию и формирует консенсус при остановке. Дебаты имеют жизненный цикл: подготовка → вступительные заявления → раунды → завершение.

### Слой системного отображения

```
DebateSession {
  id: string;
  topic: string;
  status: 'active' | 'paused' | 'completed';
  strategy: DebateStrategy;
  maxRounds: number;
  currentRound: number;
  participants: DebateParticipant[];
  arguments: DebateArgument[];
  convergenceScore: number;      // 0-100
  config: DebateConfig;
  consensus?: string;
  graphMetrics?: DebateGraphMetrics;
  interpretation?: DebateInterpretation;
  activityMetrics?: ActivityMetrics;
  qualityMetrics?: QualityMetrics;
}
```

**13 стратегий (33 встроенных пресета)** (`DebateStrategy`):

| Стратегия       | Поведение                             | Сценарий использования                     |
| --------------- | ------------------------------------- | ------------------------------------------ |
| `round_robin`   | Фиксированный модульный порядок       | Сбалансированные, предсказуемые дебаты     |
| `moderated`     | LLM выбирает следующего выступающего  | Динамическая, адаптивная очерёдность       |
| `free_for_all`  | Случайный ≠ последний выступавший     | Непредсказуемое, хаотичное исследование    |
| `socratic`      | Сократ ↔ респондент Q&A               | Логическое зондирование, скрытые допущения |
| `argument_tree` | Иерархические ссылки `[parent:id]`    | Структурированное картирование аргументов  |
| `constrained`   | Round-robin с ограничениями на агента | Контролируемые эксперименты по рассуждению |

### Слой поведения

1. **Вступительные заявления**: Все участники выступают один раз (раунд 0) по порядку
2. **Цикл раундов**: `getNextParticipant()` диспетчеризирует по стратегии → `executeArgumentRound()` формирует промпт, вызывает LLM, извлекает структуру, передаёт управляющему
3. **Переход к следующему раунду**: После того, как все участники выступили в текущем раунде, `currentRound` увеличивается
4. **Условия остановки** (проверяются после каждого аргумента): управляющий говорит остановиться, нет новых утверждений, плато конвергенции (3 раунда >80 Jaccard, диапазон <10), конвергенция >85, достигнут максимум раундов
5. **Завершение**: Вычисляются метрики, запускается интерпретатор, формируется консенсус, сессия сохраняется

## 2.3 Граф утверждений

### Слой концепций

**Граф утверждений** — это структурированное представление всех фактических утверждений, сделанных в ходе дебатов. Он не совпадает с лентой аргументов — это DAG извлечённых утверждений с рёбрами, представляющими отношения поддержки, оспаривания или уточнения. Граф утверждений поддерживается `DebateGovernor` и используется для обнаружения противоречий, измерения конвергенции и определения момента остановки.

### Слой системного отображения

```
Claim {
  id: string;
  text: string;
  sourceArgumentId: string;
  speaker: string;
  role: string;          // pro/con/neutral
  round: number;
  status: 'active' | 'challenged' | 'resolved' | 'disputed';
  supportCount: number;
  challengeCount: number;
  createdAt: number;
}

ClaimEdge {
  from: ClaimId;
  to: ClaimId;
  type: 'supports' | 'challenges' | 'refines';
  weight: number;
}

ClaimGraph {
  claims: Record<string, Claim>;
  edges: ClaimEdge[];
}
```

Управляется `src/kernel/services/debate-governor/`:

- `claim-extractor.ts` — разбирает текст аргумента на объекты утверждений
- `claim-graph.ts` — вставка утверждений, запрос по выступающему/статусу, обнаружение перекрёстных рёбер
- `contradiction-detector.ts` — попарное обнаружение семантических пересечений с настраиваемым порогом

### Слой поведения

- Каждый раз, когда добавляется аргумент, вызывается `DebateGovernor.ingestArgument()`
- Утверждения извлекаются, добавляются в граф, и существующие утверждения проверяются на противоречия
- Оценка конвергенции вычисляется как меж-спикерное перекрытие Jaccard утверждений (30% новых, 70% сглаженных)
- Оценка новизны отслеживает, являются ли новые утверждения действительно новыми или переформулировкой старых
- Решение об остановке использует: `hasNoNovelClaims() || isConvergencePlateau() || allCriticalContradictionsResolved()`
