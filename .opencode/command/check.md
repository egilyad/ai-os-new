---
description: Подобрать уровень проверок под изменения (L0-L4)
---

Определи, что изменилось, и назови уровень проверок:

- L0 (гигиена, после каждого файла): `node ./node_modules/eslint/bin/eslint.js <файл>`
- L1 (быстрый контур, перед коммитом): `node ./node_modules/typescript/bin/tsc -b --noEmit` — только если тронут `src/**`; eslint изменённых файлов
- L2 (модульно, перед коммитом фичи): + `npm run lint`-эквивалент (`node ./node_modules/eslint/bin/eslint.js .`), `test:stable` — НЕ локально, это CI
- L3 (полный): `test:full:*`, build, e2e — только через GitHub Actions
- L4 (CI): push в main, всё гоняется автоматически

Правила:

- Если тронут `src/kernel/**` — обязательно проверить связанные wiki-файлы (`gen:wiki-*` после изменения `.md`/`.json`).
- Если изменён любой `.md`/`.json` (включая `AGENTS.md`, `.superagents/memory/`) — запусти все `node scripts/gen-wiki-*.mjs` генераторы и закоммить вместе с кодом.
- Тяжёлые проверки локально НЕ запускаем — доверяем CI.

Сообщи пользователю: какой уровень нужен и почему, что уже проверено, что остаётся на CI.
