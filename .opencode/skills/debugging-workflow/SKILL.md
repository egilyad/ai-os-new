# Workflow отладки

1. **Воспроизведи** ошибку (минимальные шаги).
2. **Собери данные**: логи, статусы процессов, версии, окружение.
3. **Сформулируй гипотезы** (минимум 2–3) — помечай их явно.
4. **Проверь каждую** дешёвым способом (grep, чтение кода, точечный запуск).
5. **Минимальный фикс**: одно изменение, без побочной рефакторизации.
6. **Регрессионный тест** на ошибку (если есть тестовая инфраструктура).
7. **Зафиксируй результат**: причина + решение (в память/ADR при наличии).

Запреты: не менять несколько вещей сразу, не «чинить вслепую», не игнорировать логи.

## Purpose

Use for: падений, неверных результатов и зависших задач — найти причину минимальным числом проверок и закрепить её тестом.

## Examples

- `отладка: тест падает только на Windows`
- `debug why the server hangs after reload`
- Ожидаемый вывод: гипотеза → дешёвая проверка → минимальный фикс → регрессионный тест.

## Error handling

Если воспроизвести ошибку не удалось, скажи об этом и запроси логи/шаги. Если гипотезы не подтвердились — вернись к шагу 2, не меняй код наугад.

## Limitations

Не подходит для проблем с инфраструктурой без доступа к логам; не заменяет профилировщик при проблемах производительности.

## Troubleshooting

Логов нет — включи verbose-режим и повтори. Ошибка нестабильна — зафиксируй условия и увеличи число попыток.
