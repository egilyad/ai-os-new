# Правила документации

- Отвечать на русском (если проект русскоязычный), термины — по соглашению проекта.
- Чёткая структура: заголовки, короткие абзацы, списки, таблицы для сравнения.
- Для каждого раздела — назначение, пример, ссылки на исходники (`файл:строка`).
- Не создавать .md-файлы без необходимости (по умолчанию — только по просьбе).
- После изменения .md/.json в репо ai-os-new — перегенерировать вики (`npm run gen:wiki-*`) при наличии.
- Код в блоках `…`; длинные команды — с пояснением.

## Purpose

Use for: создания и правки `.md`-документации — чтобы текст был структурированным, проверяемым и не расходился с кодом.

## Examples

- `напиши статью в вики про новый сервис`
- `update README for the new flag`
- Ожидаемый вывод: заголовки, короткие абзацы, ссылки `файл:строка`, пример команды.

## Error handling

Если источник не найден, не выдумывай путь — помечай утверждение как `needs-check`. При отсутствии переводов не создавай пустой файл локали.

## Limitations

Не заменяет ревью кода и не проверяет фактическую работу описанной функции; генерация вики требуется отдельно.

## Troubleshooting

Сломались ссылки — перегенерируй вику (`npm run gen:wiki-*`). Документация расходится с кодом — сверь с источником перед правкой.
