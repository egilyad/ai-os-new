# Чеклист ревью

Проверяй:

- **Логика**: корректность, граничные случаи, обработка ошибок, гонки.
- **Безопасность**: ввод пользователя, пути, команды, секреты (никогда не логировать токены).
- **Ресурсы**: потребление памяти и CPU на Windows 10 / AMD E-350; избегать тяжёлых зависимостей.
- **Совместимость**: Node.js (не Bun), PowerShell 5.1, Windows-пути.
- **Конвенции**: стиль проекта, именование, отсутствие лишних комментариев.
- **Полнота**: тесты, документация, обновление AGENTS.md при изменении конвенций.

Формат ответа: findings с `файл:строка`, приоритетом (high/medium/low) и конкретным предложением. Не изменяй файлы при ревью.

## Purpose

Use for: ревью diff, пулл-реквестов и проверки перед коммитом — поймать логические ошибки, утечки секретов и перерасход ресурсов до попадания в main.

## Examples

- `review the diff of the last commit`
- `проверь этот diff перед коммитом`
- Ожидаемый вывод: `- src/a.ts:42 [high] Не экранирован пользовательский ввод → ...`

## Error handling

Если файл или строка не найдены — сообщи об этом и запроси diff, а не выдумывай findings. Отсутствие тестов отмечай как medium.

## Limitations

Статический чеклист не заменяет тесты и typecheck; не проверяет runtime-поведение и совместимость версий без прогона.

## Troubleshooting

Слишком широкий diff — сузься до изменённых файлов. Нет доступа к репозиторию — попроси вставить diff в сообщение.
