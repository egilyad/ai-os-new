# Оптимизация под слабое железо

- **Последовательность вместо параллельности**: один агент/процесс за раз; не запускать параллельные тяжёлые задачи.
- **Вынос вычислений**: всё тяжёлое — вне Electron/OpenCode: MCP-серверы, индексаторы, CLI.
- **Ленивая загрузка**: MCP-серверы по требованию (`enabled: false` в конфиге), skills — по контексту.
- **Лёгкие инструменты**: предпочитать Rust/Go (малая память) или Node.js без тяжёлых зависимостей; избегать PyTorch.
- **Контекст**: подзадачи (`subtask: true`) для изоляции; сжатие вывода инструментов.
- **Не более 3 активных MCP-серверов одновременно.**
- **Индексация**: инкрементальная, в фоне с низким приоритетом (PowerShell: `Start-Process -Priority BelowNormal`).
- **Память**: не держать весь репозиторий в контексте; использовать поиск через индексы.

## Purpose

Use for: выбора инструментов, библиотек и архитектуры на слабом ПК (AMD E-350, 11.6 ГБ ОЗУ), чтобы не уронить машину тяжёлыми проверками.

## Examples

- `выбери лёгкий способ запустить тесты на этой машине`
- `can we add this dependency without slowing the laptop?`
- Ожидаемый вывод: один процесс, node вместо Bun, тяжёлое — в MCP/CLI вне редактора.

## Error handling

Если сценарий требует параллельных воркеров или PyTorch — предложи последовательный аналог или вынос в отдельный процесс. Не обещай «быстро» без замера.

## Limitations

Не заменяет профилирование: рекомендации эвристические. На другой машине пороги памяти и число процессов могут отличаться — уточняй окружение.

## Troubleshooting

Выросло потребление памяти — закрой лишние MCP-серверы и проверь число активных процессов. Тормозит индексация — переведи в фон с низким приоритетом.
