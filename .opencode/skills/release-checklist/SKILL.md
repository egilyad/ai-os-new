# Чеклист релиза

Перед коммитом/релизом проверить:

- [ ] `git status` — только нужные файлы, без секретов и артефактов.
- [ ] `git diff` — изменения соответствуют задаче, нет мусора.
- [ ] Лёгкие локальные проверки (eslint одного файла, быстрые node-скрипты).
- [ ] Тяжёлые проверки — только через GitHub Actions (локально НЕ запускать).
- [ ] Документация обновлена (README, wiki, ADR при необходимости).
- [ ] Версия/чанжлог (если применимо).
- [ ] Нет токенов/ключей в коде и логах.

Коммитить только по явной просьбе пользователя.

## Purpose

Use for: проверки перед коммитом, релизом и запуском CI — не допустить секреты, мусор в diff и непроверенные изменения.

## Examples

- `проверь перед коммитом`
- `prepare release checklist for this change`
- Ожидаемый вывод: список отмеченных пунктов с `git status`, тестами и версией.

## Error handling

Если `git status` показывает чужие файлы — остановись и уточни. Если тесты не запускаются локально — явно переводи тяжёлые проверки в CI, а не пропускай их молча.

## Limitations

Чеклист не гарантирует корректность кода; не заменяет ревью, typecheck и e2e в CI.

## Troubleshooting

Не знаешь версию — сверь CHANGELOG и package.json. Нужно отменить коммит — спроси пользователя, не используй force-push без явной просьбы.
